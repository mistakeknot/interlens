## Task Context

Creative approaches to enriching a TUI/ASCII colony sim (Elf Revel) beyond traditional terminal constraints. The game is a Rust colony sim using rust_pixel/crossterm for terminal rendering at 120x40 characters. Current rendering uses simple single-character glyphs (. for meadow, # for stone, ~ for water, H/W/G/F for buildings, first-letter for elves) with basic Color enum values (Green, Blue, White, etc.). The user wants to keep the ASCII aesthetic but explore richer rendering: video-to-ASCII, SVG-to-ASCII, hybrid rendering, half-block chars, braille unicode, 24-bit color, sixel graphics, kitty image protocol, procedural ASCII art generation. The core tension: how to convey rich, living worlds through the extremely constrained medium of a character grid.

## Review Approach

### 1. Rasmi

- Rasmi-to-vault projection and the character cell as compression format: muqarnas plans are flat 2D drawings that encode 3D vaults — the craftsman reads depth, tier, and structural role from a plan that looks like a simple tiling. A 120x40 character grid is exactly this kind of compressed representation. Does the rendering design treat each cell as a projection point that decodes into richer information via context (neighbors, color, temporal state), or as a literal pixel that must individually carry all its meaning? The half-block and braille approaches increase pixel density, but the muqarnas insight suggests that CONTEXTUAL GRAMMAR between cells matters more than resolution within cells.

### 2. Finite cell vocabulary

- Finite cell vocabulary and the glyph palette problem: muqarnas uses approximately 7-12 fundamental cell types to generate infinite compositions. ASCII has 95 printable characters plus Unicode blocks — but the rendering design should identify which small set of glyphs constitute the 'cell vocabulary' and how their composition grammar creates emergent visual meaning. Does the design specify a curated glyph palette where each character has a defined compositional role (structural vs. decorative vs. informational), or does it treat the full Unicode range as an undifferentiated resource? A muqarnas craftsman would never use 200 cell types when 10 create richer results.

### 3. Polychromatic tier encoding

- Polychromatic tier encoding and color as dimensional signal: in painted muqarnas, color is not decorative — it encodes structural tier. Blue cells are at one depth, gold at another, red at a third. The viewer reads depth from color without perspective geometry. 24-bit terminal color should serve this same function: color carries dimensional or categorical information that the character glyph cannot. Does the color design treat hue, saturation, and brightness as independent encoding channels (hue = category, brightness = depth, saturation = state), or as a monolithic 'prettiness' parameter? Wasting 24-bit color on decoration when it could encode three independent information dimensions is like painting all muqarnas tiers the same color.

### 4. Recursive subdivision

- Recursive subdivision and zoom levels: muqarnas vaults read differently at different distances — from afar, the overall dome shape; from middle distance, the tier structure; up close, the individual cell geometry. A TUI could implement analogous zoom levels where the same map data renders at different subdivision granularity. At full-map zoom (120x40 = entire world), each cell is a biome summary. At quarter-zoom, each cell resolves to terrain type. At tile-zoom, each cell shows individual entity detail. Does the rendering architecture support this kind of recursive subdivision where the SAME underlying data renders at multiple levels of geometric decomposition, or does each zoom level require a separate rendering pipeline?

### 5. The rasmi as data format

- The rasmi as data format and SVG/image-to-ASCII conversion: the muqarnas rasmi is the original 'lossy conversion format' — it compresses a 3D vault into a 2D plan by discarding the third dimension and encoding it as a cell-type grammar. SVG-to-ASCII and image-to-ASCII conversion face the same compression problem. The muqarnas approach suggests that good lossy conversion preserves the GRAMMAR of the source (structural relationships, tier hierarchy, compositional logic) rather than the PIXELS (individual color values). Does the conversion pipeline prioritize structural fidelity (edges, boundaries, compositional hierarchy) over pixel-level fidelity (brightness matching, dithering)?

### 6. Temporal muqarnas

- Temporal muqarnas and animation as tier rotation: some muqarnas compositions create an optical effect where the vault appears to rotate as the viewer moves — a kinetic illusion from static geometry. Terminal animation (cycling colors, shifting glyphs) could create analogous kinetic effects where a static grid appears to have depth or motion. Does the rendering design consider temporal cycling of color or glyph as a way to convey information that a single static frame cannot — time as an additional encoding dimension beyond x, y, character, and color?

## Severity Calibration

- **P1**: The rendering enrichment plan treats 24-bit color as a decoration layer (prettier terrain colors) rather than an information encoding layer (color channels mapping to independent data dimensions like depth, category, and state), wasting the richest available encoding channel on aesthetics alone
  - When: Color usage is specified only in terms of visual appearance ('green for grass, blue for water') with no design for how color hue, saturation, and brightness independently encode game-state information
- **P2**: Each zoom level requires a completely separate rendering pipeline with no shared grammar — the full-map view, terrain view, and entity view are three disconnected renderers rather than recursive subdivisions of the same compositional grammar
  - When: Zoom is implemented as distinct render functions that share no data structures or glyph vocabulary, preventing the 'progressive disclosure' that muqarnas achieves through tier hierarchy
- **P2**: The glyph palette grows unbounded — 50+ distinct characters for terrain, buildings, flora, elves, weather — without a compositional grammar specifying how characters relate, creating visual noise rather than legible complexity
  - When: New visual features each introduce their own glyphs without a curated vocabulary that defines structural vs. decorative vs. informational character roles
