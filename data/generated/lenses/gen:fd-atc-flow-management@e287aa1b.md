## Task Context

## Review Approach

### 1. Event sequencing and ordering guarantees: ATFM must route events in strict

- Event sequencing and ordering guarantees: ATFM must route events in strict priority order (emergency > delay program > normal flow) across sector adapters — assess whether the interop event bus defines message priority and delivery ordering, or whether goroutine scheduling makes delivery order non-deterministic between adapters processing the same logical resource (a beads issue being updated by both GitHub and Notion adapters simultaneously)

### 2. Sector handoff and the adapter boundary: in ATC

- Sector handoff and the adapter boundary: in ATC, handoff is the explicit transfer of ownership from one sector controller to another, with acknowledgment — check whether interop models the equivalent: when a cross-adapter event (GitHub issue to beads bead) is emitted, does the receiving adapter acknowledge processing, or does the hub treat emission as completion, creating silent loss when the receiving adapter goroutine is backpressured or panicking

### 3. Flow control programs and backpressure: ATFM uses ground delay programs to slow

- Flow control programs and backpressure: ATFM uses ground delay programs to slow ingest when downstream sectors are saturated — assess whether the event bus implements backpressure from slow adapters upstream, preventing the hub from accepting webhook payloads faster than adapters can consume them, and whether the design distinguishes between transient backpressure (retry) and structural capacity limits (drop + dead-letter)

### 4. Conflict alert and the two-bead problem: ATC conflict detection fires when two

- Conflict alert and the two-bead problem: ATC conflict detection fires when two aircraft are projected to occupy the same airspace — check whether interop detects the equivalent: two external systems updating the same entity (a beads bead modified by both a Notion webhook and a GitHub webhook within the same sync window), and whether the conflict resolution strategy (three-way merge, last-write-wins) is applied before or after both updates are emitted to downstream adapters

### 5. Radar returns and adapter health heartbeats: ATC systems declare loss of radar

- Radar returns and adapter health heartbeats: ATC systems declare loss of radar contact when a sector data feed goes silent — assess whether each adapter emits a regular health signal and whether the hub can distinguish between a healthy adapter with no events (legitimate silence) and a failed adapter goroutine that stopped processing (silent failure), and what the hub does during the silence interval

### 6. Contingency routing and adapter fallback: when a sector goes offline

- Contingency routing and adapter fallback: when a sector goes offline, ATFM reroutes through adjacent sectors — check whether interop has a fallback routing strategy when a primary adapter (e.g., Notion webhook) fails: does it degrade to polling, queue events for retry, or lose them, and whether the fallback activation is automatic or requires operator intervention

## Severity Calibration

- **P0**: Two adapters emit conflicting updates for the same beads issue within the same sync window — the event bus delivers both to the beads adapter, which applies them in goroutine-scheduled order, producing a non-deterministic final state that differs between runs and cannot be reproduced
  - When: When the event bus does not serialize concurrent updates to the same entity through a per-entity ordering guarantee or optimistic locking, making conflict resolution outcomes depend on goroutine scheduling
- **P1**: A webhook payload arrives during a Notion adapter restart; the hub accepts the payload (HTTP 200), the adapter goroutine is not yet running, and the event is lost with no dead-letter queue or retry mechanism
  - When: When the hub webhook ingestion layer is decoupled from adapter readiness — payloads are accepted before the consuming adapter is healthy, and no durable queue bridges the gap
- **P2**: The Notion adapter goroutine pool is saturated processing a bulk sync; new events queue in an unbounded channel; the hub accepts webhook traffic normally; memory grows until the process OOMs with no operator-visible backpressure signal
  - When: When per-adapter goroutine channels are unbounded and no backpressure signal propagates from the adapter to the webhook ingestion layer

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
