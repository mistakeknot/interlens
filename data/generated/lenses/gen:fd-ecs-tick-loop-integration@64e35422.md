## Severity Calibration

- **P0**: consumer_tick unavailable to derivations, optimal mood port blocked
  - When: The spec's §9 optimal port shape (mood_system vanishes, decay is a derivation) requires current_tick in DerivationFn. The locked DerivationFn signature does not carry it. If Phase 1 code starts with the locked signature, every implementation of time-relative derivations must use a workaround (captured Arc<AtomicU64>, closure mutation) that the spec does not anticipate or bless. This is a P0 for the ECS integration because the entire argument that 'the hot path stays sync' depends on derivations being able to compute without store calls — and without tick context, they can't compute ticks_remaining.
- **P1**: Pattern A write-through under SqliteSoulStore
  - When: The spec recommends Pattern A as the Phase 1 default and Pattern B as 'Phase 1.5 opt-in.' If elf-revel ships Phase 1 with SqliteSoulStore and Pattern A, every Soul::append will fsync, making the tick loop I/O-bound at 100 ticks/sec. The spec should invert the default: Pattern B (deferred-batch) is the default for any I/O store; Pattern A is only for MemSoulStore.
- **P2**: Soul placement in ECS world unspecified
  - When: The port shapes in §9 and §14 use world.get_soul_mut(soul_id) but this function is not defined anywhere in the spec. Whether Soul is an ECS component, a side-table HashMap<SoulId, Soul>, or a field on a higher-level ElfWorld struct determines whether elf-revel's existing &mut World parallelism is preserved or broken.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

A game tick is a budget. Every allocation, every syscall, and every block_on is a deduction from that budget. The right integration layer makes the happy path fit the budget with zero tax; the wrong integration layer makes every tick pay for abstractions it doesn't use. The ECS community has learned that 'bolt-on external state stores' fail unless the integration is co-designed with the component model. If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.
