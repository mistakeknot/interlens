## Task Context

Elf Revel — Rust colony sim exploring ASCII-as-polygon isometric rendering for browser via WASM. Current renderer is rust_pixel TUI; this review covers the proposed spatial rendering paradigm shift. hecs ECS, 200+ entities, scrollable colony map.

## Review Approach

### 1. Coordinate system design: world

- Coordinate system design: world-space (axial/cube hex or cartesian grid) → screen-space (2:1 isometric diamond) transform; does the math correctly handle sub-tile entity positioning and smooth scrolling?

### 2. Depth sorting algorithm: painter's algorithm with y

- Depth sorting algorithm: painter's algorithm with y-sorting works for flat tiles but breaks with multi-height structures (trees, buildings); does the architecture handle z-layers or per-entity depth keys for correct occlusion?

### 3. ASCII

- ASCII-as-tile-texture feasibility: rendering pre-rasterized ASCII art into tile-sized textures via fontdue/lyon, then compositing them as sprites — does this preserve the character aesthetic or does bilinear filtering destroy the pixel crispness?

### 4. Tile atlas

- Tile atlas and batching strategy: how many draw calls per frame? A naive per-tile approach in wgpu will crater performance; does the design batch tiles into texture atlases and use instanced rendering?

### 5. Camera

- Camera and viewport: smooth panning, zoom levels (where ASCII characters scale from readable to abstract pattern), minimap generation — does the architecture support these without re-rendering the entire scene?

## Severity Calibration

- **P0**: Depth sorting uses simple y-coordinate ordering which causes elves behind tall structures to render on top of them, breaking spatial comprehension entirely
  - When: No z-layer or composite depth key accounting for entity height and tile elevation
- **P1**: Each visible tile is a separate draw call in wgpu, causing 2000+ draw calls per frame and dropping WASM performance to <10fps on mid-range hardware
  - When: No tile atlas batching; tiles rendered individually rather than instanced
- **P2**: Zooming out causes ASCII characters to become unreadable sub-pixel noise rather than gracefully transitioning to abstract color/density representation
  - When: No LOD system for tile rendering at different zoom levels

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
