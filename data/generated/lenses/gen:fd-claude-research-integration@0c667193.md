### 1. Context window strategy: the research corpus compounds with every episode

- Context window strategy: the research corpus compounds with every episode — at scale, research/ may contain hundreds of documents far exceeding any context window. Is there a retrieval-augmented approach (embed + retrieve relevant chunks) or does the brainstorm assume full-corpus injection?

### 2. Stateful dialogue: 'Socratic exploration' implies multi-turn conversation with

- Stateful dialogue: 'Socratic exploration' implies multi-turn conversation with memory of prior exchanges. Does the Swift app maintain the messages array client-side, or proxy through FastAPI which manages session state? The brainstorm mentions both direct SDK use and proxy options without resolving the question.

### 3. Transcript-to-artifact pipeline: dialogue transcripts become research artifacts

- Transcript-to-artifact pipeline: dialogue transcripts become research artifacts added to the corpus. What prevents circular retrieval (a transcript from session N being injected into session N+1 and amplifying its own claims)?

### 4. API availability and offline use: if the Claude API is unreachable (no internet

- API availability and offline use: if the Claude API is unreachable (no internet, rate limited), does the research surface degrade gracefully — allowing corpus browsing and script editing — or does the entire surface become unusable?

### 5. Tool use for corpus search: a Socratic dialogue agent likely needs to search

- Tool use for corpus search: a Socratic dialogue agent likely needs to search the corpus during conversation. Is there a tool use schema for corpus retrieval that the API can call, and does the FastAPI layer expose this as a callable endpoint?

### 6. Cost and token management: interactive research dialogue can generate high

- Cost and token management: interactive research dialogue can generate high token volumes. Is there a token budget visible to the user, a maximum turn length, or a session summarization strategy to compress context?

## Severity Calibration

- **P1**: After 20 research sessions, the corpus is too large to inject into context; the brainstorm has no retrieval strategy, so the research surface silently degrades to using only recent documents
  - When: If there is no plan for semantic chunking, embedding, and retrieval-augmented injection as the corpus grows
- **P1**: The Swift app calls the Claude API directly with the Anthropic Swift SDK, bypassing FastAPI — but Claude Code skills also call Claude through a different session, creating two independent conversation histories with no shared state
  - When: If the brainstorm does not resolve whether Claude session state lives in the app or in the FastAPI layer that skills also use
- **P2**: A 45-minute research dialogue session is lost when the app is force-quit, because transcript persistence to disk only happens on explicit user save
  - When: If transcript auto-save is not specified as a background write on every assistant turn

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
