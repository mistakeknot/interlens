## Task Context

Garden Salon's governance model is per-garden with platform invariants. Attribution records compute contributions but defers meaning to gardens. The BYOK model means contributors bring API keys; the platform proxy verifies usage. The evolutionary path (emergent → templates → constitutions) defers governance design. The review target is the governance/attribution design's game-theoretic soundness.

## Review Approach

### 1. Attribution gaming vectors
- Token count as governance weight: the brainstorm acknowledges this is gameable. Is "qualified attribution" (only tokens from reviewed artifacts) sufficient defense?
- Artifact hash linkage: can someone generate real artifacts that are technically correct but strategically useless, just to accumulate attribution?
- Provider-receipt vs client-estimate: is there a path where client_estimate data gets treated as trusted?
- Can a participant run cheap models to accumulate token count cheaply?

### 2. Direction lifecycle as governance surface
- Proposing a direction is free. Can someone flood a garden with proposals to dilute attention?
- The `max_active_directions` soft limit — what happens when it's exceeded? Who decides?
- Staleness auto-flagging at 30 days — does this punish careful, slow work?
- Can direction ownership transfer be used to launder attribution?

### 3. Governance transition risks
- "Cooling period" for governance changes — what prevents a hostile majority from waiting it out?
- "Participants who contributed under one governance model must have notice" — notice is not consent. Is this sufficient?
- The evolutionary path (emergent → templates → constitutions) means early gardens have no governance framework. Who resolves disputes during the emergent phase?

### 4. Role model sufficiency
- Only three roles: Owner, participant, agent. The brainstorm acknowledges the patron/creative director capture problem. Is "future refinement target" good enough?
- Owner has unilateral power. In a cooperative garden, what prevents owner capture?
- Agent-as-first-class-actor but always under a principal — can the principal deny responsibility for agent actions?

### 5. Platform invariant enforcement
- "No garden can delete attribution records" — but the platform admin can? Who watches the platform?
- Owner succession at 90 days of inactivity — what if the owner is deliberately absent (on sabbatical)?
- Attribution survives garden deletion — where does it live? Who can query it?

## Severity Calibration

- **P0:** Attribution can be trivially gamed to capture governance
- **P1:** The governance transition model has an exploit path
- **P2:** Role model is insufficient for the cooperative use case
- **P3:** Edge cases in succession or cross-garden attribution
