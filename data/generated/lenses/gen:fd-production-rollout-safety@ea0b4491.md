## Severity Calibration

- **P0**: Go resolver auto-degrades from enforce to shadow (model not loaded) silently with no log entry — a mis-deployed router operates in stealth shadow mode for an entire sprint session, appearing to work while B3 is silently providing all routing decisions, making the sprint's calibration data useless for evaluating B6.
  - When: When the model-not-loaded fallthrough path has no structured log emission and the operator has no alerting on the microrouter endpoint health.
- **P1**: Rollback procedure deletes routing-calibration.json (B3 escape hatch) rather than the B6 adapter checkpoint — B3 calibration is destroyed along with B6, reverting the system further than intended and losing 21+ sprint sessions of calibration data.
  - When: When the B6 rollback documentation reuses B3/B4 escape-hatch language without distinguishing which file(s) each track's escape hatch targets.
- **P1**: The ≥ 1 sprint shadow soak is conducted during a doc-update-heavy sprint where 80% of subagent calls are trivially Haiku-routable — the soak shows 30% reroute rate and zero pass@1 regression, but the first enforce-mode sprint is implementation-heavy with a different task mix, revealing a 15% pass@1 regression on complex tasks the soak never covered.
  - When: When the soak sprint is not representative of the long-run execution distribution and there is no minimum required diversity criterion for the soak period.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
