## Task Context

Six open design questions for a dynamic flora system in an elven colony sim (Rust ECS, WASM). The system needs procedurally generated species (or fixed species) with growth stages, soil preferences, beauty values, and seasonal states. Entity density could range from ~20 sparse entities to ~600 full-coverage entities on a 40x30 map. The tension between 'every world unique' (procgen) and 'shared vocabulary' (fixed species) is central to Q1. ## Review Approach

### 1. Palette sizing

- Palette sizing and species count (Q1): the Iznik tradition's most productive period used exactly 4-5 colors. Too few (blue and white only) was limiting; too many (European maiolica's unlimited palette) produced visual incoherence. Option A's 8-12 species mirrors the Iznik sweet spot — enough for rich composition, few enough that each is recognizable. But the Iznik lesson is that palette size must be EARNED through mastery of each element before adding the next. Did Armenian bole arrive because they mastered the previous palette. Does the design allow for palette expansion over game time — starting with fewer species and adding as the colony matures?

### 2. Fixed vocabulary vs

- Fixed vocabulary vs. arrangement grammar (Q1): Iznik tiles use standardized motifs (saz leaf, tulip, carnation, cloud band) that appear across thousands of tiles but are never identical — each is hand-painted within the motif template. Option D (6 fixed archetypes + 2-4 procgen) mirrors this perfectly: fixed motifs (archetypes) with hand-varied instances (procgen). But does the design specify the ARRANGEMENT GRAMMAR — the rules for how species combine on a tile, across a field, through a biome? Iznik panels work because motif placement follows compositional rules (symmetry, flowing stems, border patterns), not because the motifs themselves are interesting.

### 3. Quality control

- Quality control and the decline (Q1, Q5): the Iznik tradition's 17th-century decline happened when quality control loosened — too many colors, sloppier painting, loss of the Armenian bole technique. Option B's 20-30 species risks the same decline: too many elements, each less carefully realized, the whole less coherent. Does the design have a quality control mechanism — a way to ensure that each species is 'painted' with enough care (distinct soil preferences, beauty values, visual character) that adding more species doesn't dilute the palette?

### 4. Tessellation

- Tessellation and terrain architecture (Q3): Iznik tiles are individually crafted but designed to tessellate — the edge of one tile continues seamlessly into the next. Option B (overlay) treats terrain as the tile body and flora as the painted surface — the tile tessellates (terrain handles pathfinding, adjacency) while the decoration varies (flora entities add species detail). This is architecturally sound IF the 'tile body' (terrain) provides consistent edges. Does the terrain system guarantee that adjacent tiles have compatible properties for flora to tessellate across?

### 5. Standardization enabling scale (Q5): the Iznik tradition ...

- Standardization enabling scale (Q5): the Iznik tradition produced thousands of tiles for mosque interiors because the motif vocabulary was standardized enough for workshop production. High entity density (Q5 Option A, ~600 entities) is only feasible if species have standardized, lightweight representations — the ECS equivalent of a tile template. Does the component design for flora entities follow a standardized pattern that makes 600 instances as manageable as 600 tiles from the same motif vocabulary?

## Severity Calibration

- **P1**: Species are generated with individual properties but no arrangement grammar — the system knows what each species looks like but not how species combine into compositional patterns across tiles and biomes
  - When: Q1 specifies per-species generation (soil preference, beauty, growth rate) but no inter-species tessellation rules for how a forest, meadow, or garden composes multiple species
- **P2**: Option B's 20-30 species dilutes the palette so that individual species lose recognizability — the Iznik decline pattern where more variety produces less quality
  - When: Species count exceeds the threshold where each can be given distinct, memorable properties (visual character, gameplay niche, compositional role) and begins to blur into categorical noise
- **P3**: All species are generated at world creation with no palette expansion over time, missing the Iznik lesson that palette growth should track mastery
  - When: Q1 options all generate the full species set at world generation rather than starting with a core palette and introducing new species as the colony's botanical knowledge grows
