## Task Context

The app's core value proposition is native media capability — frame-accurate scrubbing, stem waveform preview, A/B comparison. These are the features that justify ditching the Tauri/web approach. If the media pipeline has threading or lifecycle gaps, the core promise fails.

## Review Approach

### 1. AVPlayer/AVPlayerItem lifecycle: are seek operations debounced and cancellable?

- AVPlayer/AVPlayerItem lifecycle: are seek operations debounced and cancellable? Does the brainstorm account for the async nature of seekToTime and status KVO observation?

### 2. Waveform rendering: does stem preview require a separate AVAssetReader pass

- Waveform rendering: does stem preview require a separate AVAssetReader pass, and is there a plan to cache waveform data to avoid re-reading large WAV files on every view appearance?

### 3. Core Audio threading: are audio graph modifications (A/B stem switching)

- Core Audio threading: are audio graph modifications (A/B stem switching) performed on the audio render thread or dispatched through a message-passing queue to avoid priority inversion?

### 4. Codec coverage: the pipeline produces ffmpeg-transcoded MP4s and Demucs WAV

- Codec coverage: the pipeline produces ffmpeg-transcoded MP4s and Demucs WAV stems — are H.264/AAC containers assumed, or is there a fallback for ProRes/ALAC outputs from Manim or other tools?

### 5. Shot preview in the episode timeline: individual shots/*.mp4 may be written

- Shot preview in the episode timeline: individual shots/*.mp4 may be written mid-render — does the plan handle AVPlayer loading a file that is still being written by ComfyUI or ffmpeg?

### 6. Two-cut view (9:16 + 16:9 side-by-side): synchronized playback of two AVPlayer

- Two-cut view (9:16 + 16:9 side-by-side): synchronized playback of two AVPlayer instances requires AVSynchronizedLayer or a shared AVPlayerItemVideoOutput — is synchronized scrubbing addressed?

## Severity Calibration

- **P0**: Waveform view triggers AVAssetReader on the main thread for a 200MB stem WAV, blocking the UI for several seconds
  - When: If async dispatch to a background serial queue with cancellation is not specified in the design
- **P1**: A/B stem comparison causes audio glitch or dropout because the Core Audio graph is mutated from a non-real-time thread
  - When: If the brainstorm does not specify a lock-free or message-passing audio graph update pattern
- **P2**: Shot thumbnails in the timeline strip are blank for shots still being rendered because AVAssetImageGenerator returns no frames from a partially-written file
  - When: If there is no file-completion signal or polling strategy for in-progress render outputs

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

- P3: Improvements and polish — suggest but don't block on these
