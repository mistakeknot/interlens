- Confirm that a delete-my-data flow is specified: when a user disconnects Gmail or requests data deletion, the pipeline must delete (not just mark inactive) all extracted purchase records from Auraken's context DB and all wardrobe rows from jawncloud, and revoke the OAuth token

## Severity Calibration

- **P0**: Delete-my-data flow removes the Gmail token but leaves purchase records and wardrobe rows intact in jawncloud and Auraken context DB
  - When: When the disconnection handler only calls the OAuth revoke endpoint and deletes the token row, without cascading to derived data stores
- **P1**: OAuth consent screen says 'read your Gmail' without disclosing that purchase history, product names, and prices will be stored permanently in Auraken
  - When: When the consent UI copy was written before the storage scope was finalized and has not been updated to match the brainstorm's data flow
- **P2**: Error tracing middleware captures the raw email HTML snippet in the exception context — product names and prices appear in Sentry or equivalent
  - When: When the parser raises an exception mid-parse and the framework's default exception handler serializes the local variables including the email body

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
