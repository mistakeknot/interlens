### 1. Python-to-Go regex dialect divergence in observable extraction: Go's regexp

- Python-to-Go regex dialect divergence in observable extraction: Go's regexp package uses RE2 semantics (no backtracking, no lookahead/lookbehind), while Python's re module supports lookahead and lookaround assertions — any pattern in style.py:39-92 that uses (?=...) or (?<=...) will silently compile in Python but fail or behave differently in Go's RE2; each pattern must be audited for RE2 compatibility before claiming parity

### 2. Unicode category matching divergence: Python's \w in re matches Unicode word

- Unicode category matching divergence: Python's \w in re matches Unicode word characters by default (including accented letters, CJK, Arabic) but Go's regexp \w matches only ASCII word characters — emoji detection, capitalization ratio, and vocabulary token extraction for non-ASCII conversations will produce different observables between Python and Go unless the patterns are explicitly updated to use Unicode character classes

### 3. Weighted mode classification tie-breaking: ClassifyMode applies weight-3

- Weighted mode classification tie-breaking: ClassifyMode applies weight-3 patterns (emotional), weight-2 (analytical), and weight-1 (others) — when two modes score identically, the Python dict iteration order (3.7+ insertion-ordered) determines the winner, while Go's map iteration is randomized; tie-breaking must be made explicit (e.g., prefer by mode priority order) rather than relying on source language map ordering

### 4. EMA transition boundary at N=5: the alpha formula switches from 1/(n+1) to 0.3

- EMA transition boundary at N=5: the alpha formula switches from 1/(n+1) to 0.3 at n>=5; a port that applies the switch at n>5 or n>=4 will produce divergent per-mode profiles for the critical 4th and 5th messages, where the fingerprint is first becoming reliable; verify the boundary condition is tested with a golden fixture at exactly n=4, n=5, and n=6

### 5. Vocabulary counter semantics vs EMA fields: vocabulary counters (word lists)

- Vocabulary counter semantics vs EMA fields: vocabulary counters (word lists) use raw increment while numeric fields (avg_words, capitalization ratio) use EMA — if the Go port accidentally applies EMA to vocabulary counters or raw increment to EMA fields, the per-mode profile will diverge silently; the JSON field names matching Python do not guarantee the update logic is correct

### 6. Golden-file test coverage of all 7 mode classifiers: a parity test suite must

- Golden-file test coverage of all 7 mode classifiers: a parity test suite must exercise inputs that score highest in each of the 7 modes with known observable outputs and known mode classifications; testing only emotional and general modes leaves 5 classifiers unvalidated against the Python reference

## Decision Lens

A ported behavioral scoring model is correct only when: (1) every feature extracted from a raw input string is bit-for-bit identical between the source and target runtime on the same input; (2) every segment classification (the equivalent of a risk tier) assigned to an input is label-identical, not merely 'similar', between source and target; (3) the rolling score after N inputs is within machine epsilon of the source runtime's output given the same input sequence. Any port that validates only aggregate statistics ('mean segment accuracy = 98%') rather than per-input label agreement is not a correctness validation — it is a sampling exercise that will miss the tail cases that matter most. If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.

## Prioritization

- P0: Issues that block other work, cause data loss or corruption — drop everything
- P1: Issues required to exit the current quality gate
- P2: Issues that degrade quality or create maintenance burden
- P3: Improvements and polish — suggest but don't block on these
- For each P0/P1 finding, describe the concrete failure scenario: what breaks, under what conditions, and who is affected

- Frame uncertain findings as questions, not assertions
