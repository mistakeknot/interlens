## Task Context

Elf Revel native full-screen Rust colony sim needing 100K+ ASCII-aesthetic glyphs at 60fps. Options include fontdue bitmap atlas, SDF atlas, MSDF atlas, and ab_glyph outline tessellation. Tile sizes are 16-24px logical (32-48px physical on Retina). Characters include full printable ASCII, Unicode box-drawing, geometric shapes, and potentially custom PUA glyphs for flora/fauna.

## Review Approach

### 1. Bitmap atlas vs SDF tradeoff at tile sizes: at 16px tiles...

- Bitmap atlas vs SDF tradeoff at tile sizes: at 16px tiles on a 2x HiDPI display (32px physical), bitmap atlas rasterized at 32px physical is perfectly sharp with zero rendering overhead; SDF adds complexity and GPU cost for no quality benefit at this size — evaluate whether the complexity of SDF is justified for Elf Revel's use case or if fontdue bitmap rasterization is the pragmatic choice

### 2. MSDF for ASCII aesthetics: standard SDF blurs sharp corne...

- MSDF for ASCII aesthetics: standard SDF blurs sharp corners (the '+' character's right-angle junction, '#' crossbars) which destroys the crisp ASCII game aesthetic; MSDF (multi-channel SDF) preserves corners correctly but requires the msdfgen crate or offline atlas pre-generation — assess whether the atlas generation pipeline can run offline (ship baked atlases) or must generate at runtime from user font choices

### 3. Fontdue integration path: fontdue provides SubpixelRasterize

- fontdue integration path: fontdue provides SubpixelRasterize and rasterize() for bitmap output directly into a pixel buffer; it does not provide SDF; verify the integration path from fontdue rasterization output → wgpu TextureView → WASM-compatible texture upload, and whether fontdue's Rust API is stable enough for a production game build (last release timeline matters)

### 4. Per

- Per-glyph color as first-class GPU data: Elf Revel needs per-glyph foreground and background color (for mood visualization, seasonal tinting, depth-based color temperature); verify whether the chosen approach passes color as vertex attributes to the fragment shader (efficient, batched) or as per-instance uniform buffers (works but limits batching) or as texture lookups (flexible but adds a texture sample per glyph)

### 5. Unicode coverage for elven aesthetic: the design calls fo...

- Unicode coverage for elven aesthetic: the design calls for elvish/decorative characters, box-drawing (U+2500 block), geometric shapes (U+25A0 block), and potentially custom Private Use Area glyphs for flora/fauna icons; verify that the chosen font pipeline can handle a 512+ character atlas without blowing WASM texture memory budgets (512x512 atlas at 32px glyph size fits ~256 glyphs; verify coverage)

### 6. Subpixel rendering

- Subpixel rendering and HiDPI: native full-screen on Apple Silicon means Retina display; subpixel antialiasing is unavailable in Metal/wgpu (no RGB subpixel layout access); verify the atlas rasterization DPI strategy — rasterize at 2x physical pixels and render at logical size, or rasterize at logical size and let the OS scale? The first produces crisper glyphs.

## Severity Calibration

- **P1**: Standard SDF atlas causes the '#' terrain glyph (used for walls in every ASCII roguelike) to render with rounded corners and blurred crossbars, making it visually indistinguishable from the 'H' entity glyph — the fundamental ASCII readability contract is broken
  - When: Vanilla SDF atlas used for ASCII tile rendering without MSDF corner correction; tile size small enough that SDF blur radius is a significant fraction of glyph size
- **P1**: The Unicode box-drawing block (U+2500–U+257F) used for building walls and structural tiles is not included in the pre-baked atlas, causing missing-glyph fallback boxes to appear wherever structural glyphs are used — the colony sim's architecture is visually illegible
  - When: Atlas generation script only covers printable ASCII (U+0020–U+007E); Unicode blocks not enumerated in atlas build configuration
- **P2**: fontdue rasterizes glyphs at logical pixel size (16px) rather than physical pixel size (32px on 2x Retina), producing noticeably blurry characters compared to native macOS text on the same display — the game looks low-quality next to system UI despite running at native resolution
  - When: DPI scaling factor not applied to fontdue rasterization size; logical and physical pixels conflated in atlas generation code

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
