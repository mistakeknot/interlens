## Severity Calibration

- **P0**: The safety theme gate is promoted to hard tier at FNR = 0.31 (just above the 0.30 threshold). Hard tier gates block shipping. Two weeks later, the safety theme accumulates 12 new outcomes with FNR = 0.28 (just below the threshold). The 7-day cooldown has passed and change_count_90d = 1, so the calibration engine demotes the safety theme back to soft. A safety gate that was catching 69% of safety violations is now catching fewer — because the calibration rule applies the same FNR threshold to safety as to docs, and the threshold was chosen without reference to the cost of a safety false negative.
  - When: When a single FNR threshold drives promotion and demotion for all themes without per-theme cost weighting, and the threshold is set at a value appropriate for low-cost-FN themes like docs
- **P1**: The v2 schema does not include a fnr_threshold field per theme entry. A follow-up bead adds per-theme thresholds by extending the entry object. The existing entries in gate-tier-calibration-v2.json lack the field, so the calibration engine must handle the missing-field case. The code defaults to 0.30 for missing entries — correct behavior. But the migration does not backfill the field, so the schema validator reports missing required fields for all existing entries, and any tooling that validates the schema strictly rejects the file on every SessionEnd until all entries are manually updated.
  - When: When a schema field known to be needed in v2 is deferred from the initial schema definition, requiring a partial v2.1 migration that was avoidable
- **P2**: A check_type fires on every SessionEnd for a given theme because a structural issue persists across sprints. Every fire has verdict=blocked (true positive). The FNR for this theme is 0 (no false negatives) and FPR is also 0 (no false positives). The calibration engine leaves the tier at soft because FNR < 0.30. But the gate is correctly catching the issue every time — the soft tier is working, not failing. The system has no mechanism to recognize that a consistently-firing gate under soft tier is evidence the gate is well-calibrated, not evidence for promotion.
  - When: When the calibration algorithm only reads FNR and ignores FPR, missing the case where low FPR under sustained high-FNR-approaching-zero is the correct signal that the gate is operating at its intended sensitivity

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
