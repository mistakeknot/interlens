## Severity Calibration

- **P1**: The pipeline contract's minimum_tier field is documented as informational metadata with no accompanying schema rule or conformance vector proving a scheduler must refuse to run a stage below its declared tier.
  - When: Without this as an enforced contract property from M0, tier-routing bugs (e.g., garment segmentation attempted on-device under thermal throttle) become a runtime behavior bug discovered at M1-M4 instead of a contract violation caught by shared conformance tests.
- **P1**: The stage interface and manifest schema have no representation for a stage that is declared but has not yet run, or has run on one tier and awaits confirmation from a stage on another tier.
  - When: The brief's own storage-ceiling policy (raw reclaimed only once every routed stage confirms) requires exactly this kind of partial/pending state; if M0's schema can't express 'stage X pending on tier Y' cleanly, M1's storage/reclaim logic will bolt on an ad hoc side-channel instead of using the contract.
- **P2**: Fixture conformance vectors validate schema shape only (well-formed vs malformed JSON against the schema) with no vector representing a semantically-invalid but schema-valid combination, e.g., a stage claiming minimum_tier: device_realtime while privacy_class: raw_quarantined targets a destination the flow rules forbid.
  - When: This is the same gap post-pipelines hit when an EDL is technically well-formed XML but references a reel that violates delivery-spec rules — schema validity alone doesn't catch domain-rule violations, and the brainstorm's own flow-rule table needs its own semantic fixture class.
