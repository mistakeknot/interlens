## Task Context

Garden Salon is a multiplayer human-agent collaboration workspace built on Yjs CRDTs. The architecture separates real-time collaborative editing (CRDT-managed) from governance lifecycle transitions (server-authoritative). Agents are first-class Yjs participants with presence. The review target is the entire project: mission, vision, roadmap, and approach.

## Review Approach

### 1. CRDT-server authority boundary
- Where exactly does the CRDT end and server-authoritative state begin?
- Are direction lifecycle transitions (proposed → active → merged) correctly isolated from CRDT state?
- Can a malicious Yjs client inject governance state changes through the CRDT layer?
- Is the two-phase merge (governance authorizes, platform applies atomically) architecturally sound?

### 2. Agent participation protocol
- How do agents connect as Yjs participants? WebSocket with custom awareness?
- Can the awareness protocol handle agents that don't have cursors but have activity state?
- What happens when an agent disconnects mid-proposal? Is the proposal orphaned or cleaned up?
- Latency requirements: can agents receive real-time rejection feedback fast enough to adapt?

### 3. Scalability of the multiplayer model
- How many concurrent participants (humans + agents) per garden before Yjs breaks down?
- Is the WebSocket relay a single point of failure? What's the hosting plan (Vercel, dedicated)?
- Does the presence model scale? Awareness updates for N participants are O(N²).

### 4. Data model coherence
- How does the Yjs document model relate to the Postgres attribution model?
- Is there a consistency boundary between CRDT state and DB state?
- What happens during a merge: is the CRDT state atomically updated, or can partial merges occur?

### 5. Garden persistence
- How are Yjs documents persisted across sessions? y-indexeddb? Server-side snapshots?
- What happens to CRDT history when a garden is forked or archived?

## Severity Calibration

- **P0:** CRDT state can be corrupted by a malicious participant or a merge race
- **P1:** Server-authoritative transitions can be bypassed through CRDT operations
- **P2:** Scalability limits are undocumented or the persistence model has data loss risk
- **P3:** Awareness protocol inefficiencies or missing cleanup for disconnected agents
