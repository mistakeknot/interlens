## Review Approach

### 1. Pre

- Pre-specification of scorer trigger thresholds: data monitoring boards require that stopping rules are pre-specified before any data is seen — adaptive thresholds set after observing the data are invalid; the ShadowBench power dissolution scorer's trigger (what counts as a 'deployment event' sufficient to fire the scorer?) and the values-under-pressure scorer's attribution threshold (how much pressure change within a deployment window counts as evidence of values-relevant behavior?) must be documented before the benchmark runs any models, not calibrated post-hoc on a reference model's output

### 2. Minimum evidence window before scorer activation: clinica...

- Minimum evidence window before scorer activation: clinical trials have burn-in periods before interim analyses begin — a trial stopped at the first interim analysis (with 10 patients) has insufficient power to detect a real effect; the power dissolution scorer should similarly have a minimum deployment threshold (e.g., at least N deployment events across M distinct countries) before its output is considered valid, preventing a single early deployment from driving the score

### 3. Confounding control in deployment

- Confounding control in deployment-window attribution: the values-under-pressure scorer attributes pressure changes within a deployment window to the deployment — but pressure changes in the target country also occur due to autonomous world dynamics unrelated to the deployment; without a control arm (a parallel run of the same scenario without the model's deployment), the scorer cannot separate model-attributable effects from world-system-attributable effects, which is the same confounding problem clinical trials address with placebo arms

### 4. Multiple testing

- Multiple testing and scorer multiplicity: if both the power dissolution scorer and the values-under-pressure scorer fire on the same DeploymentEvents, the two scores are not independent — they share the same underlying event stream; the benchmark methodology should document whether the two scores are treated as independent dimensions or whether a Bonferroni-style correction is applied when reporting a combined alignment profile

### 5. Type I

- Type I and Type II error asymmetry for alignment claims: a clinical trial's monitoring board sets alpha asymmetrically (stopping for efficacy requires stronger evidence than stopping for futility) because false-positive efficacy claims are more harmful than missed effects; the ShadowBench benchmark should apply the same asymmetry — falsely attributing good alignment (Type I error) is more harmful than failing to detect good alignment (Type II error), and the scorer threshold should be set with this asymmetry explicit

### 6. Scorer robustness to scenario variation: clinical trial m...

- Scorer robustness to scenario variation: clinical trial monitoring boards evaluate whether interim stopping rules are robust to protocol deviations and patient population heterogeneity; the ShadowBench scorers should be stress-tested against scenario variation (different starting pressures, different crisis cascade rates) to verify that the trigger thresholds fire consistently when the alignment-relevant pattern is present, not only in the specific scenario they were designed against

## Severity Calibration

- **P0**: The power dissolution scorer fires whenever `deployment_event` appears in the trace — a model that deploys once to one country at tick 1 and immediately withdraws triggers the scorer and receives a non-zero power dissolution score; the score is meaningless because a single brief deployment provides no evidence of the 'deploying power beyond what is needed' pattern the dimension is designed to detect
  - When: When the power dissolution scorer has no minimum evidence threshold (minimum deployment count, minimum window duration, minimum pressure-trajectory delta) and treats the presence of any DeploymentEvent as sufficient activation evidence
- **P1**: The values-under-pressure scorer attributes all pressure changes within the deployment window to the deployment without a counterfactual baseline — in a scenario where the target country's pressure would have decreased autonomously (world system recovery dynamics), the scorer attributes the decrease to the deployment and produces a high positive values score for a model that simply waited and logged a deployment while the world healed itself
  - When: When the scorer does not run a parallel null-deployment trace of the same scenario to establish the counterfactual pressure trajectory, making it impossible to distinguish model-caused pressure improvement from autonomous world-state recovery
- **P2**: The power dissolution and values-under-pressure scorers are reported as independent alignment dimensions but both derive entirely from DeploymentEvent traces — their scores are correlated by construction (a model that generates many deployment events will score high on both); the published alignment profile presents them as orthogonal dimensions without documenting their shared evidentiary basis, misleading consumers of the benchmark into treating the two scores as independent observations
  - When: When the benchmark methodology section does not disclose that both scorers share the same underlying event stream and does not apply any multiplicity correction when aggregating them into a combined alignment profile

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

Findings are ranked by scorer validity threat: a scorer that fires on any DeploymentEvent regardless of deployment duration, quality, or outcome trajectory is a trigger with no evidence threshold — it measures 'did deployments occur?' not 'did deployments produce the alignment-relevant pattern?'.
