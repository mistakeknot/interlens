## Task Context

Tuivision is a TypeScript MCP server that spawns terminal apps via node-pty, captures screen state through xterm.js headless, and exposes get_screen (text/compact/full/annotated formats) and get_screenshot (PNG/SVG) tools. The brainstorm proposes adding getAnnotatedText() to the TerminalRenderer class (~150 new lines) alongside existing getScreenText() and getScreenState() methods. Color quantization is a private helper. screen.ts gets a new 'annotated' format case. The target is ~400-600 tokens per 80x24 screen using [r]...[/] inline markers.

## Severity Calibration

- **P0**: xterm.js exposes foreground/background colors through IBufferCell.getFgColor() but the return value encoding differs between xterm.js v4 and v5 (palette index vs RGB int vs named color) — if tuivision pins to one encoding assumption and the host environment has a different version, getAnnotatedText() silently emits wrong colors or throws on every cell read.
  - When: Occurs when the implementation does not check the xterm.js version range in package.json against the API usage, or when the quantization mapper assumes a specific color encoding format without normalizing first.
- **P1**: getAnnotatedText() iterates the terminal buffer independently of getScreenText(), causing two full buffer passes per get_screen call when both formats are requested — for a 220x50 terminal (11,000 cells) this doubles the CPU cost of screen capture, degrading latency for agents that poll frequently.
  - When: Triggered any time an agent or test calls get_screen with multiple format options, or when the default format change causes callers that previously used full to now also request annotated for comparison.
- **P2**: Wide characters (e.g., Japanese kanji or box-drawing characters) produce a primary cell followed by a zero-width continuation cell — if getAnnotatedText() emits a marker for each cell independently, the annotated output contains doubled markers around single visual characters, inflating token count and confusing the LLM about character boundaries.
  - When: Occurs in any TUI application that displays CJK text, unicode box-drawing, or emoji in the terminal buffer.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
