## Severity Calibration

- **P1**: A ECS component refactor splits MoodModifier into MoodModifier and MoodStack and renames the corresponding ontology class — all historical triples asserting 'feature X is implemented via MoodModifier' are now broken and the audit trail for that feature reads as unimplemented
  - When: No owl:equivalentClass bridge, redirect, or migration script is part of the refactoring protocol, leaving historical records orphaned from the new schema
- **P1**: The entire feature matrix ontology is stored in a single Turtle file — every sprint update touches dozens of features in this file, creating Git conflicts whenever two developers work in the same sprint and both update feature status
  - When: No sharding strategy (one file per DF system category, one file per sprint, or named graph per domain) is specified for the ontology storage layout
- **P2**: The ontology reaches version 3.x but historical queries from documentation, blog posts, and planning artifacts still use v1.x class IRIs — with no owl:priorVersion chain or redirect mechanism, these queries silently return empty results rather than failing with a schema mismatch error
  - When: Version IRIs are minted but backward compatibility shims (owl:equivalentClass, owl:sameAs bridges, or SPARQL inference rules) are not maintained across versions

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
