Mahrai reconciles intended session state (control-plane config) against live runtime state (tmux). ## Review Approach

### 1. Unknown track disposition: unknown_session drifts are emitted at severity='info'

- Unknown track disposition: unknown_session drifts are emitted at severity='info' — in ATC, an unknown track is never 'info'; it is at minimum a caution requiring immediate identification. Are there conditions where unknown sessions should escalate to 'warning' or 'critical'?

### 2. Positive control coverage: the reconciler only matches runtimes that have a

- Positive control coverage: the reconciler only matches runtimes that have a session_id set; runtimes without session_id are not checked for unknowns. This is a coverage hole — some valid runtimes may have no session_id and pass through without any drift record.

### 3. Radar return latency

- Radar return latency — is 'last_seen_at' used in any drift logic, or is it only stored? A runtime that last reported activity 72 hours ago but is still in the tmux list should trigger a different class of alert than one that just started.

### 4. Separation between intended sessions: when two sessions have overlapping

- Separation between intended sessions: when two sessions have overlapping project_id and agent_kind, the reconciler's session-to-runtime matching (one-to-one dict lookup) silently takes only the first match. In ATC this is a conflict alert — two aircraft on converging paths.

### 5. Sector boundary hand-offs: the canonical_host concept enforces locality but

- Sector boundary hand-offs: the canonical_host concept enforces locality but there is no mechanism for an authorized temporary deviation from canonical host to be logged with an expiry. Every host_mismatch looks identical whether it is a crisis or a planned maintenance move.

### 6. Strip-board completeness: the reconciler's output is five snapshot lists

- Strip-board completeness: the reconciler's output is five snapshot lists — but there is no human-readable 'strip' (like an ATC flight progress strip) that gives a one-line status for every session. Operators currently must parse JSON to understand the traffic picture.

## Severity Calibration

- **P0**: A runtime exists on the wrong host (host_mismatch), the session also has no runtime found (missing_runtime would not fire because a runtime was found), and the canonical host has no runtime — so the project is running nowhere it should be and the drift is only a 'warning'.
  - When: Aircraft has departed from an uncleared runway. The system recorded a host_mismatch but the intended sector has no aircraft on it at all — two independent failures that combine into a gap neither drift type catches alone.
- **P1**: load_runtime_inventory_from_tmux silently returns [] on any tmux error (returncode != 0). If tmux is unavailable, the reconciler would produce no runtimes, and all intended sessions would emit missing_runtime drifts — indistinguishable from a real outage vs. a reader failure.
  - When: Radar scope goes dark: the controller cannot distinguish 'all aircraft landed' from 'I lost radar'. The system needs a distinct 'reader_unavailable' signal separate from the drift report.
- **P2**: Two sessions in the control plane have the same desired_runtime_id; the reconciler's runtime_by_id lookup will silently bind both sessions to the same runtime without conflict detection.
  - When: Two flight plans filed for the same tail number. The system accepts both without flagging the conflict, and one session will simply never get a runtime it believes it has.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
