## Task Context

Hassease is a Go daemon that receives code instructions over Signal and routes them to GLM 5.1 / Qwen 3.6 (routine, ~80% of tasks) or Claude Sonnet/Opus 4.6 (complex, planning, review). The costrouter package makes per-turn model selection decisions based on task complexity signals (line count, file count, task type classification). The router 'starts cheap and escalates on evidence' — failed edits, low confidence, complexity signals trigger mid-task escalation. The routing strategy is explicitly cost-optimization, not capability gating. Hassease imports Skaffen's internal router package and extends it with GLM/Qwen providers.

- Spoilage vs. dilution threshold calibration: RM systems distinguish two error types — spoilage (keeping a seat empty that a low-fare buyer would have filled) and dilution (selling a seat cheaply when a high-fare buyer was incoming) — assess whether the routing decision boundary in the costrouter is calibrated against measured error rates from both error types, or whether the '80% to cheap models' target is an aspirational ratio that has not been validated against the actual error distribution of tasks routed to GLM/Qwen that should have escalated

## Severity Calibration

- **P1**: A task classified as 'simple single-file edit' is routed to GLM 5.1. During execution, GLM discovers that the edit requires modifying an interface definition used by six other files. The mid-task escalation trigger fires, but the escalation path attempts to hand off to Claude Sonnet with the full GLM conversation history as context — however, the conversation history format is GLM-specific and Claude's API rejects it, causing the escalation to fail silently and GLM to continue with a partial edit that breaks the interface consumers
  - When: When the mid-task escalation mechanism passes raw provider conversation history across provider boundaries without format normalization, and the failure of the escalation is treated as a non-fatal error that allows the cheap-tier model to continue rather than halting and reporting the escalation failure to the human operator
- **P1**: The 80% cheap-model routing target is implemented as a runtime counter: once 80% of session tasks have been routed to GLM/Qwen, the remaining 20% are routed to Claude regardless of complexity. A session with 10 tasks routes 8 to GLM (including 2 that should have escalated) and 2 to Claude (including 1 that GLM could have handled). The counter resets per session rather than per rolling window — a session with many simple tasks depletes Claude quota early, starving complex tasks later in the session
  - When: When the routing ratio is enforced as a hard per-session counter rather than as a complexity-signal-driven threshold, causing the routing target to function as a quota that overrides task complexity signals once the ratio is reached
- **P2**: A refactor task is correctly classified as Claude Sonnet class and routed accordingly. The refactor touches 4 files and produces correct changes. The costrouter logs '0 escalations in this session' as a success metric. However, 3 of the 4 files were also touched by a concurrent GLM task from a different Signal message — the two tasks have overlapping file scopes and the costrouter did not detect the concurrency, causing a merge conflict that requires human resolution and negates the cost savings from the GLM task
  - When: When the costrouter makes routing decisions independently per task without checking for file-scope overlap with concurrently executing tasks, and the concurrency detection responsibility is left to the tool registry rather than the routing layer

## Decision Lens

Evaluates through the lens of yield management's core tradeoff — routing tasks to cheap model tiers (GLM/Qwen) is a seat-availability decision: opening low-fare inventory risks dilution (cheap model handles a task that needed Claude, producing a wrong or incomplete result), while holding inventory for Claude risks spoilage (expensive model sits idle on work GLM could have handled). The design must correctly calibrate the escalation threshold — the demand signal that triggers closure of the cheap tier and reservation of capacity for the expensive tier — and must implement continuous nesting so that a task routed to a cheap model cannot 'block the seat' from Claude if mid-task complexity signals warrant escalation.
