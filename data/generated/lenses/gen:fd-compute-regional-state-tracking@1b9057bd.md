## Task Context

Shadow Work tracks per-country state in PressureStore (HashMap<String, CountryPressures>) and SupplyChainPhysicalEconomy (flat Vec indexed by country_index). The compute module must model heterogeneous country roles: Taiwan (fab), Netherlands (equipment), USA (consumer + sanctions authority), China (consumer + sanctioned), South Korea (fab + consumer). State must be serializable for save/restore via SimulationTicker::default() replacement.

## Review Approach

### 1. Unified state struct
- Verify ComputeCountryState (or equivalent) has fields for all roles: fab_capacity_nm7_wafers_per_month (producer), gpu_stockpile_units (consumer/military), data_center_capacity_gw (cloud/AI), equipment_export_license_tier (equipment supplier like NLD), and entity_list_membership (sanctioned receiver) — confirm no role requires a separate struct

### 2. Node-level granularity
- Check that advanced-node fab capacity is tracked at the node-size level (3nm, 5nm, 7nm, 28nm separately) rather than as a single capacity scalar — a country like CHN with mature-node capacity but no advanced-node capacity must be distinguishable from TWN without field overlap

### 3. Local resource constraints
- Assess water and energy as local constraints on data center scaling: data_center_capacity_gw should be bounded by regional energy_grid_headroom and water_stress_index — verify these are read from existing country-level fields (if they exist) rather than being hard-coded per-country constants

### 4. Directed export controls
- Verify the export control state is per-directed-pair, not per-country: USA can export to KOR but not CHN; NLD can export to TWN but is sanctioned for certain node sizes to CHN — confirm the data structure supports (exporter, importer, control_tier) triples, not just (country, control_tier) pairs

### 5. Save/restore cycle
- Check that compute state participates in the save/restore cycle: ComputeCountryState must be serde-serializable, included in the simulation snapshot, and correctly restored in from_snapshot() so that a saved game with a compute advantage correctly restores that advantage

### 6. GPU allocation tracking
- Evaluate GPU/TPU allocation tracking: if a country's gpu_stockpile is consumed by both military AI and civilian AI workloads, verify there is an allocation record (not just a total) so players and agents can observe the competition for scarce units and deployment actions can target specific allocations

## Decision Lens

Flag state designs where a country's role in the semiconductor ecosystem cannot be expressed without a code change — if TWN and USA differ only in field values, the schema is extensible; if they require different struct variants, that is a design smell.

## Success Criteria

- A country with no advanced fab capacity, no equipment export role, and entity-list sanctioned status can be fully described by ComputeCountryState field values alone — no code branch special-cases it
- Saving and restoring a simulation at tick N with CHN on the entity list and TWN at 40% fab capacity produces identical compute pressure outputs at tick N+1 as the unsaved simulation would
