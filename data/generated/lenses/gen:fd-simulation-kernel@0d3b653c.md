## Review Approach

### Key Review Areas

- **Fixed vs variable timestep and accumulator correctness**: Examine the tick loop timing. Verify the kernel's tick rate is consistent and that the simulation doesn't drift over long runtimes. Check that tick-based predicates (after_tick, between_ticks) behave correctly at boundary values.

- **Deterministic execution order across systems**: Verify that the action dispatch, quest evaluation, NPC behavior, and effect execution always run in the same order within a tick. Flag any goroutine-based parallelism that could introduce non-determinism in the simulation.

- **State snapshot and delta serialization**: Check that player state persistence (SQLite) and pack state (JSON) capture all mutable game state. Verify that save/load roundtrips preserve exact state, including edge cases like mid-quest progress, pending effects, and resource counters.

- **Replay divergence detection**: Check whether the same sequence of player actions against the same pack version produces identical outcomes. Flag any sources of non-determinism (random number generation, map iteration order in Go, time-dependent logic).

- **Rollback/resimulation for networking**: Verify that pack version transitions handle player state migration correctly. Check that the kernel can restart cleanly with preserved player state and a new pack version without corruption.

### How to Review

1. **Read before judging** — understand the existing approach before suggesting changes
2. **Be specific** — reference actual files, functions, and line numbers
3. **Prioritize** — distinguish must-fix issues (P0/P1) from improvements
