## Review Approach

### 1. Empty-versus-error distinction at the Selector interface: Select returning

- Empty-versus-error distinction at the Selector interface: Select returning ([]Lens{}, nil) must be semantically distinct from (nil, err) — the former means 'the model found no suitable lenses' while the latter means 'the advisory system failed'; downstream callers must handle each case explicitly, and the HaikuSelector must never collapse a context timeout into an empty list return with nil error

### 2. 15-second context timeout adequacy under provider latency variance: the plan

- 15-second context timeout adequacy under provider latency variance: the plan specifies a 15-second timeout for HaikuSelector; under high-load conditions Haiku's p95 latency may exceed 15 seconds; if the timeout fires, the selector returns gracefully — but the caller has no signal about whether to retry, fall back to a default lens set, or surface a degraded-mode indicator to the user

### 3. Fallback lens set specification: the plan says 'graceful degradation (empty

- Fallback lens set specification: the plan says 'graceful degradation (empty list on error)' — this is not a graceful degradation design, it is a silent failure; a genuine graceful degradation strategy requires a pre-specified fallback lens set (e.g., the 15 bridge lenses, or the top-5 lenses by prior effectiveness score) that the caller uses when Select returns an empty result or an error

### 4. Structured output parsing fragility: the selector parses a JSON array from LLM

- Structured output parsing fragility: the selector parses a JSON array from LLM output, handling markdown fences and extra text; this is a pattern with well-known failure modes (model outputs a JSON object instead of array, array contains invalid lens IDs, array is empty because the model refused the task) — each failure mode must produce a typed error, not a panic or a silently empty result

### 5. Provider-agnostic interface boundary: the plan supports Haiku and GLM 5.1 via

- Provider-agnostic interface boundary: the plan supports Haiku and GLM 5.1 via provider.Provider; if the two providers return different lens ID formats (e.g., one uses numeric indices, one uses lens name strings), the parsing layer must normalize before returning — the Selector interface contract must specify what format lensIDs take in the returned []Lens, not leave it to each provider implementation to decide

### 6. Retry and backpressure policy: ATFM systems have explicit re-clearance

- Retry and backpressure policy: ATFM systems have explicit re-clearance procedures when the advisory system is degraded; the HaikuSelector must specify whether it retries on transient errors (connection reset, 429 rate limit) and if so, with what backoff policy and maximum retry count, because an unbounded retry loop inside Select will block the agentloop goroutine for far longer than 15 seconds under sustained provider degradation

## Severity Calibration

- **critical**: Context timeout collapses into ([]Lens{}, nil) — caller cannot distinguish timeout from no-lenses-found
  - When: Skaffen's provider experiences a 30-second Haiku latency spike; HaikuSelector's context fires after 15 seconds and returns an empty list with nil error; the agentloop treats this as 'model found no relevant lenses' and proceeds without any lenses applied; the user receives a response with no lens framing applied and no indication of degraded mode — the degradation is invisible in both the user experience and the application logs
- **high**: JSON parsing panics on LLM output that is a JSON object instead of array
  - When: A Haiku response for an ambiguous message returns {"lenses": [1, 3, 7]} instead of [1, 3, 7] — the parser calls json.Unmarshal into a []int target, which returns a type mismatch error; if the parser does not handle this error and falls through to a nil slice, the agentloop proceeds with zero lenses applied; if the parser panics, it crashes the goroutine and potentially the entire agentloop without recovery
- **medium**: GLM 5.1 returns lens IDs as name strings while Haiku returns 1-indexed integers; Selector interface does not specify which format callers should expect
  - When: A caller that switches from Haiku to GLM 5.1 via environment variable receives lens ID strings instead of integers; the downstream lens lookup (which uses the integer index from the embedded JSON) silently finds no matching lenses and returns an empty selection — the caller has no error, no warning, and no indication that the provider switch changed the ID format contract

## Decision Lens

The boundary between the LLM advisor and the deterministic system must be a typed contract with an explicit failure mode. The selector (LLM) outputs a []Lens with zero or more elements; the caller must define behavior for all three cases — non-empty, empty, and error — before the selector is integrated. An LLM advisory that returns an empty list because the model timed out must be distinguishable from an empty list because the model found no relevant lenses, because the two cases require different downstream handling. Any implementation that collapses these into a single 'return what we got' pattern has failed to define the integration boundary and will produce silent degradation under load. If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.
