## Task Context

The Gmail purchase import pipeline fetches potentially years of email history via Gmail API (gmail.readonly), parses them per-retailer, then batch-upserts to interjawn MCP (product data) and Auraken context DB (purchase patterns). The pipeline must handle Gmail API quotas, large import volumes, and dual-destination writes. The baray lens evaluates whether the flow architecture can absorb volume spikes, resume after failure, and distribute to multiple consumers without loss.

## Severity Calibration

- **P0**: No backpressure — pipeline floods downstream systems
  - When: Importing 5 years of Amazon history fires thousands of concurrent MCP upsert calls, overwhelming interjawn — like opening all sluice gates during peak monsoon
- **P1**: Non-resumable batch processing
  - When: Pipeline failure at email 3,000 of 5,000 requires re-processing all 5,000 — no checkpoint state, like a baray with no water-level markers
- **P2**: Unparseable emails block the pipeline
  - When: A single malformed email causes the entire batch to fail rather than being diverted to a spillway for later triage

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

Baray hydraulics — transform a massive, irregular input pulse (monsoon rains / Gmail API batch response) into a controlled, steady distribution flow. The system must absorb volume spikes without overflow (backpressure), guarantee delivery to every downstream consumer (no dropped items), and be idempotent (the same rain falling twice must not flood the fields). If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.

- P0: Issues that block other work, cause data loss or corruption — drop everything
- P1: Issues required to exit the current quality gate
- P2: Issues that degrade quality or create maintenance burden
- P3: Improvements and polish — suggest but don't block on these
- For each P0/P1 finding, describe the concrete failure scenario: what breaks, under what conditions, and who is affected
