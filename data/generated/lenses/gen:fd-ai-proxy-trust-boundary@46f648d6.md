## Task Context

Garden Salon's 'bring your own compute' model means participants supply their own LLM API keys. The AI proxy currently reads content to send to LLM providers. The encryption brainstorm presents four options for AI under encryption: server sees plaintext, encrypted AI (impossible today), opt-out, and client-side AI. The platform's core value is collaborative human-agent work.

## Review Approach

### 1. Trust model incoherence

- Trust model incoherence — the design presents AI proxy plaintext access (Dimension 3A) as a trust compromise, but participants using 'bring your own key' already send their content to LLM providers. If the threat model is 'protect content from the server operator,' the AI proxy is a real concern. If the threat model is 'protect content from external parties,' the LLM provider is the larger exposure and the AI proxy is a secondary channel for the same trust decision.

### 2. Client

- Client-side AI viability (Option 4) — calling LLM APIs directly from the browser requires exposing API keys in client-side code, which is a security anti-pattern. Rate limiting, cost controls, and abuse prevention cannot be enforced client-side. The design presents this as a privacy win without acknowledging the security tradeoffs it introduces.

### 3. Confidential computing as a middle path

- Confidential computing as a middle path — the design does not mention secure enclaves (Intel SGX, AWS Nitro Enclaves, Azure Confidential Computing) as a mechanism for the AI proxy to process plaintext without the operator being able to read it. This is an active area of industry practice for exactly this use case and its absence from the design space is a gap.

### 4. AI context window

- AI context window and encryption granularity — LLMs need coherent context (full document or large sections) to be useful. If encryption is per-field or per-update, the client must decrypt and reassemble full context before sending to the LLM. This means the client is the only place where full document plaintext exists, which may conflict with mobile or low-powered device targets.

### 5. Streaming responses under encryption

- Streaming responses under encryption — AI responses streamed from LLM providers must be encrypted before being relayed to other participants via the server. If the AI proxy is eliminated (client-side AI), only the requesting participant sees the response until they manually share it through the encrypted CRDT channel. This changes the collaborative AI interaction model the platform is built around.

## Severity Calibration

- **P1**: Client-side API keys exposed in browser
  - When: Option 4 (Client-Side AI) requires participants to call LLM APIs directly from the browser. API keys stored in browser memory or localStorage are extractable by browser extensions, XSS attacks, or any code running in the same origin. A single compromised participant leaks their API key, incurring unbounded cost. The design presents this as a feature without a security analysis.
- **P1**: AI proxy as covert plaintext channel
  - When: In the Sealed Rooms model (Option 5), a sealed garden disables server-side AI. But if a participant uses the AI proxy in an open garden and pastes content from a sealed garden into a prompt, the server-side AI proxy sees sealed content through a side channel. The design does not address cross-garden content flow through the AI proxy.
- **P2**: Collaborative AI breaks under client-side-only model
  - When: Garden Salon's core value proposition is collaborative human-agent work. If AI runs client-side only, agent contributions are not visible to other participants in real-time — they must be encrypted and pushed through the CRDT channel, adding latency and complexity. The design does not analyze how client-side AI affects the collaborative experience.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.

- P2: Issues that degrade quality or create maintenance burden
- P3: Improvements and polish — suggest but don't block on these
