## Severity Calibration

- **P1**: Answering 'what work can I pick up next sprint' requires a SPARQL query that computes the transitive closure of the dependency graph, which times out on a triplestore without pre-computed closure indexes after the graph exceeds 200 features
  - When: No materialized transitive dependency view or cached closure is specified, leaving all path queries as runtime property path evaluations
- **P1**: The simulation-side ontology requires syncing ECS world state to the triplestore every tick to answer in-game procedural queries, creating a 16ms sync budget that is impossible to meet with any RDF serialization strategy
  - When: No boundary is drawn between simulation-side data that lives in the triplestore vs. data that lives in ECS — all simulation state is treated as ontology data
- **P2**: The feature audit trail becomes unsynchronized with the beads issue tracker because updates to beads are not reflected in the ontology, or vice versa — creating two authoritative sources that disagree on implementation status
  - When: No specified synchronization protocol or single-source-of-truth designation for feature status between beads and the ontology

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
