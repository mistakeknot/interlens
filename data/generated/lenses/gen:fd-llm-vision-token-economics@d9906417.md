## Task Context

Tuivision is a TUI testing/automation MCP server that gives AI agents visual access to terminal applications. Current modes: get_screen text (~200-400 tokens, no style), get_screenshot png (~1600 vision tokens), get_screenshot svg (~2000-8000 tokens, contains text+style but verbose). The goal is a new representation that captures text + task-relevant visual semantics at significantly fewer tokens than PNG/SVG while preserving the semantic information that plain text loses. Ideas already proposed include local OCR on PNGs and optimized SVG stripping.

## Severity Calibration

- **P0**: The cost model assumes vision tokens are priced identically to text input tokens, but Anthropic actually charges vision tokens at a different effective rate due to the tile-based counting — the 'optimization' that switches to text saves fewer dollars than projected, or none at all.
  - When: Occurs when the economic analysis uses simplified token-count comparisons without provider-specific vision pricing models.
- **P1**: The analysis ignores prompt caching: a text-based representation that changes every turn (breaking cache) may cost more than a stable PNG that gets cached, because the cache discount on input tokens exceeds the vision token premium.
  - When: Triggered when the optimized text representation includes dynamic elements (cursor position, timestamps) that vary per call and prevent prefix caching.
- **P2**: The cost model only considers input tokens and ignores that a lower-fidelity representation causes the LLM to generate longer reasoning chains (more output tokens) to compensate for ambiguous input, partially or fully offsetting the input savings.
  - When: Occurs in complex TUI tasks where the LLM must infer layout structure from text that a screenshot would have made immediately obvious.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

The cheapest representation that achieves the required task accuracy wins. But 'cheapest' must account for the full cost: input tokens, output token changes (a worse representation may cause longer chain-of-thought), retry costs from misinterpretation, and engineering maintenance cost of the encoding pipeline. A solution that saves 500 input tokens but causes 200 extra output tokens and 10% more retries is not actually cheaper. If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.
