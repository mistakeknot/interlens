- **P1**: The mode classification weights (emotional=3, analytical=2, others=1) produce unstable classifications for messages near mode boundaries — a message scoring emotional=6 and analytical=5 is classified as emotional, but adding a single word ('however') pushes analytical to 7 and flips the classification, and since the EMA accumulator treats each classification as ground truth for profile updates, a sequence of near-boundary messages causes the per-mode fingerprints to oscillate between modes rather than converging, corrupting the accumulated style profile
  - When: When real conversation messages frequently score within 1-2 points of each other across multiple modes, and the winner-take-all classification (highest weighted score wins) amplifies small scoring differences into categorical mode switches that the EMA accumulator treats as definitive
- **P2**: The capitalization ratio observable is computed over all characters including emoji, URLs, and non-alphabetic content, diluting the signal — a message that is entirely lowercase text with a URL containing uppercase letters (https://GitHub.com) gets a non-zero capitalization ratio that does not reflect the user's actual capitalization style, and this noise propagates through the EMA accumulator into the mirroring instructions, potentially generating 'use some capitalization' advice for a user who never capitalizes
  - When: When ComputeObservables does not filter non-prose content (URLs, code blocks, emoji) before computing capitalization ratio, and such content appears frequently enough in real messages to measurably skew the ratio

## Decision Lens

Every feature extraction and classification system evaluated as a tea assessment problem: are the observables truly independent (can each be extracted without interference from others), or do some extraction techniques contaminate adjacent measurements? Are the extraction techniques specific enough that two independent extractors produce the same values, or do they leave room for subjective interpretation? Are the classification weights defensible and documented, or are they implicit conventions that different implementers might apply differently? The cha shi's cardinal principle is that extraction must precede classification — you never taste with a category already in mind, because confirmation bias corrupts the observables. If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.
