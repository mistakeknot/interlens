Creative approaches to enriching a TUI/ASCII colony sim (Elf Revel) beyond traditional terminal constraints. The game is a Rust colony sim using rust_pixel/crossterm for terminal rendering at 120x40 characters. Current rendering uses simple single-character glyphs (. for meadow, # for stone, ~ for water, H/W/G/F for buildings, first-letter for elves) with basic Color enum values (Green, Blue, White, etc.). ## Review Approach

### 1. Selection operator

- Selection operator and the critical question of what NOT to render: at 120x40, every character cell is precious — a map at roughly 1:10,000 equivalent where most real-world features must be omitted. Cartographic selection asks: what features serve the MAP'S PURPOSE at this scale? In a colony sim, the purpose shifts between 'manage resources' and 'appreciate the living world.' Does the rendering design define selection criteria that change based on the player's current intent (management mode vs. appreciation mode), or does it attempt to show everything always? Showing flora entities, building details, terrain texture, and weather simultaneously at 120x40 may violate the cartographic principle that omission is the primary tool of legibility.

### 2. Exaggeration operator

- Exaggeration operator and the sixel/kitty question: cartographers routinely exaggerate important small features — a 2-meter-wide road becomes visible at 1:50,000 because it is drawn 10x wider than scale would warrant. The sixel and kitty image protocols offer sub-cell resolution, but the cartographic question is: which features deserve exaggeration beyond their 'true' grid size? An elf entity might warrant 2x2 character exaggeration when selected, while terrain fades to half-resolution background. Does the enrichment plan use variable resolution as a SELECTIVE EXAGGERATION tool (important things get more pixels, unimportant things get fewer), or as a uniform resolution increase?

### 3. Imhof relief shading

- Imhof relief shading and the lighting-direction convention: Swiss cartographic relief shading creates 3D terrain from 2D maps through a single convention — consistent northwest illumination. Terminal color could implement an analogous convention where brightness systematically encodes a spatial property (elevation, proximity to player attention, recency of change). Does the design establish a CONSISTENT LIGHTING CONVENTION — a single spatial rule that viewers internalize and then read unconsciously — or does brightness vary per-element without a unifying spatial logic?

### 4. Classification operator

- Classification operator and the visual hierarchy problem: cartographers classify features into hierarchical types (highway vs. road vs. track vs. path) rendered with systematically different visual weight. The current rendering uses ad-hoc colors (Green for meadow, Blue for water) without a classification hierarchy. Does the enrichment plan define a systematic visual hierarchy where the most important features have the heaviest visual weight (widest, brightest, most saturated) and less important features systematically recede? The Swiss cartographic tradition uses exactly four levels of visual weight — does the terminal rendering define analogous weight levels?

### 5. Displacement operator

- Displacement operator and the label/entity conflict problem: when two features are too close to render at scale, cartographers displace one slightly for legibility rather than letting them overlap. At 120x40, entities WILL overlap — two elves on adjacent tiles, a building touching a forest edge. Does the rendering design have a displacement strategy for overlapping entities (priority-based occlusion, offset rendering, abbreviation), or does it render by z-order and accept that lower-priority features disappear? A well-generalized map never loses a feature to overlap without a conscious decision.

### 6. Multi

- Multi-scale consistency and the rendering pipeline architecture: professional map series (1:25,000, 1:50,000, 1:100,000, 1:200,000) use RELATED visual grammars — the same road appears at all scales but with scale-appropriate generalization. If the enrichment plan includes multiple rendering modes (ASCII, half-block, braille, sixel), do they form a CONSISTENT FAMILY where the same underlying data renders through related but scale-appropriate grammars? Or is each mode an independent rendering engine with its own ad-hoc visual language, forcing the player to re-learn the visual grammar when switching modes?

## Severity Calibration

- **P1**: The rendering attempts to show all information simultaneously at 120x40 — terrain texture, flora entities, building details, elf positions, weather effects, resource overlays — violating the cartographic principle that the primary tool of legibility is omission, producing an unreadable visual cacophony
  - When: No selection framework defines which information layers are visible at which zoom levels or in which interaction modes — all layers render simultaneously with no information hierarchy
- **P2**: Higher-resolution rendering modes (sixel, kitty, braille) are applied uniformly rather than as selective exaggeration — background terrain gets the same resolution increase as foreground entities, diluting the attention-directing power of variable resolution
  - When: The enrichment plan applies new rendering capabilities (half-block, braille, sixel) as blanket upgrades across the entire viewport rather than as selective tools applied to high-importance features
- **P2**: Multiple rendering modes (ASCII, half-block, sixel) each use unrelated visual grammars — different color meanings, different glyph conventions, different spatial layouts — requiring the player to re-learn the interface for each mode rather than recognizing a consistent family of representations at different scales
  - When: Each rendering mode is designed independently with no shared visual grammar document specifying how the same game concept appears across all modes

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
