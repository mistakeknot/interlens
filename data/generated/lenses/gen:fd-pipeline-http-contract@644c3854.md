## Severity Calibration

- **P0**: edit-chunk fires an HTTP request to the pipeline worker; the response is cut off by a proxy timeout; the MCP server retries, causing the pipeline to process the chunk a second time with different output.
  - When: Occurs on any LLM call that exceeds the intermediate proxy timeout, common for large chunks at high load.
- **P1**: The PIPELINE_AUTH_TOKEN is read at MCP server startup; if rotated server-side, all subsequent calls return 401 with no recovery guidance.
  - When: Occurs after any pipeline worker restart that regenerates the token.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

A pipeline call that times out after 90 seconds must be treated as outcome-unknown, not as a failure — the worker may have completed the edit and just failed to respond. Any design that retries such a call will double-process a chunk, corrupting the document. If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.
