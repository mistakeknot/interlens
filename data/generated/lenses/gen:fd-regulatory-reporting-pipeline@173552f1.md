## Task Context

F5 builds a TemplateRegistry of 8 named QueryTemplate protocol classes bridged to MCP tools via a Go subprocess adapter. Each template's execute() method joins data from multiple connectors and returns a QueryResult dataclass. The Go adapter serializes Python's QueryResult to JSON over stdin/stdout. Templates must compose existing primitives (crosswalk, engine, connectors) without adding new storage.

## Review Approach

### 1. Output schema validation before result delivery: regulatory reporting pipelines

- Output schema validation before result delivery: regulatory reporting pipelines validate every output record against the submission schema before writing to the output file — a mistyped field or missing required attribute fails the entire report and blocks submission. Assess whether QueryResult has a validation step before it is serialized by the Go subprocess protocol: are required fields present, do relationship types match the ontology's type system, and are entity identifiers in canonical form — or does the Go adapter receive and forward raw Python output without schema validation, allowing malformed results to reach MCP consumers silently

### 2. Completeness attestation and the mandatory-field problem: regulatory reports

- Completeness attestation and the mandatory-field problem: regulatory reports distinguish between fields that are required for every submission and fields that are conditionally required based on the report type — missing a mandatory field is a fatal error, missing a conditional field may be acceptable. Assess whether QueryResult's entities and relationships fields have a defined mandatory-vs-optional structure per template: for bead_context, is the bead's owning actor always required, or only when an actor exists? What is the behavior when a mandatory field cannot be populated because the connector returned an error?

### 3. Audit trail from query invocation to result: regulatory reporting requires

- Audit trail from query invocation to result: regulatory reporting requires traceability — every submitted figure must trace back to the source system, extraction timestamp, and transformation steps. Assess whether QueryResult.metadata captures sufficient provenance for a developer to diagnose why a query returned a specific result: which connector versions were active at execution time, what the crosswalk lookup returned before relationship resolution, and whether the engine applied any inference rules that are not obvious from the result. Without this, debugging wrong results requires re-running the query and hoping conditions are identical

### 4. Idempotent execution and deterministic results: regulatory pipelines must

- Idempotent execution and deterministic results: regulatory pipelines must produce the same result when re-run with the same parameters at the same logical point in time — a report that returns different results on re-run due to connector state changes or crosswalk cache staleness is unacceptable. Assess whether QueryTemplate.execute() produces deterministic results for the same canonical ID and whether re-running a template query with the same parameters at different times can produce different relationship graphs due to cass indexing changes or crosswalk cache updates that occurred between invocations

### 5. Error taxonomy and the fail-fast vs. partial-result tradeoff: regulatory

- Error taxonomy and the fail-fast vs. partial-result tradeoff: regulatory submissions cannot be partially wrong — a firm either submits a complete, correct report or holds the submission until the data is available. Assess whether the QueryTemplate protocol defines an error taxonomy that distinguishes between fatal errors (connector unreachable: do not return partial result), non-fatal gaps (connector returned empty set for this entity: return with gap annotation), and validation errors (result failed schema check: do not deliver to consumer) — or whether the protocol silently returns whatever is available, leaving consumers to decide how to handle incomplete data

### 6. Submission deadline and the latency-completeness tradeoff: regulatory reports

- Submission deadline and the latency-completeness tradeoff: regulatory reports have hard submission deadlines — a report that is 100% correct but delivered 5 minutes late is a regulatory breach. Assess whether QueryTemplate.execute() has latency SLAs that are declared per template (based on the number of subsystems joined and typical connector latencies), and whether the Go MCP adapter propagates these SLAs to the calling agent so the agent can decide whether to invoke a high-latency template (entity_timeline) or a lower-latency alternative (entity_relationships) when operating under time constraints

## Severity Calibration

- **P1**: The entity_timeline template aggregates crosswalk history and identity chain data. The crosswalk SQLite database is locked by a concurrent write operation (the crosswalk indexer is updating). The template's connector call raises an OperationalError. The execute() method catches the exception and returns a QueryResult with an empty events list and no error indication in metadata. The Go adapter serializes the empty result and delivers it to the calling agent. The agent interprets the empty timeline as 'this entity has no history' and marks it as newly created, when it actually has six months of history.
  - When: When QueryTemplate.execute() has exception handlers that convert connector errors into empty results rather than into structured error states in QueryResult.metadata, causing connector failures to be indistinguishable from genuine empty-result answers
- **P1**: The session_entities template is invoked with a session ID from cass. The cass connector returns a list of file paths touched during the session. The template passes these file paths to crosswalk to resolve canonical entity IDs. Crosswalk has not yet indexed three of the files (they were created in the same session and the indexer runs asynchronously). Crosswalk returns None for those three files. The template silently drops the three unresolved files from the result. The agent receives a session_entities result that omits 30% of the files touched during the session, with no indication of the omission.
  - When: When the template's crosswalk resolution step silently drops entities that crosswalk cannot resolve rather than including them in the result with a resolution_status of 'unresolved', causing coverage gaps to be invisible to the consumer
- **P2**: The QueryResult dataclass's metadata field is a plain Python dict with no enforced schema. Different templates populate it with inconsistent keys: who_touched_file writes metadata['source_connectors'] while bead_context writes metadata['connectors_used']. The Go adapter serializes the metadata dict as-is into the MCP response. Agents that inspect metadata to detect partial results must handle both key variants. A monitoring script that checks metadata['source_connectors'] for all templates silently misses bead_context's connector status because it uses the wrong key.
  - When: When QueryResult.metadata is a free-form dict rather than a typed dataclass with required fields, causing inconsistent metadata key naming across templates that breaks consumers who rely on metadata for completeness detection

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
