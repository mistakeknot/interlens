## Task Context

F5 builds a TemplateRegistry of 8 named QueryTemplate protocol classes, each exposed as a typed MCP tool by the Go adapter. Agents invoke these tools to get cross-system context for development decisions. The 8 templates span question types: who touched this (actor provenance), what is connected to this (relationship graphs), what happened to this (timelines), what evidence exists about this. Results must be structured and actionable for the calling agent.

- Alert fatigue analog: result noise and signal-to-noise calibration: CDS systems with low-specificity rules produce so many alerts that clinicians dismiss all of them, including the critical ones. - Result currency and the stale-data-for-live-decision problem: CDS rules that use stale data can cause patient harm — a drug interaction check against a medication list that hasn't been updated since admission is dangerous. - Query chaining and the multi-hop coherence problem: CDS workflows often chain queries — a sepsis screen fires, the clinician reviews the result, then queries a care plan template with the patient's ID. - Feedback loop and the rule effectiveness problem: CDS rules that are never acted on should be retired or redesigned — CDS governance requires tracking which rules clinicians override, ignore, or act on. ## Severity Calibration

- **P1**: The related_artifacts template uses the structure interaction rule to return structurally related artifacts for a central utility module (e.g., interweave's crosswalk.py). The rule returns 47 artifacts: every file in the codebase that imports crosswalk. The QueryResult contains 47 entity stubs with no relevance scoring, no relationship strength indicators, and no filter for relationship recency. The calling agent receives a 47-item result set and must decide which of the 47 artifacts are relevant to its current task. The agent, unable to rank the results, treats all 47 as equally relevant and includes all of them in its working context, exhausting its token budget before completing the task.
  - When: When related_artifacts has no relevance threshold, result limit, or ranking mechanism, causing high-degree nodes in the artifact graph to produce unboundedly large result sets that are operationally useless to the consuming agent
- **P1**: An agent invokes bead_context for a bead that is currently being actively worked on (a session is in progress, files are being edited). The template joins beads connector + crosswalk + engine. The crosswalk cache was last updated 45 minutes ago, before the active session began editing files. The bead_context result shows the file relationships as they existed 45 minutes ago — the agent acts on the stale context, makes a conflicting edit to a file that the active session is also editing, and creates a merge conflict. The QueryResult.metadata contains no indication that crosswalk data is 45 minutes old.
  - When: When QueryResult.metadata does not include per-source freshness timestamps and the template does not warn when crosswalk cache staleness exceeds a defined threshold for a query type where stale data creates operational risk
- **P2**: The TemplateRegistry is initialized and the 8 templates are registered. Over time, 3 additional templates are added. Some of these new templates cover overlapping question types: a new 'actor_files_touched' template covers a subset of what actor_activity covers, but with different parameter names and a different result structure. Agents that learned to use actor_activity now have two valid options for similar queries, with no guidance on which to prefer. The MCP tool listing grows to 11 tools covering partially overlapping question domains. Agents begin invoking the wrong template for their use case, producing results that are technically valid but answer a subtly different question than intended.
  - When: When the TemplateRegistry has no governance mechanism for detecting and resolving overlapping template scope, causing the tool listing to accumulate redundant templates that create agent confusion rather than expanding coverage

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

Evaluates through the lens of CDS rule design: a named clinical query is a high-stakes structured retrieval that must return actionable context in a form the consumer can act on immediately — not a data dump, not a partial result, not a result whose completeness depends on which modules happen to be populated. The critical failure modes are query results that require the consumer to reason about data quality before acting, results whose structure does not map cleanly to the decision the consumer must make, and queries that fire or are invoked in contexts where their results are not actionable.
