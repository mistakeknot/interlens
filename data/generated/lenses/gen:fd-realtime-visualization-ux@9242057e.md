## Task Context

Meadowsyn is Garden Salon's three-layer visualization: L1 (WebGL ambient field encoding project health), L2 (FIDS split-flap board for glanceable status), L3 (interactive detail panels). The non-developer persona (Ryan) needs to understand what agents are doing without developer tools. The review target is the visualization strategy and its coherence with the product mission.

## Review Approach

### 1. Three-layer architecture coherence
- Does L1 (ambient field) actually communicate useful information, or is it decoration?
- L2 (FIDS board) — what exactly is displayed? Participant status? Direction progress? Attribution?
- L3 (interactive detail) — is this where the real work happens? If so, what are L1/L2 for?
- Is the three-layer model tested with users, or is it an aesthetic choice?

### 2. Ryan's comprehension path
- Ryan needs to see "track changes appearing" — which layer handles this?
- Can Ryan understand the direction lifecycle from the visualization alone?
- Attribution display timing (aggregate shown only after terminal state) — how does the in-progress view help Ryan make decisions?
- What does "agent presence" look like visually? Activity descriptors, reasoning streams?

### 3. Cognitive load management
- Multiple agents + multiple directions + multiple participants = information overload
- How does the visualization prioritize what to show? Is there a focus/defocus model?
- What does the view look like with 1 agent vs 5 agents vs 15 agents?
- The "garden purpose" field is supposed to be an orientation signal — is it surfaced prominently enough?

### 4. Technical feasibility
- WebGL ambient field on a web platform — what about mobile? Low-power devices?
- FIDS split-flap animation — charming, but does it work at scale? What about screen readers?
- Real-time updates from Yjs awareness → visualization pipeline — what's the latency budget?

### 5. Meadowsyn port maturity
- How much of Demarch/Meadowsyn is production-ready vs research prototype?
- Is the port a lift-and-shift or a rethink? Should it be a rethink?

## Severity Calibration

- **P0:** The visualization is incomprehensible to the non-developer persona
- **P1:** The three-layer model has no clear information architecture
- **P2:** Technical feasibility gaps for target platforms
- **P3:** Aesthetic choices that don't serve comprehension
