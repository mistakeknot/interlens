## Severity Calibration

- **P0**: The privacy_class -> allowed (tier, destination) flow rules are implemented as parallel if/else logic in Swift and Python rather than loaded from the single shared data file described in the brainstorm.
  - When: Any drift between the two implementations of the flow-rule table would silently permit a §8 invariant violation (e.g., raw_quarantined reaching cloud_burst) in one language but not the other — exactly the 'undefined control is not a control' failure the M0 amendment was written to prevent.
- **P1**: Conformance vectors only include obviously-valid and obviously-invalid manifests, with no boundary/edge vectors (e.g., a manifest at exactly the tier boundary, a privacy_class value that existed in a prior draft).
  - When: Vector coverage this thin will pass CI while leaving real classification disagreements between Swift and Python undetected until a field incident.

  - When: Left open past M0, this becomes an undocumented convention negotiated ad hoc at M1-M4, the same way un-versioned ISO 20022 extensions caused years of interop pain across banks.
