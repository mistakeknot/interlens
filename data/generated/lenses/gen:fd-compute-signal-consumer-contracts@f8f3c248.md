## Task Context

Shadow Work uses pressure amplification as the primary signal mechanism between emergence modules — issues emit (country_id, PressureType, delta) tuples consumed by the pressure store. The compute module must emit signals consumed by technology adoption, economy (GDP modifier), and military modules. The debug server exposes /diag/ endpoints consumed by sw-agent for smoke tests and assertions.

## Review Approach

### 1. Signal enumeration
- Enumerate all signals the compute module is expected to emit — compute_capacity_index (0..1 per country), gpu_allocation_ratio, export_control_tier (enum), data_center_energy_pct — and verify each has a named consumer in technology/, economy/, or military/ with a documented application site

### 2. Tick ordering
- Check the signal bus pattern: if compute emits pressure amplification deltas like collect_pressure_amplification() does for issues, verify the tick order means compute runs before the pressure amplification collection phase so consumers see current-tick values, not last-tick values

### 3. Feedback loop safety
- Audit the 'compounding multiplier' contract: compute_capacity_index feeding into technology adoption rate which feeds back into compute capacity growth is a feedback loop — verify there is a one-tick delay or normalization step preventing runaway compounding within a single tick

### 4. Export control directionality
- Check whether export_control_tier is a per-country-pair signal or a per-country signal — if country A is on the entity list, the signal must block flows A→B and B→A asymmetrically; a per-country scalar cannot encode directionality

### 5. Military integration path
- Verify military module consumption: GPU/TPU allocation to military AI should express as a pressure modifier on military_capability_pressure, not as a direct stat bonus — confirm the integration goes through the pressure system rather than a direct field write

### 6. Debug endpoint
- Assess the debug server handler for compute state: verify a /diag/compute endpoint exists (parallel to /diag/economy) returning ComputeDiag with per-country capacity, allocation, and export control status, so sw-agent can assert on compute state

## Decision Lens
