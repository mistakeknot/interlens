## Severity Calibration

- **P0**: EnrichedModel contains Map<string, number> instances attached during scoring. If BestForTiles passes scored models as props to a use client child component, Next.js will throw a serialization error at runtime because Maps are not serializable across the RSC boundary.
  - When: Only applies if BestForTiles or any wrapper passes raw scored model objects with Map fields to a client component rather than extracting only the plain fields needed for rendering.
- **P1**: The Wizard component uses useSearchParams() to read ?useCase= for pre-filling step 1. Since useSearchParams() requires a Suspense boundary, omitting it causes the entire /recommend route to deopt to client-side rendering, breaking the revalidate=3600 ISR behavior.
  - When: If the wizard is updated to read searchParams for pre-fill without wrapping in Suspense, this silently degrades the page caching behavior.
- **P2**: The homepage fetches cachedGetAllExternalScores() and passes scores through computeAgMoBench() + withCompositeScores() even after the scatter plot is removed, inflating the cached payload size for a data set that BestForTiles only partially needs.
  - When: If BestForTiles only needs agmobench sub-scores (not full composite scores), the withCompositeScores() call becomes dead weight that increases ISR cache payload size unnecessarily.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
