## Severity Calibration

- **P0**: The per-item fixed cost — plan authoring, spawn, the executor's 20-40K orientation, the validator's independent re-orientation, and the report read back into main context — is never stated, while the ≤50% share gate rewards moving generation off the main thread, which is achieved most easily by cutting a goal into more, smaller items. At plausible item sizes the re-priming paid twice or three times per item exceeds the main-thread context each item saved, so a goal can pass its gate while costing more in total than the baseline it replaced.
  - When: P0 because it inverts the design's purpose while satisfying its only enforcement mechanism, and the pilots cannot detect it: the meter reports share, not total, so the more finely a pilot is sliced the better it scores and the worse it does. Three pilots run this way would ratify the shape on the strength of the number that hides the defect.
- **P1**: Both the ≤50% gate and the three pilot results are measured at cut-off — when the validator returns PASS and the goal's session ends — with no defined finish event. Orchestrator repair turns after a returned item, plan-template growth, and the follow-up fix sessions a thin plan generates all land after that measurement, so the pilot figures are loom-state numbers that shrink under washing.
  - When: P1 rather than P0 because the error is directional and correctable by defining the finish event before the pilots run, but if it is not defined first the pilots produce a number that cannot be compared to the 30-day baseline it is meant to improve on.
- **P1**: Fresh context is mandated three times for executors and validators with no stated reason and no examined alternative, so the design pays the largest fixed cost in the system at the highest possible frequency by default rather than by decision — never asking whether one executor session can take three plan files of the same goal in sequence, or whether one validator can validate a batch.
  - When: P1 because the amortization may be genuinely forbidden by context poisoning across items — but the document does not say so, which means the cost is being paid without anyone having priced the alternative, and the pilots are not instrumented to reveal it.
- **P2**: A single settings-level CLAUDE_CODE_SUBAGENT_MODEL=sonnet default is threaded through 48 command/skill sites and 25 doc-shaped agents at once, before any pilot has run, with no per-site review of which of those sites was ever intended to resolve to Sonnet and no stated way to detect the few where it is wrong.
  - When: P2 because a wrong site produces visible, loud degradation rather than silent contamination, and the correction is a per-site model pin — but it is a decision frozen at setup across the whole shop, so the cost of being wrong scales with everything woven before anyone notices.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
