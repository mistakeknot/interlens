## Severity Calibration

- **P0**: An executor detects a dangerous deviation during a time-sensitive external operation but lacks authority to stabilize or abort it while awaiting the orchestrator.
  - When: The affected operation can corrupt durable state or user data during escalation, and the plan defines neither a safe local action nor a recovery boundary.
- **P1**: A common, intent-preserving deviation repeatedly stops fresh executors and forces the main thread to reconstruct local state and rewrite the plan.
  - When: The contract treats every unplanned observation as scope expansion and provides no bounded adjustment envelope or response deadline.
- **P1**: A validator reruns a check after repository or environment state has changed, then attributes disagreement to executor quality.
  - When: The design treats a later run as another observation of the same process without identifying which transient conditions cannot be replayed.
- **P2**: A pilot passes the main-thread token-share gate while creating many small escalations, idle waits, revised plans, and abandoned attempts.
  - When: The pilot counts lane output but does not record exception-loop count, decision latency, resumption cost, or full-attempt waste.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
