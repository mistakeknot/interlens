## Severity Calibration

- **P1**: A returning power user who bookmarked the homepage for the scatter plot quick-view arrives to find a wizard. They have no above-fold indicator that the scatter plot still exists at /visualize. The 3D Explorer link is buried in the escape-hatch row below the tiles — below fold on most viewports.
  - When: If the /visualize promotion is not added to the main nav or prominently surfaced above fold, a real segment of existing users will experience the redesign as a regression.
- **P2**: The See all CTA on the Coding tile links to /recommend?useCase=coding, which navigates the user to the full 4-step wizard at step 1 pre-selected. But the user has already implicitly selected Coding — arriving at a wizard that starts at step 1 with Coding pre-selected feels redundant and slows them down compared to skipping to step 2.
  - When: Only applies if the Wizard component does not advance to step 2 when a defaultUseCase prop is provided — a UX issue that the architecture review may also catch but from a different angle.
- **P3**: On the homepage, the Best Value tile links to /recommend?useCase=general (or similar) even though Best Value is a budget-oriented category, not a use-case category. Users clicking through expect to see budget-filtered results but arrive at a use-case wizard.
  - When: The brainstorm maps tiles to USE_CASE_WEIGHTS but Best Value and Fastest categories do not map cleanly to a single use case — their See all links need a different routing strategy.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

Prioritizes findings where the redesign creates navigation dead ends, hides previously discoverable content, or fails to serve a significant user segment. Discoverability regressions and broken returning-user workflows rank highest. If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.

## Prioritization

- P0: Issues that block other work, cause data loss or corruption — drop everything
- P1: Issues required to exit the current quality gate
- P2: Issues that degrade quality or create maintenance burden
- P3: Improvements and polish — suggest but don't block on these
- For each P0/P1 finding, describe the concrete failure scenario: what breaks, under what conditions, and who is affected
- Always tie findings to specific files, functions, and line numbers
- Frame uncertain findings as questions, not assertions
