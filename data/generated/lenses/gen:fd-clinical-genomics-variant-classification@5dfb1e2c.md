## Severity Calibration

- **P1**: Feature reclassification silently propagates to all downstream dependency entries without flagging them for review
  - When: The format treats dependency edges as static facts rather than evidence-backed claims that must be re-evaluated when parent classifications change
- **P2**: Format forces binary classification (in/out of sprint) with no VUS-equivalent for features under active design debate
  - When: Contested design decisions get forced into a classification that satisfies one consumer (planning) while misleading another (implementation)
- **P2**: Schema version 2 adds a required 'subsystem' field — all 555 v1 entries become invalid with no migration path
  - When: Format chosen (RON/TOML/markdown) has no built-in schema versioning, so schema evolution requires a bulk migration pass that creates a month-long inconsistent state

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
