## Severity Calibration

- **P0**: Label leakage: routing-calibration.json written after the holdout window incorporates verdict outcomes from the test period, and those calibration scores are used as features in judge augmentation prompts, allowing the model to see test-period signal during training.
  - When: When the judge augmentation step (bead .19.3) calls the calibration file to determine 'which tier would interspect recommend?' and the calibration file has been updated since the holdout cut date.
- **P1**: The ≥ 20% reroute rate gate for shadow→enforce promotion is measured only on LCB v6 problems, which have a different complexity distribution than real sprint tasks — the router achieves 25% reroute on code benchmarks but only 8% on actual sprint traffic, and the gate passes based on an unrepresentative distribution.
  - When: When the eval matrix aggregates all workloads into a single reroute percentage rather than reporting per-workload breakdown.
- **P2**: The ≥ 90% agreement threshold counts cases where both microrouter and baseline route to Sonnet as agreements, inflating the metric on the majority class — a router that agrees on every Sonnet case and is random on Haiku/local cases can exceed 90% agreement while providing no routing intelligence.
  - When: When the agreement metric is computed over all examples without stratification by tier, masking per-tier precision.
