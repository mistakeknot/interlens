## Task Context

Cuneiform evolved from pictures to abstract symbols under recording-medium cost pressure over 3000 years. Terminal encoding faces the same pressure (token cost) over a much shorter timescale. The destination is the same: symbolic, not iconic.

## Review Approach

### 1. Iconic → symbolic transition

- Iconic → symbolic transition — early Sumerian: picture of a cow. Late cuneiform: abstract wedge pattern meaning 'cow'. Terminal encoding should evolve from 'here are the pixels' to 'here is the meaning'.

### 2. Determinatives

- Determinatives — unpronounced classifier signs that disambiguate (DINGIR before a god's name, KI before a place). Terminal encoding could use type tags (ERROR:, MENU:, PATH:) as determinatives.

### 3. Logographic efficiency

- Logographic efficiency — one cuneiform sign can represent an entire word. Common terminal patterns (file paths, error messages, stack traces) could get single-token representations.

### 4. Tablet economy

- Tablet economy — scribes minimized clay usage by developing abbreviations and conventions. Token economy drives the same optimization pressure on terminal state encoding.

### 5. Multi-value signs

- Multi-value signs — cuneiform signs often have multiple readings (polyphony). A compact encoding might use context-dependent interpretation, trading encoding size for parsing complexity.

## Severity Calibration

- **P1**: Encoding remains iconic (visual reproduction) under token pressure
  - When: Still sending 'what the screen looks like' when 'what the screen means' would be 80% smaller
- **P2**: No determinatives for ambiguous content
  - When: LLM can't tell if '404' is an HTTP status code, a line number, or part of a filename without type context

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
