- **P0**: RouteSketch's own route line and endpoint markers can disagree on theme
  - When: components/RouteMap.tsx's `RouteSketch` (~lines 241-260) draws the route via `stroke: routeLineColor(band)` (frozen at last render) while its two marker circles use live `var(--color-shade)`/`var(--color-extreme)`. - **P1**: The manual dark-mode override is fully wired in code and CSS but has no reachable trigger
  - When: `data-sw-theme` is read by isDark()/onThemeChange(), encoded in the CSS `:root[data-sw-theme="dark"]` block, and asserted for cross-block parity by the sw-contrast lint test — but no file in apps/solwend-web ever calls `setAttribute("data-sw-theme", ...)`. R13.3's 'explicit override wins in both directions' is canon-promised, CSS-encoded, and lint-verified for internal consistency, yet a user cannot actually force dark or light mode independent of the OS today; nothing flags this as a missing feature rather than a passing test suite.

  - When: Every `||` fallback in shadewright-map.ts (lines ~24-29, 67-69, 109-113, 129) treats an SSR-time empty read identically to a genuinely-zero or unset custom property, so a slow-loading stylesheet on a cold cache would silently render a default color/width rather than surfacing 'tokens not ready yet' — worth confirming whether Next.js's static-export CSS injection order can ever let PlanMap's mount effect observe an un-attached stylesheet.
