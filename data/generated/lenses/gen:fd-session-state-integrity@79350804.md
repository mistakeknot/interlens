## Severity Calibration

- **P0**: accept-chunk writes the edited text to the session file in-place; a SIGKILL during the write produces a truncated JSON file that the next tool call parses as an empty or malformed session, losing all prior accepted chunks.
  - When: Occurs whenever the host OS reclaims the process mid-write, which is routine on memory-pressured servers or after a Claude Code timeout.
- **P0**: load-document stores chunk boundaries computed from the file at load time; if the source file is edited externally between load-document and a later edit-chunk call, the chunk offsets are wrong, causing edit-chunk to splice text at the wrong byte position and silently corrupt the document.
  - When: Happens whenever the user edits the source file in their editor while a session is open, which is a common workflow for iterative editing.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

Prioritise invariants that protect against silent divergence over those that merely produce loud errors.
