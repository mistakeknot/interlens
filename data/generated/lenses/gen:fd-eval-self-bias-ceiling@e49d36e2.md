## Task Context

cipher_evaluator_matrix.py runs an N×M matrix of reconstruction models × evaluator models to identify the pareto-optimal LLM judge. The human-editor row serves as a calibration ceiling. The matrix is used to select which model evaluates the production CIPHER benchmark. After migrating to 1-5 scale (v2, 2026-03-28), ceiling effects and scoring distribution deserve fresh scrutiny.

## Review Approach

### 1. Examine whether the evaluator matrix test design computes self-evaluation cells

- Examine whether the evaluator matrix test design computes self-evaluation cells (evaluator=reconstructor) separately and flags them as suspect in the output report

### 2. Whether the calibration examples in DEFAULT_CALIBRATION are injected into every

- Check whether the calibration examples in DEFAULT_CALIBRATION are injected into every evaluator call or only some — calibration drift between runs means matrix cells are not on the same scale

### 3. Assess whether the 1-5 scale produces ceiling effects for the best models (>50%

- Assess whether the 1-5 scale produces ceiling effects for the best models (>50% of scores at 5), which would collapse discrimination between top performers

### 4. Review whether the human-editor calibration ceiling row is scored by ALL

- Review whether the human-editor calibration ceiling row is scored by ALL evaluator models or a subset — if only some evaluators score it, cross-evaluator normalization is impossible

### 5. Examine whether the eval prompt includes the reconstruction model's identity

- Examine whether the eval prompt includes the reconstruction model's identity (even implicitly via model artifacts in output), which could trigger self-preference bias in autoregressive models that recognize their own output style

### 6. Whether inter-rater agreement (Spearman/Kendall) is computed across evaluators

- Check whether inter-rater agreement (Spearman/Kendall) is computed across evaluators per dimension and whether any dimension has near-zero inter-rater agreement (rendering it useless as a signal)

## Severity Calibration

- **P0**: A model consistently scores its own reconstructions 0.8 points higher than peers score the same reconstructions, but self-evaluation cells are included in the aggregate leaderboard, causing that model to appear best-in-class when it is mid-tier
  - When: The matrix does not exclude or flag diagonal (self-evaluation) cells in aggregate rankings
- **P1**: Calibration examples are only injected when the --calibrate flag is passed, so production matrix runs and calibration runs are on different scoring scales, making cross-run comparison meaningless
  - When: DEFAULT_CALIBRATION is not uniformly included in the eval prompt
- **P2**: The human-editor row is only scored by 3 of 9 evaluators because the run was interrupted, so the calibration ceiling cannot normalize the 6 remaining evaluators, invalidating cross-evaluator comparison
  - When: No check that human-editor row is complete before reporting normalized scores

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

Prioritizes bias sources that systematically favor one model family in ways that are invisible from aggregate scores. A model that self-scores at 4.8/5 while peers score it at 3.2 is not a better model — it is a biased evaluator, and using it to select the production pipeline is a catastrophic mistake. If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.
