## Task Context

Elf Revel — Rust colony sim with visual assets (SVG icons, potential animation sequences for revels); exploring offline ASCII conversion pipelines to create elven art tile atlases without abandoning the ASCII aesthetic

## Review Approach

### 1. Algorithm selection for aesthetic intent: edge

- Algorithm selection for aesthetic intent: edge-detection (Sobel/Canny → box-drawing chars) produces structural ASCII; luminance-mapped (chafa dithered) produces photorealistic ASCII; stipple/threshold produces woodcut/engraving ASCII — which maps to an elven aesthetic?

### 2. Offline vs

- Offline vs. runtime conversion: converting SVG/PNG assets to ASCII tile atlases at build time (offline) avoids runtime cost and allows curation; runtime conversion (via chafa bindings or WASM port) enables dynamic content but adds complexity

### 3. SVG

- SVG-to-ASCII pathway: SVG has vector structure that AA rasterizers discard; a better path is SVG → high-res raster → edge detection → ASCII, or SVG → path extraction → coordinate-mapped box-drawing chars

### 4. Tile atlas format for rust_pixel: rust_pixel uses a sprit...

- Tile atlas format for rust_pixel: rust_pixel uses a sprite/tile system — ASCII 'art' assets need to be encoded as multi-cell tile blocks, not single-char substitutions; what is the tile coordinate format and how does a 20×10 ASCII art piece map to it?

### 5. Color quantization: chafa supports 24

- Color quantization: chafa supports 24-bit, 256-color, and 16-color output; the coloring strategy (per-block average color vs. per-char dominant color) dramatically affects whether colored ASCII reads as intentional art or color noise

### 6. Video

- Video-to-ASCII: frame-by-frame conversion of animation sequences (e.g., a revel dance sequence) requires temporal coherence — ASCII char assignments should be temporally stable, not independently re-solved per frame

## Severity Calibration

- **P1**: Runtime chafa conversion runs on every render tick to draw an animated flora sprite, consuming 40ms per frame and dropping to unplayable framerates
  - When: No offline prebaking step; conversion treated as a real-time filter
- **P2**: SVG icon converted to ASCII via naive rasterization loses all vector structure — the result is luminance smear with no recognizable form
  - When: SVG fed directly to an luminance-mapping AA algorithm without edge-preserving preprocessing
- **P3**: ASCII animation flickers because each frame independently chooses different characters for the same region, breaking temporal coherence
  - When: No frame-to-frame character stability constraint in the conversion pipeline

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
