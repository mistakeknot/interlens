## Severity Calibration

- **P1**: The best-for.ts scoring loop runs 6 weight-set passes over 500+ models with per-metric sort operations on each ISR render, taking 800ms+ on cold ISR revalidation. This pushes TTFB above 1s for users who land during a revalidation window.
  - When: Applies if scoring is not memoized or pre-computed at seed/sync time, and is computed inline during the ISR render rather than cached separately.
- **P2**: The homepage previously passed models through withCompositeScores() used for scatter plot color coding. If this call is kept after the scatter plot is removed, it adds dead computation to every ISR render and inflates the serialized model data passed to client components.
  - When: Only a risk if the scatter plot removal is not accompanied by a cleanup of the data pipeline in page.tsx.
- **P3**: The Quick Stats strip is implemented as a separate uncached fetch, causing the homepage to issue an additional DB round-trip on every ISR revalidation just for two numbers.
  - When: Avoidable if model count is derived from cachedGetModels().length and benchmark count from the already-fetched external scores.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
