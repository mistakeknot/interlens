## Severity Calibration

- **P0**: microrouter endpoint (localhost:8421/route) conflicts with B5 local_models endpoint (localhost:8421) — when B5 is in shadow mode and B6 is in enforce mode, HTTP requests to the microrouter are handled by the B5 interfer server, which interprets /route as an unknown path and returns a 404, causing the resolver to treat it as 'endpoint unreachable' and fall through to B3 — B6 is silently non-functional.
  - When: When the schema does not distinguish between the B5 local_models endpoint and the B6 microrouter endpoint, and both point to localhost:8421 by default.
- **P1**: The Go resolver implements ineligible_agents check as a string prefix match on 'fd-safety' — an agent named 'fd-safety-extended' added in a future track is incorrectly excluded from microrouter routing, silently forcing it to a lower tier than intended.
  - When: When the eligibility check uses prefix matching rather than exact match, and new agent names follow the fd-{name} convention with compound names.
- **P2**: routing-overrides.schema.json is not updated with the microrouter: section, so user-written overrides that include microrouter configuration pass schema validation silently — any typo in mode (e.g., 'enforc') is accepted and the resolver uses the default (off) without warning.
  - When: When the schema bump bead is deferred or merged separately from the resolver integration bead, leaving a window where the schema and implementation are out of sync.
