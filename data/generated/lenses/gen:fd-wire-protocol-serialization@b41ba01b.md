## Task Context

The terminal state is structured data that needs to travel over a token-constrained channel to an LLM consumer. This is a wire protocol design problem.

## Review Approach

### 1. Schema-driven encoding

- Schema-driven encoding — defining a terminal state schema where field order carries meaning, eliminating tag overhead

### 2. Varint and delta encoding

- Varint and delta encoding — encoding row/column positions as deltas from previous, reducing numeric overhead

### 3. Dictionary compression

- Dictionary compression — building a per-session dictionary of repeated strings (file paths, error messages) and referencing by short ID

### 4. Human-readable compact formats

- Human-readable compact formats — YAML-like or DSL formats that tokenize well while remaining parseable by LLMs

### 5. Hybrid encoding

- Hybrid encoding — metadata in structured text + visual content as compressed inline (like multipart MIME)

## Severity Calibration

- **P1**: Verbose format with redundant field names
  - When: JSON-style encoding where 'background_color' appears 1920 times for an 80×24 terminal
- **P2**: Format not self-describing enough for LLM
  - When: Compact binary-like encoding that the LLM can't parse without a schema in context

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
