## Severity Calibration

- **P1**: Player clicks a building, Selection becomes Building(3), but HUD still renders the elf name from the prior Elf selection because it checks SelectedElf(Option<u64>) which was not cleared — the refactor from SelectedElf to Selection enum left a stale resource that some systems still read
  - When: SelectedElf resource not removed from ECS world during Selection enum migration; two selection resources coexist and diverge
- **P1**: Selection::Building(usize) uses a snapshot index, but the snapshot is rebuilt every tick — between the click frame and the render frame, the snapshot index shifts because an entity was added or removed, causing the sidebar to display the wrong building
  - When: Building and Flora selection stored as Vec index into snapshot rather than a stable entity ID; snapshot ordering not guaranteed to be stable between ticks
- **P2**: Clicking on a tile where an elf and a building overlap produces Selection::Elf (elf takes priority in hit-testing) — the player intended to select the building; there is no way to cycle to the building under the elf
  - When: Hit-testing priority order (elf > building > flora > terrain) not documented; no secondary-click or modifier+click to access lower-priority entities on the same tile
