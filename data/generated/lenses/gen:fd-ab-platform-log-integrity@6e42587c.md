- **P0**: The cursor_ts is updated to the end of the drained segment before the tier change is written to gate-tier-calibration-v2.json. The process crashes between the cursor_ts write and the tier change write. On the next SessionEnd, the drain starts from the new cursor_ts, skipping all records that informed the now-lost promotion decision. The FNR is recomputed on a window that excludes the evidence for promotion. If the excluded records were the marginal ones that pushed FNR above 0.30, the new computation finds FNR < 0.30 and no promotion occurs — the calibration system has permanently lost the promotion signal.
  - When: When cursor advancement precedes the tier change write rather than following it, making the log evidence for a promotion decision unreplayable after a crash in the write gap
- **P1**: A cmdEnforceGate call writes a new outcome record to gate-outcomes.jsonl 50ms before the SessionEnd drain reads the file. The drain includes this record. The FNR computed with this record crosses 0.30. The tier is promoted to hard. The record that tipped the decision belongs to the current session — the session that is triggering the promotion — creating a feedback loop where the last gate fire in a session can determine whether the current session's work ships under soft or hard tier on the next enforce-gate call.
  - When: When the drain boundary is the current end-of-file at drain time rather than the file offset at session start, allowing within-session outcomes to influence the calibration applied to within-session work
- **P2**: The v1 migration writes gate-tier-calibration-v2.json and then renames gate-tier-calibration.json to gate-tier-calibration.v1.json.bak.
