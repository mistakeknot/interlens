## Task Context

The pipeline.py orchestrator runs corpus-ingest → score-pairs → icai → cipher → rag-index → training as a DAG with per-step idempotent state tracking in pipeline-state/. gates.py registers quality gate functions per step. The overnight runner invokes the full pipeline and relies on gates to decide whether to proceed or halt.

## Severity Calibration

- **P0**: latest-icai.json is updated before the icai run directory is fully written, and a crash between pointer write and directory completion leaves the pointer referencing a partial run that passes the gate check
  - When: Subsequent pipeline steps consume an incomplete constitution without any error
- **P1**: A corpus-ingest run extracts exactly 51 pairs (one above min_pairs=50) but many pairs have empty source or target fields due to a docx parsing edge case — the gate passes on count alone
  - When: Gate validates pair_count but not pair quality; downstream ICAI trains on degenerate data
- **P2**: --skip-gates is used to advance past a failing rag-index gate during development and the flag is never removed from the cron invocation
  - When: Production pipeline silently runs without the RAG index quality check for multiple overnight cycles

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

Flags cases where a batch (pipeline run) can be silently accepted despite partial completion, where a gate passes on incomplete evidence, or where re-running a step would contaminate an existing batch record rather than issuing a new one. If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.

## Prioritization

- P0: Issues that block other work, cause data loss or corruption — drop everything
- P1: Issues required to exit the current quality gate
- P2: Issues that degrade quality or create maintenance burden
- P3: Improvements and polish — suggest but don't block on these
- For each P0/P1 finding, describe the concrete failure scenario: what breaks, under what conditions, and who is affected
- Always tie findings to specific files, functions, and line numbers
- Frame uncertain findings as questions, not assertions
