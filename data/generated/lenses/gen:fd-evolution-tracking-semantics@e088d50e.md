## Task Context

lens_evolution.py tracks lens effectiveness per user using EMA scoring with five named parameters and an exploration bonus. The Go Tracker interface exposes RecordEvent(lensID, userID, event) and Effectiveness(lensID) methods. In-memory EMA state replaces Python's SQLAlchemy LensUsage table. ## Severity Calibration

- **P0**: The floor of 0.1 is applied after the delta but Python applies it before, so pushed_back events on a lens already at 0.1 produce 0.0 in Go but remain at 0.1 in Python — lenses permanently suppressed in Go that Python would continue offering
  - When: User's disliked lenses reach floor=0 and are never shown again, breaking the exploration guarantee
- **P1**: In-memory EMA state is never restored from the Store between sessions because the constructor doesn't call Store.Load() — every new session starts all lenses at effectiveness=1.0, losing accumulated user preference signal
  - When: Effectiveness tracking is silently stateless across sessions despite the Store interface existing
- **P2**: usage_count is tracked globally (not per user) in the in-memory map, so a lens used by 3 different users loses its exploration bonus for all future users, even first-time recipients of that lens
  - When: New users receive no exploration bonus for rare lenses, reducing lens diversity

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
