## Severity Calibration

- **P1**: DerivationFn purity violation is undetectable
  - When: A consumer derivation that performs a blocking I/O read (fetching a game asset) will stall `Soul::derived`, poison the cache with a value that cannot be invalidated, and produce non-deterministic replay; there is no debug-mode purity check and no documented way to detect this class of consumer error
- **P1**: DerivedCache race condition in multi-threaded consumers
  - When: If `Soul` is shared across threads (e.g. Solwend's async handlers reading the same Character-Soul from two concurrent requests), concurrent calls to `Soul::derived` may race on `DerivedCache::derived_at` — `Soul` does not implement `Sync` (and probably should not), but the spec does not state whether `Soul` is intended to be single-owner or shareable, leaving consumer threading models to guess
- **P2**: Panicking derivation closure propagates to caller
  - When: A consumer derivation that panics on unexpected `FacetValue` shape (e.g. receiving `Unit` where it expected `Int`) propagates the panic through `Soul::derived` to the game tick loop, crashing the sim; the spec does not document panic policy or recommend `catch_unwind` at the derivation call site

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
