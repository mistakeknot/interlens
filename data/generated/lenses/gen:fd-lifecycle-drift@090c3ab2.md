## Severity Calibration

- **P0**: An upgrade path can delete or overwrite user state (e.g. legacy wrapper removal in the Codex bootstrap) with a backup step that fails silently or cannot actually be restored
  - When: A realistic upgrade sequence leads to data loss or an unbootable plugin state with no working recovery
- **P1**: clavain-cli or the prebuilt ic binary is older than the skills/commands that invoke it, and new flags or subcommands fail at runtime with no version check anywhere in the chain
  - When: Any markdown workflow invokes a binary capability without a freshness gate or a clear build/error path
- **P2**: kimi.plugin.json versions across interverse plugins are stale or inconsistently bumped, so the marketplace installs a different artifact than the repo HEAD implies
  - When: Declared manifest version and latest CHANGELOG/commit content disagree for a shipped plugin

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
