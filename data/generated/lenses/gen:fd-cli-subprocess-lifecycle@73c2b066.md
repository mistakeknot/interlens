## Task Context

The pipeline-worker uses agent-spawner.ts to spawn claude -p and codex CLI subprocesses for each editorial pass (analyst, line-editor, copy-editor, critique, verification). The system and user prompts are concatenated and passed via stdin. After migrating to claude-haiku-cli (Claude Max flat rate), CLI subprocess correctness is the production critical path.

## Review Approach

### 1. In spawnClaude()

- In spawnClaude(), the system and user prompts are concatenated with a bare '---' separator before being written to stdin — examine whether user text containing '---\n\n' on its own line can confuse the claude CLI's prompt boundary parsing

### 2. The spawn() timeout option (Node.js child_process) actually delivers SIGTERM

- Verify that the spawn() timeout option (Node.js child_process) actually delivers SIGTERM and that claude -p respects it; check whether SIGTERM causes partial stdout to be flushed or silently lost

### 3. In spawnCodex()

- In spawnCodex(), the codex exec flag is '-' (stdin) with '-s read-only' sandbox — verify that codex in read-only mode cannot write files and that there is no escape via tool calls in a pipeline context

### 4. Whether concurrent spawnClaude() calls (e.g. spawnAgentsParallel) hit claude's

- Check whether concurrent spawnClaude() calls (e.g. spawnAgentsParallel) hit claude's own in-process auth/session lock, causing silent 429s that manifest as empty stdout rather than non-zero exit codes

### 5. Audit the JSON parse path in spawnAgent: if the model emits a markdown fence

- Audit the JSON parse path in spawnAgent: if the model emits a markdown fence with content before the fence (preamble), the strip regex drops the preamble but the JSON may still be malformed — verify the error path includes the offending raw string in the AgentError

### 6. Examine whether bare: true suppresses error output that would normally appear

- Examine whether bare: true suppresses error output that would normally appear in stderr and surface in AgentError.lastStderr, leaving debugging blind

## Severity Calibration

- **P1**: User submits text containing a line that matches the '---' prompt separator, causing the claude CLI to treat trailing user text as a second system-prompt injection
  - When: The system+user concatenation in spawnClaude uses a simple string delimiter with no escaping or sentinel
- **P1**: A 5-minute timeout fires but SIGTERM is not delivered to claude's actual subprocess (which may be a shell wrapper), leaving a zombie that accumulates across concurrent pipeline requests until the worker OOMs
  - When: spawn() timeout kills the immediate process but not the grandchild claude binary
- **P2**: spawnAgentsParallel fires N claude -p processes simultaneously; claude's local session file or auth token is locked, causing all-but-one to emit a 'session already in use' error to stderr and exit 0 with empty stdout
  - When: claude CLI uses a single-writer lock for its session state on disk

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
