## Task Context

Creative approaches to enriching a TUI/ASCII colony sim (Elf Revel) beyond traditional terminal constraints. The game is a Rust colony sim using rust_pixel/crossterm for terminal rendering at 120x40 characters. Current rendering uses simple single-character glyphs (. for meadow, # for stone, ~ for water, H/W/G/F for buildings, first-letter for elves) with basic Color enum values (Green, Blue, White, etc.). ## Review Approach

### 1. Terasu/kumorasu

- Terasu/kumorasu and sub-glyph expression: a Noh mask changes emotion through 0.5mm of shadow variation — the carved surface is static, the lighting does the work. Terminal cells similarly have 'lighting' channels that don't change the glyph itself: foreground color temperature (warm = terasu/joy, cool = kumorasu/sorrow), background brightness (lit = attention, dim = neglect), and blink/bold attributes. Does the enrichment plan recognize that the SAME glyph character with different color temperature, brightness, and attribute combinations can convey multiple emotional/state readings WITHOUT changing the glyph? An elf represented by 'A' that shifts from warm amber to cool blue conveys a mood change as powerfully as a face animation — IF the player has learned the color-temperature grammar.

### 2. The ambiguity principle

- The ambiguity principle and viewer-projected meaning: the ko-omote mask works BECAUSE it is ambiguous — the audience reads their own emotional understanding into the neutral face. Over-rendering (adding explicit mood icons, status bars, detailed tile art) removes this productive ambiguity. Does the enrichment plan preserve spaces of interpretive ambiguity where the player reads meaning into minimal visual signals? A forest rendered as dense green characters with subtle brown undertones 'feels' ancient to the player through projection — adding explicit 'ancient' labels or distinct ancient-tree glyphs may actually reduce the emotional impact by replacing projection with depiction.

### 3. Mask selection (omote

- Mask selection (omote-awase) over mask resolution: in Noh performance, the MOST IMPORTANT visual decision is which mask to use for a scene — this determines the character's entire emotional register for the performance. Analogously, the most important rendering decision may be which RENDERING MODE to use for a given game state, not how to increase the resolution of any single mode. Does the enrichment plan include a 'mask selection' framework — rules for when to switch between ASCII, half-block, braille, and full-graphic modes based on the dramatic context (combat = crisp ASCII for legibility, contemplation = soft color for atmosphere, festival = dense color for celebration)?

### 4. The 0

- The 0.5mm principle — how much variation is enough: Noh masks achieve full emotional range from sub-millimeter carved differences. The terminal equivalent is sub-character rendering variations: slightly different Unicode characters (period vs. middle dot vs. bullet), color shade differences (RGB +-10), animation timing (50ms vs. 200ms pulse). Does the enrichment plan recognize that SMALL, CONTROLLED variations in these sub-character channels may be more expressive than large dramatic changes? A meadow that shifts from rgb(34,120,34) to rgb(34,115,28) over a season conveys time passing more subtly and powerfully than switching from a green dot to a yellow dot.

### 5. The mask as interface

- The mask as interface — rendering as mediation layer: the Noh mask is not an illustration of a face — it is an INTERFACE between the performer's embodied intention and the audience's emotional response. It mediates, translates, and amplifies. Terminal rendering should similarly be understood as an interface that mediates between game state and player understanding, not as an illustration of the game world. Does the enrichment plan design rendering as a mediation layer (what does the player need to UNDERSTAND from this visual?) rather than an illustration layer (what does this game tile LOOK LIKE?). The distinction matters: mediation optimizes for player cognition, illustration optimizes for visual fidelity.

### 6. Temporal rhythm

- Temporal rhythm and the concept of ma in Noh pacing: Noh is the slowest-paced theater form in the world — a single step may take 30 seconds, and the audience's perception adjusts to this tempo, making tiny changes feel dramatic. Terminal animation should consider that if the BASE PACE is slow and deliberate, then small changes (a color shift, a character change, a brief flash) become powerful dramatic events. Does the enrichment plan define a temporal rhythm — a base animation pace that makes changes meaningful — or does it default to the fastest update rate the terminal supports, drowning signal in noise?

## Severity Calibration

- **P1**: The enrichment plan adds explicit visual indicators for every game state (mood icons, status overlays, detailed tile decorations) without preserving any space for player-projected interpretation — the terminal becomes a dashboard rather than a world the player inhabits imaginatively
  - When: Every significant game state is rendered as an explicit visual indicator with no design for productive ambiguity — the player reads rather than interprets, and the experience shifts from 'living world' to 'spreadsheet with color'
- **P2**: Rendering mode selection is left to the player as a settings toggle rather than dynamically matched to game state — the player must manually choose between ASCII and graphic modes rather than the system selecting the appropriate 'mask' for the current dramatic context
  - When: Rendering enrichment modes (ASCII, half-block, sixel) are exposed as static settings with no framework for automatic mode selection based on game state, information density, or dramatic context
- **P3**: Animation runs at the fastest rate the terminal supports with no deliberate pacing, making subtle color shifts and state changes invisible against a background of constant motion — the Noh principle that slow base pace amplifies small changes is violated
  - When: Terminal update rate is set to maximum capability (60fps) with no design for deliberate pacing that makes individual changes perceptible and meaningful

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
