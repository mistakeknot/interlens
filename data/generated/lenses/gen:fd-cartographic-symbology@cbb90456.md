## Task Context

Tuivision's annotated format compresses rich terminal state (256/truecolor, style flags, text) into inline markers optimized for LLM consumption. The core decisions are: what to quantize, what to preserve exactly, and whether the resulting symbol vocabulary is calibrated against LLM parsing capacity rather than terminal capabilities.

## Review Approach

### 1. Color palette sizing vs. consumer working vocabulary

- Color palette sizing vs. consumer working vocabulary — cartographic standards converge on 8-16 named hues for field maps not because screens can't render more, but because the human map-reader reliably distinguishes 16 and fails at 32. Assess whether the 16-color quantization floor is calibrated against LLM color-semantics (can the model reliably distinguish 'bright_red' from 'red'?) or is an arbitrary xterm-defaults mapping.

### 2. Legend-in-band vs. legend-out-of-band encoding

- Legend-in-band vs. legend-out-of-band encoding — cartographic maps embed a legend that decodes symbology, either inline (symbol next to label) or as a separate panel. Assess whether the annotated format is self-describing (an LLM reading the output without a schema can infer what [r fg=red inv] means) or requires a schema preamble that must be present in every context window.

### 3. Quantization edge cases in semantically loaded symbols

- Quantization edge cases in semantically loaded symbols — cartographers distinguish between signal colors (red = hazard, blue = water) and arbitrary palette colors (green = park in one map, green = agricultural in another). Check whether the hex-to-16-color quantization correctly preserves semantic signal colors (terminal red = error) while accepting loss on decorative colors (syntax highlighting hues).

### 4. Symbol conflict and collision rules

- Symbol conflict and collision rules — cartographic standards define what to do when two features share the same visual slot: priority rules, masking, or aggregation. Assess whether the annotated format defines behavior when fg and bg quantize to the same named color (rendering text invisible), and whether the inverse boolean acts as a collision resolver.

### 5. Progressive detail with consistent base layer

- Progressive detail with consistent base layer — cartographic LOD systems keep the base symbology constant across zoom levels and add annotation layers progressively. Check whether the annotated format's optional role= attribute is a clean progressive-detail mechanism that adds a layer without disrupting the base [r]...[/] parse.

## Severity Calibration

- **P1**: Color quantization maps both 'error red' (#cc0000) and 'diff-add green' (#00aa00) to different named colors, but also maps a third terminal color to the same name as one of them — LLM can't distinguish error from a different semantic in the application's color scheme
  - When: When the quantization mapping is based on Euclidean color distance without semantic override rules for xterm colors 1 (red) and 2 (green), which terminal applications use as semantic signals regardless of exact hex value
- **P1**: The annotated format is not self-describing — an LLM receiving [r fg=bright_yellow inv] without a schema in context cannot determine whether inv means 'inverse video' or 'invisible' or 'invalid'
  - When: When the marker vocabulary is designed to be compact (saving tokens on the markers) without accounting for the tokens required to explain the vocabulary in system prompt or preamble
- **P2**: Quantization causes fg and bg to collapse to the same named color for cells using a near-white-on-white palette (e.g., theme editors, color pickers), making those cells semantically invisible in annotated output with no warning
  - When: When color quantization runs independently on fg and bg without a post-quantization collision check that either reverts to hex or applies the inverse flag as a distinguisher

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
