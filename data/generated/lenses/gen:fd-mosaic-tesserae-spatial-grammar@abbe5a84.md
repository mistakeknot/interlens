## Task Context

A paradigm question for Elf Revel (Rust colony sim, WASM): can ASCII characters serve as geometric primitives in an isometric/top-down spatial scene? The game currently renders as a flat TUI at 120x40 chars with simple single-character glyphs and basic colors. The user wants to explore paradigms where characters ARE the geometry — textured surfaces, scaled sprites, SVG fills, character-as-polygon. The core tension: gaining spatial richness (depth, perspective, procedural art) while preserving the ASCII identity. This is not about incremental rendering improvements but about a fundamental shift in how the character grid is conceived — from text display to spatial medium.

## Review Approach

### 1. Tessera angle

- Tessera angle and apparent depth from flat units: Byzantine mosaicists discovered that tilting gold tesserae 5-15 degrees off the wall plane creates surfaces that shimmer and appear to recede into infinite depth. The character cell equivalent is brightness/saturation modulation across a flat grid — cells with slightly elevated brightness 'advance' toward the viewer while dimmer cells 'recede,' creating apparent topography from a flat character plane. Does the rendering paradigm define a systematic brightness-depth convention where the same character at different brightness levels reads as different depths? This is the fundamental mechanism for making ASCII 'isometric' without changing character shapes: depth through luminance gradient, not through glyph geometry.

### 2. Andamento (directional flow)

- Andamento (directional flow) and visual movement from static characters: mosaicists lay tesserae in directional rows (andamento) that follow the contours of depicted forms — the flow of tessera rows around an eye, along a drapery fold, through a landscape. This directional grammar creates visual movement in a static medium. ASCII rendering can achieve analogous directional flow through systematic alignment of similar characters, color gradients that follow terrain contours, or Unicode characters with inherent directionality (slashes, arrows, box-drawing characters). Does the design specify how CHARACTER SEQUENCES create directional flow that implies spatial form — a line of increasingly bright dots suggesting a hillside, a gradient of green shades following a river valley? Andamento is the grammar that turns isolated cells into continuous spatial surfaces.

### 3. Opus vermiculatum vs

- Opus vermiculatum vs. opus tessellatum and rendering strategy selection: opus tessellatum uses a regular grid with meaning emerging from color pattern (like current single-char terrain rendering). Opus vermiculatum uses tesserae that flow along the contours of depicted forms, creating higher fidelity at object boundaries (like using box-drawing or braille characters that follow entity shapes). The design should identify WHEN each strategy applies — regular grid rendering for terrain (tessellatum) vs. contour-following rendering for entities and boundaries (vermiculatum). Does the paradigm distinguish between background rendering (uniform grid, pattern-based) and foreground rendering (contour-following, form-enhancing)?

### 4. The gold ground problem

- The gold ground problem — creating infinite depth from uniform material: Byzantine gold backgrounds use identically-sized gold tesserae set at slightly varying angles to create a surface that appears to have infinite depth — neither flat nor receding to a vanishing point, but existing in a luminous spatial ambiguity. The ASCII equivalent is the challenge of rendering 'space' or 'sky' or 'background' — areas that should feel spatially deep without containing specific objects. Does the design address how uniform character fields (the 'ground' of the scene) can feel spatially rich rather than flat? Subtle color variation, Unicode near-equivalents (different dot characters), or animation pulsing could create the mosaic gold-ground effect in a terminal.

### 5. Grout as compositional element

- Grout as compositional element — the space between characters: mosaic grout lines affect whether the viewer perceives individual tesserae or continuous surface. Wide dark grout = discrete units, visible grid. Narrow matching grout = continuous surface, invisible grid. Terminal rendering has an analogous grout: the background color between/around foreground characters. If background color matches foreground, characters merge into continuous surface. If background contrasts, each character reads as a discrete unit. Does the design consciously use background color as 'grout width' to control whether the player perceives a GRID OF CHARACTERS or a CONTINUOUS SPATIAL SURFACE? This is perhaps the single most important lever for making ASCII feel like geometry rather than text.

### 6. Scale

- Scale and viewing distance — the mosaic resolution paradox: mosaics are designed for a specific viewing distance. Up close, you see individual tesserae. At the intended distance, tesserae merge into continuous imagery. Mosaicists design for the merge distance, not for close inspection. The terminal grid has an analogous merge distance — at normal screen distance and font size, does the player see individual characters or do they merge into spatial patterns? The rendering paradigm should be designed for the MERGE DISTANCE of the target display (120x40 at typical terminal font size), not for cell-by-cell inspection. Does the design consider how the intended viewing distance affects whether character-level detail is perceived or wasted?

## Severity Calibration

- **P1**: The rendering paradigm attempts isometric depth through glyph shape (using / \ | _ to draw isometric geometry) without leveraging luminance gradient as the primary depth channel — forcing the limited glyph vocabulary to carry all spatial information when color could carry the z-axis for free
  - When: Isometric rendering is designed around character shape selection (which characters look like isometric surfaces) with no systematic brightness-to-depth mapping that could create apparent topography from ANY character through luminance alone
- **P2**: Background color is treated as a uniform default (black or terminal default) rather than as the primary lever for controlling whether the player perceives a grid of characters or a continuous spatial surface — the 'grout' that determines whether ASCII reads as text or as geometry
  - When: Background color is set globally or per-element without a design framework for how bg/fg color relationship controls the perceived continuity or discreteness of the character surface
- **P2**: Terrain rendering uses the same rendering strategy (uniform grid, one char per tile) for both large uniform areas and detailed boundaries, missing the mosaic insight that different spatial contexts demand different tessera-laying strategies
  - When: No distinction between tessellatum-style background rendering (regular grid, pattern-based) and vermiculatum-style foreground rendering (contour-following, form-enhancing) for entity boundaries and important spatial features
