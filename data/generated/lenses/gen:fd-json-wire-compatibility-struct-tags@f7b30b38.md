### 2. Vocabulary counter type: Python stores laughter/affirmation/intensifier/hedge/op

- Vocabulary counter type: Python stores laughter/affirmation/intensifier/hedge/opener as dicts of {string: int}. Go must use map[string]int with json tag 'laughter' (not 'laughter_counts' or 'vocab_laughter') — and the zero value must serialize as {} not null, requiring explicit initialization in the empty constructor

### 3. Fingerprint top-level keys: Python's _empty_fingerprint() has message_count

- Fingerprint top-level keys: Python's _empty_fingerprint() has message_count (int), global (dict), modes (dict of mode→profile), cadence (dict). Go Fingerprint must not rename 'global' to 'Global' — 'global' is a Go keyword so the struct field must be named differently (e.g., Global) but with json:"global" tag

### 4. Cadence sub-struct: Python cadence has avg_burst_size (float

- Cadence sub-struct: Python cadence has avg_burst_size (float, default 1.0) and burst_count (int, default 0). Go Cadence struct must not omit avg_burst_size when it equals 0.0 — use json:"avg_burst_size" without omitempty, or Python reads a missing field as whatever json.loads returns for absent keys (KeyError or .get default)

### 5. Modes map key namespace: Python modes keys are the 7 mode strings ('emotional'

- Modes map key namespace: Python modes keys are the 7 mode strings ('emotional', 'analytical', 'playful', 'intimate', 'logistics', 'update', 'general'). Go Mode type must round-trip through JSON as these exact strings — if Mode is an iota int, its MarshalJSON must return the string value, not the integer

### 6. Null vs empty object serialization: Python initializes modes as {} (empty dict)

- Null vs empty object serialization: Python initializes modes as {} (empty dict) and adds keys on first message for that mode. Go must serialize modes with no entries as {} not null — encoding/json marshals nil maps as null but initialized empty maps as {} — the Go Fingerprint constructor must use make(map[Mode]*ModeProfile) not var modes map[Mode]*ModeProfile

## Severity Calibration

- **P0**: The Go struct field for 'global' profile is named All or Profile to avoid the keyword collision but the json tag is accidentally omitted or set to 'all' — Python writes 'global' but Go deserializes into a zero-value struct, silently discarding the accumulated global profile on every read
  - When: BuildMirroring falls back to global profile which is always empty in Go's view, producing no mirroring instructions for all users during the concurrent operation period
- **P0**: ModeProfile vocabulary counter fields have omitempty tags — when the user has never used laughter tokens, the laughter field is absent from Go's JSON output; Python reads this fingerprint and laughter.get() returns the absent-key default, but then update_fingerprint() overwrites the field with {} on next write, discarding what Python had accumulated
  - When: Vocabulary counters oscillate between absent and present depending on which language wrote last, corrupting laughter/affirmation/intensifier/hedge tracking
- **P1**: Go serializes the modes map as null when no mode-specific profiles exist yet (first 3 messages all general), because the Fingerprint was constructed with var modes map[Mode]*ModeProfile — Python's json.loads reads null as None and fingerprint['modes'] = None causes AttributeError on modes.get(current_mode)
  - When: Python crashes reading Go-written early fingerprints, breaking the concurrent operation period for new users
