## Task Context

Garden Salon uses Yjs for CRDT-based real-time collaboration. The governance design introduces directions as higher-level state management objects whose lifecycle and merge semantics must compose correctly with the underlying CRDT layer.

## Review Approach

### 1. Direction merge as a state transition vs CRDT operation

- Direction merge as a state transition vs CRDT operation — merging a direction into main state is a named, intentional event. This is not automatically resolvable by a CRDT. The design must distinguish CRDT-managed real-time edits from governed merge events.

### 2. Artifact lineage under concurrent directions

- Artifact lineage under concurrent directions — if two directions both modify the same section of a document concurrently, merging the first direction changes the base state that the second was authored against. The design needs a rebase or conflict-detection step.

### 3. Direction lifecycle state machine

- Direction lifecycle state machine — proposed → active → merged/abandoned is a finite state machine. In a distributed system with no central authority, two participants can concurrently transition the same direction (e.g., one merges, one abandons). The resolution is unspecified.

### 4. Nested direction semantics

- Nested direction semantics — the design mentions directions can contain proposals. If proposals are themselves CRDT-tracked, direction merge must compose with proposal-level merge. The interaction is not described.

### 5. Attribution immutability under merge

- Attribution immutability under merge — once a direction is merged, its attribution record should be frozen. If the CRDT layer allows retroactive edits to the direction's history after merge, attribution becomes non-authoritative.

### 6. Garden main state versioning

- Garden main state versioning — after a direction merges, is there a canonical snapshot of main state? Without versioned snapshots, future directions cannot reliably compute a diff from the last known good state.

## Severity Calibration

- **P1**: Concurrent direction merges producing invalid state
  - When: Two active directions that both modify overlapping artifacts are merged concurrently (valid in a distributed system without locking). The CRDT will converge on a state, but that state may be semantically invalid — e.g., contradictory edits both present. No conflict detection layer is described.

- **P1**: Direction state machine divergence
  - When: Without a consensus mechanism for direction lifecycle transitions, two participants can simultaneously move the same direction to 'merged' and 'abandoned.' The resulting garden state is undefined. This is not a CRDT-resolvable conflict.

- **P2**: Proposal-direction composition undefined
  - When: The open question of whether directions contain proposals or are parallel is unresolved. If proposals are CRDT operations and directions are governance events, they operate at different layers and cannot be naively composed without an explicit interface.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
