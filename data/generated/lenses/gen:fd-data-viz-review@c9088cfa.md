## Severity Calibration

- **P1**: The Best for Coding tile shows Model A, Model B, Model C in a 1-2-3 podium. Models B and C have scores of 84.3 and 84.1 respectively — a 0.2-point difference that rounds to the same display value. The podium implies B is meaningfully better than C, but the difference is noise within measurement uncertainty.
  - When: If tile rendering does not apply a minimum-gap threshold or tied-rank treatment, the podium actively misleads users about the significance of rank differences.
- **P2**: A category tile for Best for Research shows only 1 model because very few models have gpqa scores in the DB. The tile renders a 1st place card with two empty slots, making the category look broken rather than sparse.
  - When: Applies if the BestForTiles component does not have a minimum model count threshold per category or a fallback rendering path for sparse categories.
- **P3**: On narrow mobile viewports (375px), the 5 use-case buttons in a 2-column grid produce a 3rd row with a single centered button. This orphaned button is visually inconsistent with the grid above it and can look like a UI bug to first-time visitors.
  - When: Standard grid behavior with 5 items in a 2-column CSS grid — easily caught in a responsive preview but not addressed in the brainstorm mobile layout notes.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
