## Task Context

Six open design questions for a dynamic flora system in an elven colony sim (Rust ECS, WASM). The brainstorm contains at least 4 distinct subsystems (core flora, ecological dynamics, garden-as-art, ForestSpirit evolution) that could each be a sprint. WASM performance constraints make entity density a real engineering concern. The project philosophy embraces system complexity but must manage it through disciplined phasing.

## Review Approach

### 1. Going train stability

- Going train stability and sprint scope (Q2): a watchmaker never ships a chronograph on an untested base caliber. Option A (core flora only) is the going train — growth stages, spread, seasonal states. This must run with metronomic reliability before blight (a complication), fire (a complication), competition (a complication), or garden-as-art (a grand complication) can be trusted. But Option A must also be DESIGNED to accept complications — the going train must have the right pivot points and power reserve for future complications. Does Sprint 1's core flora include the architectural taps (trait interfaces, component hooks, event channels) that later complications need?

### 2. Complication dependency chains

- Complication dependency chains and sprint ordering (Q2): a perpetual calendar requires a date mechanism, which requires the going train. Complications have dependency chains. Is garden-as-art (Q6) more like a date window (simple, early) or a minute repeater (complex, requires redesigned mainspring)? The brainstorm treats garden-as-art as a grand complication but doesn't map its dependencies. What base mechanisms must exist before garden compositions can work — species palettes need species, compositions need beauty calculations, Garden Walk revels need the revel system + flora system integrated.

### 3. Power reserve

- Power reserve and entity density (Q5): a mainspring has finite power. Adding complications drains the power reserve — a chronograph consumes about 30% of the mainspring's energy. Similarly, adding 600 flora entities (Q5 Option A) consumes the ECS 'power reserve' in WASM. Each complication (blight checks, fire spread, competition calculations, beauty perception) draws additional power from this reserve. Does the density decision account for the cumulative power drain of ALL planned complications, not just Sprint 1's load? A going train tested with 600 entities may fail when chronograph-equivalent systems are added later.

### 4. Utility to art transition

- Utility to art transition and garden timing (Q6): in horology, the transition from utility to art happens when the movement is over-engineered for its stated purpose — a tourbillon doesn't improve timekeeping in a wristwatch, but it requires a base movement so refined that adding it becomes possible. Garden-as-art (Q6) should require that the core flora system is so well-implemented that gardens can transcend utility. Option B (species palettes as hook) is like adding a date window — useful, modest cost, provides infrastructure for later. Option C (full garden-as-art) is like shipping a tourbillon in the first caliber — theoretically possible but requires a going train designed from the start for that complexity.

### 5. Invisible vs

- Invisible vs. visible complications and observer-dependent beauty (Q4): watchmakers distinguish between 'useful' complications (date, power reserve indicator) visible on the dial and 'connoisseur' complications (tourbillon, co-axial escapement) visible only through the caseback. Option A's species-specific beauty is a dial complication — visible to everyone. Option C's full observer-dependent beauty is a caseback complication — visible only to those who know to look. Does the design ensure that the dial complications (simple beauty) work perfectly before adding caseback complications (observer-dependent beauty) that only elves with cultivated aesthetic positions can perceive?

### 6. Over

- Over-engineering and future-proofing (Q3): haute horlogerie movements are over-engineered — larger balance wheels, higher-jewel-count bearings, finer finishing — because the base movement must support unknown future complications. The terrain architecture decision (Q3) determines the base caliber's over-engineering budget. Option D (collapse to 3 terrain types) is the most over-engineered base — maximally simple, maximally flexible. Option B (overlay) is the least over-engineered — adds complexity now to avoid rework, but may constrain future complications. Which terrain architecture leaves the most future complication headroom?
