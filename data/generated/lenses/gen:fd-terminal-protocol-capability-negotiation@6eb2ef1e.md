## Task Context

Elf Revel — Rust colony sim with dual native TUI (crossterm/rust_pixel) and WASM browser targets; exploring sixel/kitty/half-block rendering enrichment without breaking existing ASCII aesthetic

## Review Approach

### 1. Capability probe ordering: XTSMGRAPHICS (sixel)

- Capability probe ordering: XTSMGRAPHICS (sixel), APC Gc query (kitty), DA2 response parsing — each probe requires a roundtrip read; does the detection path handle terminal read timeouts without blocking the game loop?

### 2. WASM browser target constraints: crossterm in WASM target...

- WASM browser target constraints: crossterm in WASM targets xterm.js or the browser's built-in terminal emulator; neither supports sixel or kitty — is this hardcoded or detected at compile time via cfg(target_arch = 'wasm32')?

### 3. Fallback chain correctness: sixel → kitty → half

- Fallback chain correctness: sixel → kitty → half-block → basic ANSI — does each tier's renderer produce a coherent output or does a partial capability match produce corrupted frames?

### 4. Rust_pixel framework layer: does rust_pixel already abstr...

- rust_pixel framework layer: does rust_pixel already abstract terminal capabilities, or does adding sixel/kitty require bypassing its rendering abstraction and writing raw escape sequences?

### 5. ITerm2 inline image protocol: distinct from kitty

- iTerm2 inline image protocol: distinct from kitty, uses base64 ESC ] 1337; — if a user is in iTerm2, the kitty probe will fail but inline images still work; is iTerm2 probed separately?

### 6. Cell

- Cell-vs-pixel coordinate mismatch: sixel images are positioned in pixel coordinates while TUI layout is in cell coordinates; a rendering layer that mixes both risks subpixel misalignment artifacts

## Severity Calibration

- **P0**: Capability probe issues blocking terminal read hangs the game loop on SSH connections where XTSMGRAPHICS response never arrives
  - When: No timeout on terminal capability query reads; game waits indefinitely for escape sequence response
- **P1**: WASM build attempts to emit sixel escape sequences into browser console output, corrupting all log output and breaking the dev workflow
  - When: No cfg(target_arch) gate around pixel protocol code paths
- **P2**: Capability detected as 'kitty supported' on a terminal that partially implements the spec, producing garbled overlapping image frames
  - When: Protocol negotiation trusts DA2 response alone without validating an actual image roundtrip

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
