## Review Approach

### 1. Sketch vs

- Sketch vs. spec epistemology: industrial design distinguishes sketches (explore possibility space), models (answer specific questions), and specifications (commit to production) — which type is each rendering option at this moment, and is it being treated as the right type?

- Premature closure risk: ID projects fail when a sketch detail gets treated as a production decision before the design space is explored — does 'reusing the sibling renderer' close the 2D-first design space before alternatives are adequately explored?

- Prototype question scope: a good prototype answers specific questions, not all questions — what specific rendering questions must the prototype→production path answer before committing, and are those questions scoped tightly enough to bound the exploration?

- Tooling commitment as irreversibility threshold: in ID, 'cutting steel' for injection molds is the irreversibility threshold — what is the equivalent irreversibility threshold for the rendering stack decision, and is the current prototype phase deliberately staying below it?

### 5. Iteration budget: ID explorations have explicit iteration...

- Iteration budget: ID explorations have explicit iteration budgets — if the hybrid prototype takes 2 sprints and the answer is 'the sibling renderer doesn't fit,' is that a valid outcome of the prototype phase, or is it treated as failure?

### 6. Design intent vs

- Design intent vs. design specification: ID separates the intent (what the product must feel like) from the specification (what dimensions and materials achieve that) — has the rendering stack decision started with an explicit design intent for the game's visual experience?

## Severity Calibration

- **P1**: Prototype sprint begins reusing the sibling renderer before defining what questions the prototype must answer — prototype drifts into indefinite adaptation work without a decision gate
  - When: No prototype question list defined before sprint begins; success criteria absent
- **P2**: The design intent for the colony sim's visual experience is never articulated — rendering stack options are evaluated on technical criteria (performance, lines of code) without a visual design intent to evaluate against
  - When: No design brief or visual intent statement exists before the technical rendering options are compared
- **P0**: Reuse decision functions as premature closure: 2D-first rendering alternatives are never prototyped because the sibling renderer is already partially integrated — sunk cost prevents honest evaluation
  - When: Prototype phase begins with only one option; alternatives ruled out before being sketched

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
