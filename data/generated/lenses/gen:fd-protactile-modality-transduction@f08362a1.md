## Task Context

Pro-Tactile ASL solves exactly the modality transduction problem: high-bandwidth visual channel → constrained tactile channel, preserving meaning by identifying which features are contrastive. Tuivision faces: high-bandwidth visual terminal → constrained token channel.

## Review Approach

### 1. Contrastive vs. redundant features

- Contrastive vs. redundant features — in Pro-Tactile, handshape is contrastive (changes meaning), exact finger angle is redundant. In terminals: red-vs-green is contrastive, exact shade of red is redundant.

### 2. Modality transduction strategies

- Modality transduction strategies — tactile ASL uses body-as-canvas (drawing on the receiver's body) and haptic feedback. Maps to: converting visual terminal state to textual description requires choosing a transduction strategy.

### 3. Information rate matching

- Information rate matching — visual ASL is high-bandwidth (many simultaneous features); tactile channel is lower-bandwidth. Maps to: visual terminal (high info) → text representation (lower info) requires rate matching.

### 4. Backchanneling

- Backchanneling — Pro-Tactile introduced constant tactile feedback so the signer knows the receiver is following. Maps to: the encoding should let the LLM signal what level of detail it needs.

### 5. Phonological restructuring

- Phonological restructuring — some signs are restructured entirely for tactile mode, not just simplified. Maps to: some terminal states should be restructured for text mode, not just compressed.

## Severity Calibration

- **P0**: Dropping a contrastive feature during compression
  - When: Bold text (which marks headings/emphasis) stripped as 'decoration' — structural meaning lost
- **P1**: Preserving redundant features at token cost
  - When: Encoding exact RGB values when the only contrastive distinction is 'error red vs. success green vs. warning yellow'

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
