## Severity Calibration

- **critical**: A data race on the per-mode map: one goroutine calls Update() which writes to the map while another goroutine calls BuildMirroring() which iterates the map, and the mutex doesn't cover both paths, or a new mode key is created without lock protection
  - When: Like two climbing teams on the same ladder bridge simultaneously -- the structure was designed for sequential access and concurrent use causes catastrophic failure
- **major**: The mutex is held during the entire BuildMirroring() string construction (including string formatting and concatenation), blocking Update() calls from concurrent messages unnecessarily
  - When: Like closing the entire icefall route while a single ladder is repositioned -- the exclusion zone is far larger than the actual hazard, creating unnecessary bottleneck
- **minor**: ComputeObservables or ClassifyMode accidentally captures or mutates a package-level variable (e.g., appending to a shared slice used in regex matching), introducing a subtle shared-state dependency in what should be pure functions
  - When: Like a climber who drops equipment in Base Camp that rolls into the icefall approach, creating an unexpected hazard outside the managed zone

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
