## Task Context

Elf Revel — exploring whether ASCII characters can serve as geometric primitives in spatial rendering. This requires converting font data into renderable geometry (not just screen text). Rust ecosystem: fontdue for rasterization, lyon for tessellation, wgpu for GPU rendering. Target: WASM browser at 60fps.

## Review Approach

### 1. Fontdue vs ab_glyph vs cosmic

- fontdue vs ab_glyph vs cosmic-text: fontdue gives raw rasterized bitmaps (fast, simple); ab_glyph provides outline access for tessellation; cosmic-text handles complex text layout — which level of font API does the architecture actually need for character-as-polygon rendering?

### 2. Lyon tessellation pipeline: converting font outlines (cub...

- Lyon tessellation pipeline: converting font outlines (cubic beziers from TTF/OTF) into triangle meshes via lyon's tessellator — does the triangle count per glyph stay reasonable (50-200 triangles) or do complex characters (Chinese, decorative) explode into thousands?

### 3. Signed Distance Field approach: pre

- Signed Distance Field approach: pre-computing SDF textures for the ASCII character set enables resolution-independent rendering with correct antialiasing at any scale — but SDF struggles with sharp corners and thin strokes; does the chosen SDF resolution (typically 32x32 or 64x64) preserve the distinguishing features of monospace ASCII characters?

### 4. Glyph caching strategy: tessellating or rasterizing glyph...

- Glyph caching strategy: tessellating or rasterizing glyphs every frame is prohibitive; the architecture needs a glyph cache keyed by (character, font_size, style) — how large is this cache for the full ASCII printable set (95 characters) × the needed size variants?

### 5. Perspective

- Perspective and rotation tolerance: a key question for ASCII-as-polygon is whether characters remain readable when rendered on isometric tile surfaces (effectively a non-trivial affine transform) — does the approach produce characters that survive perspective projection or do stroke weights become uneven?

## Severity Calibration

- **P1**: Lyon tessellation of decorative font outlines produces 2000+ triangles per glyph, causing the vertex buffer for a screen full of ASCII tiles to exceed GPU memory limits and drop to <5fps
  - When: No triangle budget per glyph; font choice includes complex curves without simplification pass
- **P2**: SDF-rendered characters at 32x32 resolution lose the distinction between similar characters (I/l/1, O/0, rn/m) because the SDF grid is too coarse to capture the distinguishing pixels
  - When: SDF resolution chosen for storage efficiency without validating against a character confusion matrix
- **P2**: Pre-rasterized glyph atlas approach works perfectly at 1x scale but produces blurry characters at 2x zoom because the bitmap was rasterized at a fixed resolution without SDF or multi-resolution variants
  - When: Single-resolution bitmap atlas with no scale-independent rendering path

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
