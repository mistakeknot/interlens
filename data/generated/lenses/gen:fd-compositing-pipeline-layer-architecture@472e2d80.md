## Review Approach

### 1. Render pass separation: VFX compositing separates diffuse

- Render pass separation: VFX compositing separates diffuse, specular, depth, ID passes — does the ASCII renderer separate terrain, entity, UI, and effect layers for independent control?

### 2. Z

- Z-depth and occlusion: isometric scenes have depth ordering ambiguity — deep compositing's per-sample depth solves exactly this class of problem

### 3. Transparency

- Transparency and semi-occlusion: ASCII characters have inherent transparency (the space between strokes) — does the compositing model handle character-as-partial-occluder or treat each tile as fully opaque?

### 4. Blend mode vocabulary: screen

- Blend mode vocabulary: screen, multiply, overlay each serve different narrative purposes in VFX — what blend modes exist for ASCII layers (overwrite, interleave, priority)?

### 5. Pre

- Pre-multiplication and edge handling: compositing over backgrounds requires correct alpha handling — ASCII character edges against tile backgrounds need equivalent anti-aliasing/edge strategy

### 6. Performance budget for layer count: real

- Performance budget for layer count: real-time compositing has strict layer budgets — how many ASCII layers can the WASM renderer composite per frame?

## Severity Calibration

- **P1**: No defined layer order causes flickering Z-fight between ASCII elements at same depth
  - When: Isometric depth sorting is ad-hoc rather than pipeline-defined with explicit tie-breaking rules
- **P2**: Weather/particle effects obliterate underlying ASCII terrain because only 'overwrite' blend mode exists
  - When: Single blend mode for all layer interactions — no transparency or priority compositing
- **P0**: Frame budget exceeded due to unbounded layer compositing
  - When: No layer count budget or early-out optimization in the compositing pipeline

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
