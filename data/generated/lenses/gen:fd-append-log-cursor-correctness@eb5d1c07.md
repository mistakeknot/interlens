  - When: Gate tiers oscillate or permanently over-promote because a session crash causes every outcome in the re-processed window to be counted twice
- **P1**: cmdEnforceGate appends using os.OpenFile with os.O_APPEND but writes the JSON line in two separate Write calls (object bytes, then newline) — a concurrent drain reader reads the file between the two writes and gets a truncated line; if the reader errors on malformed JSON and returns early, it logs the error but does not advance cursor_ts, causing the same records to be re-drained on every subsequent SessionEnd until the log is rotated
  - When: Drain loop is permanently stuck at the truncated record's timestamp; calibration halts for the lifetime of that log file

  - When: Noisy error logs on every new project setup before the first gate check runs; operators may mistake the error for a misconfiguration

## Decision Lens

A drain loop that advances the cursor before persisting the calibration result is a P0 crash-recovery failure — the gap between cursor advance and v2 write means a crash produces a state where records are consumed but their effect is lost, with no way to replay.
