## Severity Calibration

- **P0**: Project names used as cross-reference keys instead of stable IDs
  - When: If Initiatives rows reference projects by display name and a project is renamed, all initiative-to-project links break silently with no integrity constraint to surface the breakage — the most fundamental cross-reference in the schema is fragile.
- **P1**: No controlled vocabulary for `project:` and `domain:` labels
  - When: The agent CUJ's happy path depends on `bd list --label='project:Sylveste'` working reliably; if label strings are free-form, different sessions will coin different forms and the filter will return incomplete results, undermining the core agent use case.
- **P2**: No tombstone / orphan convention for abandoned projects
  - When: When a project becomes dormant or its beads is deleted, any Initiatives rows linking to it will have dangling references; without a tombstone convention, operators and agents cannot distinguish 'this project is paused' from 'this row's data is stale'.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

Authority control — in a catalog, every entity (person, work, subject) needs a stable, unique identifier that survives renaming and reorganization; without it, cross-references break silently and searches return incomplete results. If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.
