## Task Context

Tuivision is a TUI testing/automation MCP server that gives AI agents visual access to terminal applications. Current modes: get_screen text (~200-400 tokens, no style), get_screenshot png (~1600 vision tokens), get_screenshot svg (~2000-8000 tokens, contains text+style but verbose). The goal is a new representation that captures text + task-relevant visual semantics at significantly fewer tokens than PNG/SVG while preserving the semantic information that plain text loses. Ideas already proposed include local OCR on PNGs and optimized SVG stripping.

## Severity Calibration

- **P0**: The SVG optimizer merges two adjacent tspan elements that differ only in fill color (e.g., red error text next to green success text), destroying the color distinction that an LLM needs to determine test pass/fail status.
  - When: Occurs when the merge algorithm compares only font attributes and ignores fill/color differences, or when color quantization maps distinct semantic colors to the same bucket.
- **P1**: The SVG boilerplate (xml declaration, svg root element, defs, style blocks) consumes 400+ tokens on every screen capture, accounting for 20-50% of the total token budget for small terminal windows, with zero information content that varies between captures.
  - When: Triggered on every get_screenshot svg call — the overhead is constant regardless of screen content.
- **P2**: CSS class extraction creates a style block with 30 class definitions for a screen that only has 5 visually distinct regions, because the renderer generates unique classes for minor attribute variations (e.g., fill:#1a1a1a vs fill:#1b1b1b) that are imperceptible.
  - When: Occurs when the SVG renderer preserves full color precision rather than quantizing to a reduced palette before class extraction.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

Every SVG element and attribute is evaluated against three questions: (1) does removing it change the rendered visual output, (2) does the visual change it preserves carry semantic information for an LLM, and (3) can the same information be expressed with fewer tokens? An optimization that removes 500 tokens of markup while losing zero semantic signal is always correct. An optimization that saves 100 tokens but breaks color distinction is always wrong. If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.
