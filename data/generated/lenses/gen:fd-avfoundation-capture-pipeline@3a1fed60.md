## Severity Calibration

- **P0**: AVAssetWriter.startSession(atSourceTime:) is called using the first video buffer's PTS while the audio input's isReadyForMoreMediaData is still false, so the initial audio buffers are silently dropped by the writer before the branch is ever 'sheddable' — violating the never-shed audio guarantee at the writer boundary, not the FrameGate boundary.
  - When: no explicit synchronization of writer-session-start against both inputs being ready, or no test asserting zero dropped audio samples in the first N ms of a session
- **P0**: An AVAudioSession route change (e.g. Bluetooth mic connect/disconnect mid-run) triggers a full audio input reconfiguration that the design logs as a single 'planned gap' event but which actually restarts the audio format (sample rate/channel count), producing a CMSampleBuffer format mismatch that AVAssetWriter rejects for the rest of the session — audio silently stops with no drop count increment.
  - When: the route-change recovery path is described as 'pause -> reconfigure -> resume' without specifying that the audio format must be re-negotiated with the existing AVAssetWriterInput, which cannot change format after starts writing
- **P1**: The FrameGate frame-scoring path (Laplacian variance on downsampled luma) executes synchronously on the same queue that receives captureOutput:didOutputSampleBuffer:, so under thermal/CPU pressure scoring latency backs up the video delivery queue and causes video frame drops — the exact failure mode the design intends to avoid by shedding branch B first.
  - When: no explicit statement that frame scoring runs off the capture delivery queue, or no queue-priority design distinguishing capture callback queues from scoring/writing queues
- **P2**: Locked-exposure mode is toggled via a session-configuration change after the session already started, forcing an implicit beginConfiguration/commitConfiguration that produces a brief black frame or frame gap not accounted for in the dropped-frame stats.
  - When: exposure lock is presented as a runtime-toggleable option rather than a start-of-session-only configuration

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
