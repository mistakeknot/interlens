## Task Context

Elf Revel — Rust colony sim using rust_pixel/crossterm; current map renders ASCII entities and terrain; exploring enriched rendering (Unicode density, 24-bit color, overlays) while maintaining panel UI integrity

## Review Approach

### 1. Layer separation model: map (terrain + entities)

- Layer separation model: map (terrain + entities), overlays (beauty auras, mood indicators, path highlights), panels (status, log, skills) — if all three layers write to the same crossterm buffer, enrichment of one layer bleeds into others

### 2. Caves of Qud pattern: Qud uses a Z

- Caves of Qud pattern: Qud uses a Z-order compositing system where terrain, object, actor, and effect layers are blended per-cell; does rust_pixel/crossterm support per-cell Z-order or is it a single flat buffer?

### 3. Half

- Half-block tile composition: a half-block terrain tile occupying the lower half of a cell — if a status panel overlaps by one row, does the panel background correctly overwrite the half-block or does the Unicode character bleed through?

### 4. Color inheritance in layered rendering: 24

- Color inheritance in layered rendering: 24-bit bg color set for terrain tile — does an overlay layer (e.g., danger highlight) correctly compose on top, or does it reset bg to terminal default and destroy the terrain color?

### 5. Dirty region tracking: enriched rendering with per

- Dirty region tracking: enriched rendering with per-cell Unicode selection and 24-bit color is more expensive to re-render; does the rendering pipeline track dirty cells to minimize redraws, or does it full-redraw every frame?

### 6. Dwarf Fortress tilesets as reference: DF's tile

- Dwarf Fortress tilesets as reference: DF's tile-based renderer maps each character to a custom glyph in a bitmap tileset; does Elf Revel's architecture allow an optional tileset overlay, or is it hardwired to terminal font rendering?

## Severity Calibration

- **P1**: A 24-bit color terrain background bleeds into the status panel because the panel renderer doesn't explicitly reset bg color before writing, producing corrupted panel appearance
  - When: No explicit color reset at layer boundaries in the crossterm render pass
- **P2**: Full-screen redraw on every tick causes visible flicker when the map uses dense Unicode glyphs (braille, half-block) because terminal emulator must re-render all cells
  - When: No dirty-cell tracking; entire buffer submitted to crossterm every frame
- **P3**: Overlay layer (beauty aura, path highlight) written on top of terrain completely replaces the terrain Unicode glyph instead of compositing color on it
  - When: Overlay writes full cell including glyph character, not just color attributes

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
