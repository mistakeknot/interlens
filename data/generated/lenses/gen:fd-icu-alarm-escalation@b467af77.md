## Severity Calibration

- **P1**: The health JSON `signals` object shows `status: fired` for the perf signal but does not include the current advisory_offset value or whether the offset has already reached OffsetMin — a consumer building a recovery dashboard sees a persistent fired signal with no indication of whether Ockham is still responding to it or whether the actuation path is already saturated
  - When: When health JSON is designed as a status report rather than an action-linked state snapshot — the consumer cannot distinguish between a signal that is firing and being actioned from a signal that is firing and stuck at actuator floor
- **P1**: The pleasure signal trends displayed in health JSON are computed over a 24h window for readability, while Ockham's ratchet promotion logic uses the 10-bead rolling window — a principal reads improving cycle_time trend in health JSON while Ockham is simultaneously demoting an agent because the 10-bead window shows a spike, creating a trust-destroying inconsistency where the dashboard says healthy and the ratchet says degraded
  - When: When display window and decision window are chosen independently without documenting the divergence in the health schema or flagging it to the consumer
- **P2**: The `halt_reason` field is a Go error string like `2 distinct root causes fired simultaneously: auth, perf` — parseable by a human but not by Meadowsyn's alerting logic, which needs to know the fired theme names as a structured array to route the right recovery flow
  - When: When halt_reason is designed for human log consumption rather than as a structured field that machine consumers can act on without string parsing

## Decision Lens

Evaluates through the lens of alarm actionability: every tier in a well-designed ICU alarm system has a mandatory linked action, not just a notification — INFORM must produce a visible state change in the dispatch weights, CONSTRAIN must visibly alter the theme freeze state, and BYPASS must visibly halt the factory. A health consumer reading the JSON should be able to reconstruct what Ockham did in response to each signal, not just that signals exist. If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.
