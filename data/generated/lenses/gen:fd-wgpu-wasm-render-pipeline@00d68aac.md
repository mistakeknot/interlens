## Task Context

Elf Revel — Rust/WASM colony sim evaluating wgpu-based spatial ASCII rendering. Current codebase uses hecs ECS and rust_pixel for TUI. Proposed paradigm shift requires a browser-capable GPU rendering pipeline that can composite ASCII glyphs as spatial textures. Must work across browsers.

## Review Approach

### 1. Framework selection tradeoffs: raw wgpu gives maximum con...

- Framework selection tradeoffs: raw wgpu gives maximum control but requires building a 2D renderer from scratch; bevy provides a full ECS+renderer but may conflict with hecs; macroquad is simple but WASM support has known texture memory leaks; pixels is CPU-only which simplifies but limits — does the chosen stack match the project's actual constraints?

### 2. WebGPU vs WebGL2 fallback: wgpu targets WebGPU in browser...

- WebGPU vs WebGL2 fallback: wgpu targets WebGPU in browsers but Safari/Firefox support is incomplete as of 2025; the WebGL2 backend has different shader constraints and performance characteristics — is there a tested fallback path?

### 3. WASM memory constraints: WASM linear memory defaults to 2...

- WASM memory constraints: WASM linear memory defaults to 256MB with 4GB max; texture atlases for pre-rasterized ASCII glyphs plus tile maps plus entity sprites must fit within this — is the memory budget calculated and enforced?

### 4. Shader cross

- Shader cross-compilation: wgsl shaders compiled via naga for WebGPU work differently than the WebGL2 GLSL output; custom 2D shaders for character rendering (SDF text, color manipulation, depth effects) must be tested on both backends

### 5. Frame budget accounting: at 60fps in WASM

- Frame budget accounting: at 60fps in WASM, the frame budget is 16.6ms but JavaScript GC pauses and wasm-bindgen overhead steal 2-4ms; the actual rendering budget is closer to 12ms — does the architecture account for this with a frame budget profiler?

## Severity Calibration

- **P0**: The game renders a black screen on Safari because WebGPU is not available and no WebGL2 fallback is configured, excluding a significant portion of the browser audience
  - When: wgpu WASM build targets WebGPU only with no adapter fallback to webgl2 feature flag
- **P1**: WASM memory grows unbounded as new ASCII glyph textures are rasterized on demand and never evicted, causing an OOM crash after 30 minutes of gameplay
  - When: No texture cache eviction policy; glyph atlas grows monotonically
- **P2**: Custom depth-coloring fragment shader works perfectly in native wgpu but produces different color output on WebGL2 backend due to precision differences in mediump float
  - When: Shaders not tested on WebGL2 backend; no precision qualifiers specified

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
