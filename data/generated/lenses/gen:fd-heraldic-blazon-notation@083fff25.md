## Task Context

Blazon solved the problem of describing complex visual compositions in minimal text 600 years ago. Terminal UIs are simpler than heraldic shields.

## Review Approach

### 1. Tincture vocabulary

- Tincture vocabulary — blazon uses 7 named colors instead of hex values. Terminal could use semantic color names (error-red, success-green) instead of RGB.

### 2. Positional grammar

- Positional grammar — blazon encodes position through named regions (chief, base, dexter, sinister) not coordinates. Terminal regions could be named (status-bar, main-content, input-area).

### 3. Charge description by type not appearance

- Charge description by type not appearance — a lion is described by attitude (rampant, passant) not pixels. A UI element could be described by role (button, menu-item) not characters.

### 4. Marshalling

- Marshalling — combining multiple shields into one through quartering/impalement. Maps to: composing multiple terminal panes.

### 5. Cadency marks

- Cadency marks — minimal additions that differentiate related arms. Maps to: diff encoding where only changes from a base state are described.

## Severity Calibration

- **P1**: Coordinate-based description when semantic regions would suffice
  - When: Encoding 'red text at column 45 row 3' instead of 'error message in status bar'
- **P2**: No vocabulary for common terminal patterns
  - When: Describing a progress bar character-by-character instead of 'progress: 73%'

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
