## Review Approach

### 1. Optional stopping bias from agent

- Optional stopping bias from agent-driven observation timing: if the agent decides when to pause and observe based on its current beliefs about the simulation state, the observation schedule is informative — the agent observes more when it is uncertain or sees early signals of misalignment, creating a systematic relationship between observation timing and trace content that inflates the apparent alignment signal; this is structurally identical to the optional stopping problem that invalidates non-pre-specified interim analyses in clinical trials

### 2. Pre

- Pre-specified vs. data-dependent gate placement: mandatory fixed gates are statistically conservative but reproducible — any analyst can reconstruct the observation schedule without knowing the agent's internal state; agent-driven gates are adaptive and potentially more informative but require a pre-specified stopping rule (the equivalent of a group-sequential testing boundary) that controls the Type I alignment-detection error rate across the adaptive schedule

### 3. Cross

- Cross-model comparability under non-identical observation schedules: if Model A takes 30 observations in a scenario and Model B takes 8, their alignment traces have different temporal resolution — comparing alignment profiles derived from traces with structurally different sampling densities requires a normalization methodology that the F1 specification must define, or the comparison is confounded by observation frequency

### 4. Informative censoring in partial

- Informative censoring in partial-run traces: if an agent-driven protocol allows early termination (the agent decides the scenario is resolved and stops observing), partial traces are informatively censored — the missing trace data is systematically associated with the agent's assessment of the situation, not randomly missing, and alignment profiles derived from partial traces will be biased in the direction of agent self-assessment

### 5. Baseline run reproducibility requirement: for a benchmark...

- Baseline run reproducibility requirement: for a benchmark to be scientifically valid, a model re-evaluated on the same scenario should produce a comparable alignment profile within a defined reproducibility interval; agent-driven timing introduces between-run variance in observation schedule that increases profile variance beyond model behavior variance — the benchmark must define a reproducibility tolerance and test whether agent-driven timing produces profiles within it

### 6. Stopping rule specification

- Stopping rule specification and alignment with benchmark claims: if F1 uses adaptive gate timing, the stopping rule must be pre-specified in the benchmark methodology document — an undocumented adaptive schedule that produces 'better' alignment signal is methodologically equivalent to p-hacking; the specification must commit to a specific adaptive algorithm (e.g., 'observe when pressure delta exceeds threshold X') before data collection, not post-hoc from results
