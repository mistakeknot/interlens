## Review Approach

### 1. Each parser targets stable DOM landmarks (e.g.

- Check that each parser targets stable DOM landmarks (e.g., ASIN anchor hrefs, order-ID headings) rather than positional sibling counting — Amazon redesigns its email templates frequently and positional selectors rot within months

### 2. The parsers handle both plain-text fallback and HTML multipart MIME correctly

- Verify that the parsers handle both plain-text fallback and HTML multipart MIME correctly — some Amazon confirmation emails arrive as `text/plain` only (e.g., forwarded or stripped by corporate filters), and a parser that only reads `text/html` will silently miss them

### 3. That price parsing handles currency symbols

- Validate that price parsing handles currency symbols, comma-separated thousands, and locale variants (e.g., `$1,299.99` vs `1.299,99 EUR`) — incorrect price extraction produces nonsense spending-pattern data in Auraken's context models

### 4. That ASIN extraction handles both standard B0XXXXXXXX ASINs and 10-digit

- Confirm that ASIN extraction handles both standard B0XXXXXXXX ASINs and 10-digit numeric ASINs (e.g., books) — using a regex that only matches `B0` prefixes will silently drop book purchases

### 5. The parser suite has documented sender address allow-lists and rejects emails

- Check that the parser suite has documented sender address allow-lists and rejects emails from unexpected senders before parsing — processing a spoofed `auto-confirm@amazon.com` lookalike without validation injects attacker-controlled product data

### 6. Malformed or partial emails (truncated HTML

- Ensure that malformed or partial emails (truncated HTML, missing order blocks) raise structured parse errors with the email message ID, not unhandled exceptions that crash the pipeline mid-batch

## Severity Calibration

- **P0**: Parser accepts spoofed sender address and injects attacker-controlled SKU data into jawncloud
  - When: When sender validation is absent or uses only substring matching on the From display name rather than the envelope address
- **P1**: Plain-text MIME fallback not handled — all emails from users with text-only clients or corporate email proxies are silently skipped

- **P2**: Price parser fails on non-US locale formats, storing 0 or NaN for European Amazon purchases
  - When: When a user's Gmail contains amazon.de or amazon.co.uk confirmations and the price regex assumes US decimal format
