## Task Context

## Severity Calibration

- **P1**: The cross-process cooldown file is written by one model's AdaptiveSemaphore and read by a different model's semaphore because both use the same cooldown file path pattern, causing an unaffected model to wait unnecessarily
  - When: claude-sonnet-4.6 rate limit causes gpt-5.4-api to pause even though it is on a different rate limit domain
- **P1**: ThreadPoolExecutor(max_workers=N) is set to a fixed value independent of the number of models being evaluated, and for a full 9×9 matrix run the pool is smaller than the semaphore headroom, causing live-lock where all threads are acquired but blocked waiting for pool slots
  - When: Matrix evaluation stalls with no error output, appearing to run but producing no completions
- **P2**: AIMD ramp threshold is ceil(current) consecutive successes — at concurrency=1 this requires 1 success to reach 2, then 2 to reach 3, then 3 to reach 4, which is O(n^2) recoveries after a multiplicative decrease to 1 from a large concurrency value
  - When: After a burst of 429s that collapses concurrency to 1, the model takes 100+ successful calls to restore prior throughput, causing the matrix run to take 10x longer than expected

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

Flags concurrency designs where a single slow or rate-limited backend can block progress on unrelated backends, where the adaptive algorithm oscillates rather than converges, or where backpressure from one source propagates incorrectly to others. If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.

## Prioritization

- P0: Issues that block other work, cause data loss or corruption — drop everything
- P1: Issues required to exit the current quality gate
- P2: Issues that degrade quality or create maintenance burden
- P3: Improvements and polish — suggest but don't block on these
- For each P0/P1 finding, describe the concrete failure scenario: what breaks, under what conditions, and who is affected
- Always tie findings to specific files, functions, and line numbers
- Frame uncertain findings as questions, not assertions
