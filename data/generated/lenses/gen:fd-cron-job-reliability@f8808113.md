## Task Context

scripts/training-scout-cron.sh runs daily at 3:00 AM UTC via crontab on slse. It checks pipeline health, checks if a scout is already running, then POSTs to /training-scout/search with a 30-minute timeout. Results are logged to /var/log/training-scout.log. The script sources .env if PIPELINE_AUTH_TOKEN is not set. set -euo pipefail is active.

- The overlap-prevention check calls /training-scout/status and treats a failed curl (network error) as 'running:true' (safe default) — verify this is correct and not overly conservative; a permanently unreachable status endpoint would permanently skip all cron runs

- The main curl call uses --max-time 1800 (30 minutes) but the script has set -euo pipefail — if the pipeline returns a non-200 HTTP status, curl -sf exits non-zero and the script exits with a misleading 'Scout request failed' message regardless of what the actual error was

- The .env sourcing uses 'source' (bash dot-source) which pollutes the cron shell environment for the duration of the script — if the .env file contains variables with side effects or exports, they persist and could affect subsequent commands

- The log appended to /var/log/training-scout.log via crontab redirect never rotates — examine whether this file can grow unboundedly and whether it is world-writable (permission issues) or owned by root vs mk

- Examine whether 'python3 -m json.tool' for result formatting will mask a non-zero exit from the prior command in the pipeline via EXIT_CODE=$? capture — the $? is captured before the python3 formatting, but the JSON extraction subshells also ignore errors

### 6. Assess whether the script handles the case where PIPELINE_HOST/PORT env vars

- Assess whether the script handles the case where PIPELINE_HOST/PORT env vars are not set in cron's minimal environment — cron does not inherit the user's full shell environment, so defaults (127.0.0.1:3847) must be explicitly set or sourced from a known file

## Severity Calibration

- **P1**: The /training-scout/status endpoint is slow to respond (network congestion, not actually running), curl returns exit code 28 (timeout), the script interprets this as 'running:true', and the cron job silently skips every run for days
  - When: curl failure on status check defaults to 'running:true' with no timeout distinction from genuine running state
- **P1**: Two cron runs overlap (cron triggered while previous run is still within its 30-minute --max-time window due to a slow scout run), both pass the status check in the same second before either updates the running flag, and both submit duplicate training-scout triggers
  - When: The status-check and trigger are not atomic — there is a TOCTOU window between checking 'running' and setting 'running'
- **P2**: The cron job sources .env which sets ANTHROPIC_API_KEY, but a previous cron run had already exported a different API key into the environment — source does not unset variables not in .env, so a rotated key may not take effect if the variable was already exported
  - When: source does not override previously-exported environment variables from cron's inherited environment

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

Prioritizes failure modes where the cron job completes with exit 0 despite doing no useful work (silent failures), overlapping runs that cause duplicate data ingestion, and environment leakage that causes the job to authenticate with wrong credentials on subsequent runs. If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.

## Prioritization

- P0: Issues that block other work, cause data loss or corruption — drop everything

- P2: Issues that degrade quality or create maintenance burden
- P3: Improvements and polish — suggest but don't block on these
- For each P0/P1 finding, describe the concrete failure scenario: what breaks, under what conditions, and who is affected
- Always tie findings to specific files, functions, and line numbers
- Frame uncertain findings as questions, not assertions
