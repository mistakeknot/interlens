  - When: the design doesn't specify a queue/dispatch boundary between the fork point and each branch's consumer
- **P0**: The AVAudioSession category chosen implicitly enables voice-processing/AGC (common default for .playAndRecord with voice chat options), which alters the raw audio samples before they ever reach branch A's asset-writer input — the 'raw audio' contributors consented to is actually processed, and this is unrecoverable after the fact.
  - When: no explicit AVAudioSession category/mode/option is specified, or the chosen mode is known to enable adaptive processing
- **P1**: The gap detector measures inter-buffer PTS gaps against a fixed nominal buffer duration constant, but the actual IOBufferDuration shifts after a route change (e.g. Bluetooth negotiates a larger buffer), causing every post-route-change buffer to register as a false-positive 'drop' for the remainder of the session, corrupting the acceptance metric.
  - When: gap threshold is a hardcoded constant rather than derived from the session's live audio format/buffer duration
- **P2**: Branch B shedding is described as 'lower QoS' with no defined resume/backpressure behavior — when thermal pressure clears, there's no specified mechanism to resume TapHealthMeter cleanly (re-subscribe, buffer drain, cold-start stats), so the session-stats artifact may show a permanently degraded FrameGate/audio-health signal even after recovery.
  - When: no explicit resume path is defined for a shed branch-B consumer
