## Task Context

Six open design questions for a dynamic flora system in an elven colony sim (Rust ECS, WASM). The flora system sits on a geology foundation (TileData with soil, fertility, erosion, water table). Currently 2 forest terrain types exist (AncientForest, YoungForest) with no species or growth. The core architectural question is whether flora entities replace, overlay, or gradually convert these terrain types. Sprint scoping must decompose a large brainstorm into shippable increments. Gardens currently exist as BuildingType::Garden clearing creative blocks.

## Review Approach

### 1. Layer ordering

- Layer ordering and terrain architecture (Q3): manuscript illumination has an absolute physical constraint — gold leaf must be applied before pigment, because gold sticks to wet pigment. Option A (full replacement) is like starting with blank vellum and doing everything from scratch. Option B (overlay) is like adding illumination to an already-scribed page — the text (terrain) stays, decoration (flora entities) layers on top. Option C (graduated) is like a scriptorium that scribes some pages while illuminating others. Which layer ordering respects the 'gold before pigment' constraint — which systems MUST be in place before flora entities can exist?

### 2. Scope as selection

- Scope as selection, not reduction (Q2): a master illuminator doesn't illuminate every page — the Book of Kells has fully illuminated carpet pages, moderately decorated text pages, and plain pages. Scope isn't about doing less work per page but about choosing WHICH pages to illuminate. Sprint scoping (Q2) should decide which subsystems get full treatment (Option A's growth stages = carpet page) vs. which get basic treatment (ecological dynamics = plain page for now). Does the sprint scope preserve the ability to return and illuminate later?

### 3. Utility

- Utility and art coexistence (Q6): the illuminated manuscript's deepest insight is that the same object (a page) serves both utility (you can read the text) and art (the decoration is beautiful). Garden-as-art (Q6) faces the same tension — gardens clear creative blocks (utility) AND can be compositions (art). Option B (species palettes as hook) mirrors the manuscript tradition of adding minor decoration (rubrication, colored initials) that serves both utility and beauty without full illumination. Does the design preserve the page's legibility while adding art?

### 4. Hierarchical decoration density (Q5): manuscripts have a ...

- Hierarchical decoration density (Q5): manuscripts have a density hierarchy — some pages are fully covered in paint and gold (high density), some have decorated initials only (medium), some are plain text (low). This isn't random — it follows the liturgical importance of the content. Flora entity density should similarly follow a hierarchy tied to ecological or aesthetic importance. Does the design have a principle for WHERE density concentrates, or is it uniform?

### 5. The scriptorium pipeline

- The scriptorium pipeline and sprint ordering (Q2): multiple specialists work in strict sequence — the scribe MUST finish before the gilder, who MUST finish before the painter. Sprint ordering should respect similar dependency chains. Does the sprint plan identify which systems are 'scribing' (must be done first, everything depends on it) vs. 'painting' (can be done last, depends on everything else)? Option A's 'core flora only' is scribing — but is it correctly identified as the layer everything else depends on?

## Severity Calibration

- **P1**: The terrain architecture decision (Q3) creates a layer ordering where flora entities depend on terrain types that may be removed, like applying pigment before gold leaf — the foundation layer is unstable
  - When: Option A (full replacement) is chosen but existing systems that read Terrain::AncientForest are not catalogued, creating hidden dependencies that break when the base layer changes
- **P2**: Sprint scope is defined by reducing the depth of every subsystem rather than selecting which subsystems get full treatment, producing a uniformly thin layer of work rather than concentrated excellence
  - When: Sprint 1 ships partial versions of multiple subsystems (growth + blight + gardens all at 30% depth) rather than one subsystem at full depth with others deferred as plain pages
- **P3**: Garden utility and garden art are treated as sequential phases (utility first, art later) rather than coexisting layers on the same entity, forcing a future refactor to add art to something designed only for utility
  - When: Q6 Option A is chosen in a way that makes gardens structurally unable to support later artistic enhancement without reimplementation

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
