  - When: Confirm by grep across all schema files for repeated enum value lists rather than a single `$ref`-shared definition.
- **P1**: The Swift stage-declaration type uses a plain `String` (or an enum with a `case other(String)` catch-all) for `privacy_class` instead of an exhaustive closed enum, meaning a schema addition of a new privacy_class value would compile silently in Swift with no forced call-site update, while the flow-rule check might default-allow or default-deny inconsistently with Python's handling of the same unknown value.
  - When: Check the Swift type definition for the privacy_class field and confirm it is a true exhaustive enum (no raw-string fallback case) whose non-exhaustive switch is a compile error.

  - When: Inspect the fixtures directory plan/description for at least one 'privacy-flow-violation' vector distinct from plain schema-invalid vectors.
