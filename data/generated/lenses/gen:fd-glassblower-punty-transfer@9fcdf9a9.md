The read opens state.db, which re-creates state.db-shm (a memory-mapped shared memory file), and on close leaves the DB in a post-checkpoint but -shm-present state. copytree copies the stale -shm, and the resulting profile DB fails integrity check.
  - When: Plan does not forbid any hermes or sqlite3 invocation against the root DB between checkpoint and copytree. Recommend an explicit 'do not run any hermes command between steps 4 and 6' instruction.

Operator notices the failure and retries, but the partially-copied profile directory from the first attempt is still present. Second copytree either merges with the partial directory or errors; in either case the result is an inconsistent profile. Phase 2 proceeds anyway because the plan has no 'verify profile complete' gate.
  - When: Plan does not checksum or file-count verify the profile directory after copytree before proceeding to Phase 2.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
