## Task Context

F5 builds a TemplateRegistry of 8 named QueryTemplate protocol classes, each exposed as a typed MCP tool by the Go adapter. Each template encodes expert knowledge about how to answer a cross-system question using crosswalk, engine, and connectors. The 8 templates cover distinct question types: actor provenance, bead context, session inventory, entity relationships, actor activity, evidence gathering, artifact structure, and chronological history.

## Review Approach

### 1. Template name precision and question scope boundary: library search strategies

- Template name precision and question scope boundary: library search strategies fail when their name implies broader coverage than the strategy actually provides — 'who_touched_file' implies all actors across all time, but if the strategy only queries cass (which indexes sessions from the last N days) and crosswalk (which may have sparse coverage for old files), the result is a subset of the true answer. Assess whether each QueryTemplate's description accurately documents its scope boundary: time range, subsystem coverage, entity type coverage, and what classes of actor or event it cannot retrieve

### 2. Controlled vocabulary translation and the concept binding problem: systematic

- Controlled vocabulary translation and the concept binding problem: systematic review strategies must translate a canonical concept ('myocardial infarction') into each database's subject heading scheme (MeSH, Emtree, CAB Thesaurus) — missing a vocabulary mapping means missing a class of relevant evidence. Assess whether the QueryTemplate protocol requires each template to document its entity type bindings per connector: what does 'actor' mean in the cass connector versus the beads connector versus the crosswalk, and whether a template that uses 'actor' as a concept produces consistent results regardless of whether the actor appears primarily in one subsystem versus another

### 3. Recall vs. precision tradeoff and template sensitivity calibration: library

- Recall vs. precision tradeoff and template sensitivity calibration: library search strategies are calibrated for recall (find everything relevant) or precision (find only highly relevant) depending on their use case — a systematic review strategy maximizes recall at the cost of false positives, while a quick reference strategy maximizes precision. Assess whether the 8 F5 templates have an explicit recall/precision posture, and whether templates like entity_relationships (pure engine query) and evidence_for_entity (cross-subsystem aggregation) have different sensitivity calibrations that agents should know about when choosing which template to invoke

### 4. Strategy documentation and the expert knowledge gap: the value of a library

- Strategy documentation and the expert knowledge gap: the value of a library search strategy is that it encodes expert knowledge that a non-expert cannot reconstruct — without documentation, the strategy is a black box that the invoker must trust blindly. Assess whether each QueryTemplate's description field documents not just what it returns but why it was designed that way: which interaction rules it uses, which connector joins are semantically meaningful, and what the design tradeoffs were (e.g., why entity_timeline aggregates crosswalk history rather than querying each connector's native event log)

### 5. Strategy obsolescence and the connector evolution problem: library search

- Strategy obsolescence and the connector evolution problem: library search strategies become obsolete when databases change their subject heading schemes or add new coverage — a strategy built against MEDLINE 2020 vocabulary may miss new concepts indexed under changed terms. Assess whether the TemplateRegistry design includes a mechanism for detecting when a connector's schema or indexing coverage has changed in a way that may affect template recall, and whether templates have a version or last-validated timestamp that signals to consumers when a strategy may be stale

### 6. Reference interview and parameter elicitation: expert reference librarians do

- Reference interview and parameter elicitation: expert reference librarians do not give a search strategy to a patron without first understanding the patron's actual information need, because the patron's stated question is often not their real question. Assess whether the F5 MCP tool schemas give the Go adapter and the calling agent enough information to match a question to the right template, or whether an agent asking 'what is connected to this entity?' will invoke entity_relationships when they actually need entity_timeline or related_artifacts, because the templates' scope descriptions do not disambiguate their use cases

## Severity Calibration

- **P1**: The actor_activity template's description says 'returns recent activity across subsystems: sessions run, beads worked, files touched'. An agent invokes it with an actor identifier that exists in beads (as claimed_by) but not in cass (the actor ran sessions before cass was installed). The template returns results for beads and files but empty results for sessions — but the description does not document the minimum cass installation date required for session coverage. The agent infers that this actor has no sessions, when in fact the actor has extensive session history that predates cass indexing.
  - When: When template descriptions document what is returned without documenting the temporal or installation-coverage preconditions that determine whether the returned data is complete, causing agents to treat scope-limited results as exhaustive answers
- **P1**: The entity_relationships template is documented as returning 'all valid relationships and linked entities using the relational calculus engine'. An agent passes a canonical ID for a session entity. The engine's interaction rules do not include a session-to-file relationship because sessions are modeled as Actor-family entities, not as Artifact-family entities, and the structure interaction rule only applies to Artifact-family. The template returns an empty relationships list with no indication that the query concept ('session') is outside the template's entity family scope.
  - When: When templates do not validate that the input entity's type family is within the template's defined scope before executing the query, causing silently empty results for out-of-scope inputs rather than a descriptive scope error
- **P2**: A developer adds a ninth template (agent_provenance) to the templates/ package to track which agent generated which artifacts. The template's description field is a placeholder ('returns provenance for agent outputs'). The MCP tool listing now includes agent_provenance with an underdocumented schema. An agent selects it for a query that would have been better served by evidence_for_entity because both templates surface similar evidence types. The agent gets partial results and cannot determine whether the gap is a template scope limitation or missing data.
  - When: When the TemplateRegistry does not enforce a minimum documentation standard for description quality (required fields: question scope, entity family constraints, subsystem coverage, recall posture) during registration, allowing underdocumented templates to appear in tool listings that agents rely on for self-directed template selection

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

Evaluates through the lens of search strategy formalization: a well-designed named search strategy is not a query string — it is an expert-encoded answer template with a canonical question shape, controlled vocabulary bindings per data source, and a documented scope that tells the invoker what types of evidence it will and will not retrieve. The critical failure modes are templates that answer a slightly different question than their name implies, templates whose scope is opaque to the invoker, and templates that silently return incomplete results when a source database's vocabulary does not map to the canonical concept.
