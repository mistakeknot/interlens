## Task Context

Budget enforcement is currently binary (launch or defer). Cross-model dispatch adds a continuous dimension (which tier). Budget pressure is a global constraint like grid congestion.

## Review Approach

### 1. Merit order dispatch

- Merit order dispatch — grid dispatches cheapest generation first, then more expensive units as demand rises. Cross-model dispatch inverts this: assigns expensive models to high-confidence signals. Is the inversion justified?

### 2. Must-run units

- Must-run units — some generators must run regardless of cost (nuclear baseload). Safety-floor agents are must-run. Is the must-run list complete?

### 3. Ramping constraints

- Ramping constraints — grid units can't switch instantly. Is there an equivalent constraint on model switching? (Agent restart cost, context loss)

### 4. Contingency reserves

- Contingency reserves — grid keeps spinning reserves for N-1 contingency. Should cross-model dispatch keep a reserve of sonnet-tier capacity for late-arriving expansion candidates?

### 5. Congestion management

- Congestion management — when transmission is constrained, dispatch changes. Budget pressure is congestion. Does the brainstorm handle congestion correctly?

## Severity Calibration

- **P1**: No reserve capacity: all budget allocated to Stage 2, late-arriving speculative launch has no tier headroom
  - When: Budget pressure computed without reserving capacity for incremental expansion
- **P2**: Merit order inversion: high-confidence agent gets haiku while low-confidence agent keeps sonnet due to processing order
  - When: Tier adjustment processes agents in arbitrary order instead of by expansion score

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
