## Task Context

F5 builds a TemplateRegistry of 8 named QueryTemplate protocol classes, each exposed as a typed MCP tool by the Go adapter. Each template's execute() joins data across multiple connectors (beads, cass, crosswalk, engine). The result type is a QueryResult dataclass with entities, relationships, and metadata. The Go adapter calls Python via subprocess stdin/stdout JSON. Templates compose existing primitives without adding new storage.

## Review Approach

### 1. Parameter schema stability vs. subsystem schema coupling: BI report templates

- Parameter schema stability vs. subsystem schema coupling: BI report templates that expose raw database column names as parameters create brittle contracts — when the source schema changes, every template consumer must update — check whether the F5 QueryTemplate protocol's parameters_schema() uses semantic parameter names ('file_path', 'actor_id') that are decoupled from subsystem-internal identifiers (cass session UUID column names, crosswalk entity ID formats), so that parameter changes in subsystems do not cascade into MCP tool schema changes that break agent integrations

### 2. Result schema completeness and the partial-data problem: BI reports over

- Result schema completeness and the partial-data problem: BI reports over multi-source joins must declare their completeness guarantees — a report that joins sales data with HR data returns incomplete results if HR is unavailable, and the consumer must know whether partial results are returned with a warning or whether the query fails — assess whether QueryResult's metadata field carries completeness signals: which connectors contributed data, which returned empty sets versus errors, and whether an empty QueryResult indicates 'no data exists' or 'one or more subsystems was unreachable during query execution'

- Template registry discoverability vs. tool explosion: BI platforms with hundreds of named reports create 'tool overload' for consumers who cannot discover relevant reports — this is the exact problem the brainstorm solves with one-MCP-tool-per-query — but assess whether 8 initial templates covers the actual agent query patterns or whether the initial set creates gaps that cause agents to compose ad-hoc cross-system queries outside the template layer, defeating the discoverability goal. ### 4. Parameterized query injection and the SQL analog: BI platforms that construct

- Parameterized query injection and the SQL analog: BI platforms that construct queries by string-interpolating user-provided parameters are vulnerable to injection — check whether QueryTemplate.execute() uses parameterized query primitives throughout (crosswalk.lookup(canonical_id), not string-interpolated SQL-equivalents), and whether parameter validation in parameters_schema() catches type mismatches before the query begins execution rather than after partial subsystem calls have been made

### 5. Template versioning and the MCP tool schema migration problem: BI report

- Template versioning and the MCP tool schema migration problem: BI report templates that change their output schema break dashboards that depend on them — in F5, changing a QueryTemplate's result shape changes the MCP tool schema seen by agents — assess whether the TemplateRegistry design includes a versioning mechanism for templates, and what the migration path is when a template's result schema must evolve (new fields, renamed relationships, removed connectors) without forcing all MCP consumers to update simultaneously

### 6. Execution timeout and cross-subsystem latency budgets: BI reports that join

- Execution timeout and cross-subsystem latency budgets: BI reports that join live operational data can time out unpredictably when source systems are slow — check whether QueryTemplate.execute() has a timeout budget that is allocated across the constituent subsystem calls (crosswalk, cass, beads), so that a slow cass connector cannot cause the entire who_touched_file query to time out, and whether partial results with a timeout flag are preferable to a hard failure for the agent consumer

## Severity Calibration

- **P1**: The who_touched_file template's result schema includes the raw cass session UUID as the primary actor identifier in the returned entity list. A later version of cass changes its session ID format from UUID to a prefixed string. The QueryTemplate implementation is updated to handle the new format, but the result schema still exposes the raw cass session UUID to MCP consumers. Agents that stored session UUIDs from prior who_touched_file calls to pass as parameters to actor_activity calls now receive format-mismatch errors because the stored IDs are old-format UUIDs.
  - When: When the QueryResult entity identifiers are raw subsystem-native IDs rather than canonical crosswalk IDs, causing result schema breakage to propagate to consumers when any subsystem changes its ID format
- **P1**: The bead_context template joins beads connector + crosswalk + cass. During execution, cass returns an error (cass index is stale and refuses the query). The template returns a QueryResult with the beads and crosswalk data populated but the sessions field empty. The agent consuming the result treats the empty sessions field as 'no sessions worked on this bead' rather than 'sessions data was unavailable' and incorrectly concludes the bead has no recent activity, leading to a misclassification of the bead's urgency.
  - When: When QueryResult does not distinguish between empty-set (subsystem returned zero results) and error-absent (subsystem was unreachable or errored), causing agents to misinterpret missing data as negative evidence
- **P2**: The TemplateRegistry is populated at import time when the interweave package is loaded. A new template is added by creating a new file in src/interweave/templates/ but the developer forgets to add the import line in __init__.py. The template class exists on disk and passes code review but is never registered, so it is invisible to the Go MCP adapter's tool listing. The missing tool is not detected until an agent attempts to call it by name and receives a 'tool not found' error, rather than at startup when the registry could validate that expected templates are present.
  - When: When TemplateRegistry population depends on manual import statements rather than automatic discovery of all QueryTemplate subclasses in the templates/ package directory, causing silent registration gaps when new templates are added

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

Evaluates through the lens of parameterized report template design: a named query template is a contract between the producer (the template definition) and the consumer (the agent invoking the MCP tool) — the contract must specify the input parameter schema, the output result schema, and the latency/completeness guarantee independently of the implementation. The critical failure modes are leaking implementation details (subsystem names, join keys, internal IDs) into the public result schema, allowing result shape to vary based on which subsystems have data, and failing to separate template versioning from subsystem versioning.
