## Task Context

Gmail purchase import pipeline: Auraken (Python 3.12+, PostgreSQL + pgvector) authenticates via Gmail OAuth (`gmail.readonly`), parses order confirmation emails, calls interjawn MCP to upsert SKUs into jawncloud, and writes purchase-pattern context to Auraken's profile models. ## Review Approach

### 1. The OAuth consent screen requests only `gmail.readonly` and that no broader

- Verify that the OAuth consent screen requests only `gmail.readonly` and that no broader scope (e.g., `gmail.modify`, `https://mail.google.com/`) is ever requested or stored — scope creep at consent time is invisible to users and violates the brainstorm's own privacy contract

### 2. Refresh tokens are stored encrypted at rest in Auraken's PostgreSQL and that

- Check that refresh tokens are stored encrypted at rest in Auraken's PostgreSQL and that the storage schema is documented — refresh tokens are long-lived credentials and storing them in plaintext is a P0 data exposure

### 3. The pipeline handles `invalid_grant` (revoked or expired refresh token)

- Confirm the pipeline handles `invalid_grant` (revoked or expired refresh token) gracefully — the user must be re-prompted for consent, not silently failed or left with stale data from a previous run

### 4. That token revocation is offered and implemented when a user wants to

- Validate that token revocation is offered and implemented when a user wants to disconnect Gmail — simply deleting the DB row is insufficient; the token must be revoked via `https://oauth2.googleapis.com/revoke` so Google's grant list is cleared

### 5. The OAuth redirect URI is validated and registered in Google Cloud Console

- Ensure the OAuth redirect URI is validated and registered in Google Cloud Console — an open redirect or mismatched URI causes `redirect_uri_mismatch` errors that block all new authorizations

### 6. Access tokens are never logged

- Check that access tokens are never logged, transmitted in URLs, or included in error messages — even short-lived access tokens in logs create an exposure window

## Severity Calibration

- **P0**: Refresh token stored in plaintext in a database column or log file
  - When: Any code path that persists the token without encryption, or any log statement that includes token values
- **P1**: Pipeline silently swallows `invalid_grant` and reports success with zero imports
  - When: When the error handler catches the OAuth exception but does not surface it to the user or retry with re-consent
- **P2**: Token revocation endpoint not called on user disconnect
  - When: When the user removes Gmail integration but Auraken only deletes its local token row without notifying Google

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
