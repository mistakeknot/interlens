## Review Approach

### Key Review Areas

- **System coupling and data flow between systems**: Examine how combat, economy, quests, and NPC dialogue interact. In agentmud, these are mediated by predicates and effects — verify that the predicate/effect system provides clean boundaries. Flag cases where one system directly reads another's internal state rather than going through the predicate engine.

- **Economy sinks/faucets balance**: Check that resource flows (give_resource, take_resource) have balanced sources and drains. Verify that the economy cycle detection in pack validation catches net-positive loops. Flag quest/NPC/item combinations that create unbounded resource generation.

- **Crafting recipe graph completeness**: Not applicable in v0/MVP (crafting is deferred), but review economy preset designs (Phase 3) for completeness if present. Check that resource type definitions in packs cover all referenced resources.

- **Progression curve vs content gating alignment**: Verify that quest prerequisites and predicate gates create a reasonable progression path. Check that the pack's room graph, quest dependencies, and resource requirements form a completable game. Flag dead-end states where a player can get permanently stuck.

- **Loot table probability distributions**: Check that item distribution via effects (give_item, spawn_item) and resource grants create reasonable acquisition curves. Flag items that are either trivially easy or impossibly hard to obtain given the pack's quest structure.

### How to Review

1. **Read before judging** — understand the existing approach before suggesting changes
2. **Be specific** — reference actual files, functions, and line numbers
3. **Prioritize** — distinguish must-fix issues (P0/P1) from improvements
4. **Respect context** — the team may have intentional trade-offs you're not aware of
