## Review Approach

- Cost estimate update — when a Stage 2 agent is downgraded from sonnet to haiku, does the budget tracker reflect the lower token estimate?

### 2. Budget pressure computation

- Budget pressure computation — is remaining_budget / sum(stage2_estimates) calculated before or after tier adjustment?

### 3. Circular dependency: budget pressure influences tier → tier influences cost

- Circular dependency: budget pressure influences tier → tier influences cost estimate → cost estimate influences budget pressure

### 4. Interaction with AgentDropout

- Interaction with AgentDropout — if dropout saves tokens, does that increase remaining budget for tier decisions?

### 5. Estimate-costs.sh integration

- estimate-costs.sh integration — does it have per-model cost data, or only per-agent averages?

## Severity Calibration

- **P1**: Budget tracker shows Stage 2 at sonnet cost but agents actually run at haiku
  - When: Budget not updated after tier adjustment
- **P1**: Circular dependency causes oscillation — agent downgraded, budget improves, agent upgraded, budget worsens
  - When: No fixed-point iteration or one-pass guarantee
- **P2**: AgentDropout savings not reflected in budget pressure calculation
  - When: Dropout and expansion scoring use independent budget snapshots

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
