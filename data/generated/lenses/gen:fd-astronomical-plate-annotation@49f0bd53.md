## Task Context

Astronomical plate annotation adds structured meaning to visual data without modifying it. Terminal state encoding should similarly add meaning without bloating the content.

## Review Approach

### 1. Overlay vs. inline encoding

- Overlay vs. inline encoding — astronomical annotations are a separate layer from the plate image. Terminal annotations should be separable from the text content.

### 2. Classification vocabulary

- Classification vocabulary — stars get spectral types (O, B, A, F, G, K, M), galaxies get Hubble types. Terminal elements could get standardized type tags.

### 3. Magnitude as importance signal

- Magnitude as importance signal — brighter objects get more annotation detail. More important terminal regions get more encoding fidelity.

### 4. Coordinate systems

- Coordinate systems — plates use RA/Dec relative to reference stars, not absolute pixels. Terminal encoding could use relative positions from landmarks.

### 5. Catalog cross-referencing

- Catalog cross-referencing — objects reference catalog IDs not descriptions. Repeated terminal patterns could reference a session-local dictionary.

## Severity Calibration

- **P1**: Annotations mixed into content stream
  - When: LLM can't distinguish terminal content from encoding metadata
- **P2**: No importance weighting for annotation detail
  - When: Static header gets same annotation depth as active error output

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
