## Task Context

Screen readers solve exactly this problem: conveying rich visual UI state through a text channel to enable navigation and action. Tuivision is a screen reader for LLMs.

## Review Approach

### 1. ARIA role mapping

- ARIA role mapping — screen readers don't describe pixels, they announce semantic roles (button, heading, alert). Terminal elements could be similarly role-tagged.

### 2. Live regions

- Live regions — screen readers have 'polite' and 'assertive' change announcements. Maps to: only send terminal changes that are semantically important.

### 3. Spatial serialization order

- Spatial serialization order — how screen readers linearize 2D layouts into 1D text while preserving navigational meaning

### 4. Verbosity levels

- Verbosity levels — screen readers have adjustable detail levels (character/word/line/paragraph). Maps to: adaptive terminal state detail.

### 5. Focus tracking

- Focus tracking — screen readers emphasize the focused element. Maps to: cursor/active-element prominence in terminal serialization.

## Severity Calibration

- **P1**: Serialization loses semantic role information
  - When: LLM can't distinguish a menu item from a status message because both are just text
- **P2**: No focus/active-element signaling
  - When: LLM doesn't know which part of the TUI is interactive

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
