Reviewing a brainstorm for wiring deployment actions (deploy agent to country, withdraw agent) into ShadowBench's benchmark decision gate. The existing action set has only policy-level actions. ## Review Approach

### 1. Kelir legibility: The shadow screen makes characters visi...

- Kelir legibility: The shadow screen makes characters visible to the audience as silhouettes. The scorers see deployment actions only through DeploymentEvent traces. Are these trace events cast with enough clarity (distinct silhouettes) that power_dissolution can distinguish between deployments to different countries and values_under_pressure can attribute pressure changes to specific deployment windows?

### 2. Simpingan ordering: Before the performance

- Simpingan ordering: Before the performance, all puppets are arranged in the simpingan (banana-trunk display) in hierarchical order. Before the benchmark runs, what is the defined roster of deployable agents? The brainstorm removes the recruitment pipeline — so who is available to deploy? Is there a pre-positioned roster, or does deployment create agents from nothing?

### 3. Two

- Two-hand constraint: The dalang has only two hands and can manipulate at most two puppets simultaneously. What is the analogous constraint for the benchmark? If the model can deploy unlimited agents, the dalang metaphor breaks — narrative attribution becomes impossible because there are too many characters on screen.

### 4. Gunungan scene markers: The dalang uses the gunungan (tree

- Gunungan scene markers: The dalang uses the gunungan (tree-of-life puppet) to mark scene transitions, signal time passing, and indicate cosmic shifts. When a crisis begins or ends in the benchmark, is there an equivalent scene marker that signals to both the model and the scorers that deployment actions are now narratively meaningful?

### 5. Left

- Left-right kayon alignment: In wayang, characters on the right are typically protagonists and those on the left are antagonists. Do deployments carry alignment metadata (intent, target, expected effect) that lets scorers evaluate not just that a deployment happened, but what narrative role it serves?

### 6. Dalang as single operator: The brainstorm proposes simpli...

- Dalang as single operator: The brainstorm proposes simplified deployments managed entirely by the benchmark harness, not the full game system. This is the dalang pattern — one operator behind the screen. But does this single-operator design preserve enough fidelity that scorer results are meaningful for evaluating model behavior in the full game?

## Severity Calibration

- **P1**: Simplified deployments create agents from nothing with no pre-defined roster — like a dalang reaching behind the screen and producing a puppet the audience has never seen in the simpingan
  - When: No defined set of deployable agents or agent archetypes in the benchmark; deployment action conjures entities with no prior existence
- **P1**: DeploymentEvent traces lack enough distinguishing information for scorers to attribute effects to specific deployments — shadows on the screen are indistinguishable
  - When: DeploymentEvent contains only a boolean 'deployed' flag without target, agent identity, or timing metadata
- **P2**: No scene marker (gunungan equivalent) signals when crisis windows open/close, so the model deploys into narratively meaningless moments and scorers cannot distinguish signal from noise
  - When: Crisis lifecycle transitions are not surfaced to the model as distinct events that frame deployment action relevance

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
