## Decision Lens

A style feature extractor is valid only when: (1) each observable is operationally defined with enough precision that two independent implementations produce identical values on the same input — 'word count' must specify tokenization rules for contractions, hyphenates, and emoji; (2) each mode classifier discriminates reliably between modes it is designed to separate — emotional and playful patterns often co-occur, and the weight scheme must be validated against a labeled corpus, not just assumed correct; (3) profile stability is bounded — a fingerprint derived from fewer than 3-5 messages must be flagged as low-confidence, and BuildMirroring must not present early-profile instructions as if they carry the same authority as a profile built from 50 messages. If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.

## Prioritization

- P0: Issues that block other work, cause data loss or corruption — drop everything
- P1: Issues required to exit the current quality gate
- P2: Issues that degrade quality or create maintenance burden
- P3: Improvements and polish — suggest but don't block on these
- For each P0/P1 finding, describe the concrete failure scenario: what breaks, under what conditions, and who is affected

- Frame uncertain findings as questions, not assertions
