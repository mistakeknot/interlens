## Severity Calibration

- **P1**: The app uses a custom file manager instead of NSDocument, so two app instances (or a Claude Code skill) can open the same episode simultaneously and produce conflicting writes
  - When: If NSFileCoordinator/NSFilePresenter is not used for episode directory access
- **P2**: Monaco editor is chosen via WKWebView but introduces 200ms keystroke latency due to JS bridge serialization, making the script writing surface feel worse than a plain text editor
  - When: If the text editor component decision is deferred without a prototype benchmark of WKWebView keystroke latency at 10k+ word document sizes
- **P3**: Switching from the Music surface to the Video surface deallocates all waveform bitmaps; switching back triggers a full reload of every stem WAV, causing a 2-second blank state
  - When: If there is no LRU cache or minimum-retention policy for heavy view resources

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.

## Prioritization

- P1: Issues required to exit the current quality gate
- P2: Issues that degrade quality or create maintenance burden
- P3: Improvements and polish — suggest but don't block on these
- For each P0/P1 finding, describe the concrete failure scenario: what breaks, under what conditions, and who is affected
