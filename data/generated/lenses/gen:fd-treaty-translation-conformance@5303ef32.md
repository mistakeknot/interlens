## Severity Calibration

- **P0**: The conformance test verifies each language suite passes independently but never cross-checks that Swift and Python return the same verdict on the same vector, so the two 'translations' can silently diverge on an invalid manifest and both CIs stay green.
  - When: There is no shared assertion that both runtimes classify each fixture vector identically — cross-language agreement is assumed, not tested.
- **P1**: The fixture set covers valid manifests and a few malformed ones but omits vectors targeting each privacy_class value and each flow-rule boundary, so a native type could mis-handle a specific privacy_class and no vector would expose the divergence.
  - When: Conformance vectors don't systematically cover every privacy_class, every flow-rule row, and the accept/reject boundaries — coverage is incidental rather than exhaustive.
- **P2**: A schema change (new privacy_class, changed flow rule) has no defined re-concordance step, so the schema can be edited and merged while the hand-written Swift/Python types lag, producing a live authentic-vs-translation mismatch.
  - When: No process ties schema edits to re-running the full conformance-vector gate before merge, or schema_version semantics don't force re-verification.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
