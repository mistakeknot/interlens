## Severity Calibration

- **P0**: The BYPASS trigger writes the interspect halt record or emits a log event BEFORE factory-paused.json exists on the filesystem — a process crash in this window means external consumers (lib-dispatch.sh checking halt.IsHalted()) see no halt while interspect records show a BYPASS was triggered. This is the runner-before-seal failure: the notification escaped before the state was durable, creating a split-brain where some components believe the factory is halted and others do not.
  - When: When any code path in the BYPASS trigger can emit the interspect halt record, log the BYPASS event, or return a BYPASS status to callers before factory-paused.json is confirmed written and synced to disk
- **P0**: The SQLite transaction in ockham resume resets 4 of 5 domain ratchet_state entries to 'supervised' but crashes before committing — on restart, 4 domains are at 'supervised' and 1 remains at 'autonomous', creating inconsistent authority state where one domain has elevated privileges that the resume was supposed to revoke. This is the partial-unsealing failure: E-series tablets are active but Ma-series remains sealed, and cross-references between them produce corrupted administrative state.
  - When: When the domain reset in ockham resume uses multiple SQL statements rather than a single UPDATE ... WHERE clause in one transaction, allowing partial reset if the process crashes between statements
- **P1**: ockham health works correctly when the factory is running but fails or returns incomplete data when the factory is halted — the read-only operation that is supposed to be the primary diagnostic tool during emergency is itself broken by the halt state. This violates the Pylos principle that qa-si-re-u must be able to consult records during the sealed period — the sealed archive is useless if the consultation mechanism is also sealed.
  - When: When ockham health code paths hit the halt guard intended for write operations, or when health JSON construction depends on evaluateSignals() which is blocked during halt, rather than reading the last-known signal state from signals.db

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
