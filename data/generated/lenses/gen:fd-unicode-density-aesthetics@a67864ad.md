## Review Approach

### 1. Half

- Half-block coverage: U+2580–U+259F (block elements) are universally covered; U+1FB00–U+1FBFF (legacy computing supplement) covers 2×3 sextants and 2×4 octants but is missing from many Linux monospace fonts — is fallback defined when sextant glyphs render as tofu?

### 2. Braille density gradient: U+2800–U+28FF provides 8 dots p...

- Braille density gradient: U+2800–U+28FF provides 8 dots per cell (2×4); mapping terrain elevation or flora density to braille dot patterns requires a perceptually linear dot-count-to-intensity curve, not a bitmask-sequential one

### 3. Roguelike readability contract: DF/CDDA convention is that '

- Roguelike readability contract: DF/CDDA convention is that '.' means floor, '@' means player, '#' means wall — using block elements for terrain texture risks turning readable ASCII maps into illegible noise bitmaps

### 4. 24

- 24-bit color + Unicode interaction: coloring a braille character with a 24-bit fg/bg pair over a terrain tile — does the color encode the elf/entity or the terrain underneath? Compositing semantics must be defined

### 5. Font rendering in common terminals: Nerd Fonts

- Font rendering in common terminals: Nerd Fonts, JetBrains Mono, Iosevka all handle U+2580–U+259F but differ on cell height baseline — a half-block in Iosevka may not perfectly tile with the adjacent cell

### 6. Caves of Qud glyph vocabulary: Qud uses U+2588 FULL BLOCK...

- Caves of Qud glyph vocabulary: Qud uses U+2588 FULL BLOCK for solid walls, sparse box-drawing for passages — can Elf Revel borrow this vocabulary without licensing issues, and does it fit the elven aesthetic?

## Severity Calibration

- **P1**: Sextant (U+1FB00) glyphs render as empty boxes on the player's terminal font, making entire flora density layer invisible
  - When: No font coverage detection fallback; sextant glyphs used for a primary visual layer
- **P2**: Braille dot pattern for 'dense forest' is visually identical to braille pattern for 'rocky terrain' because bit assignment follows Unicode codepoint order rather than perceptual density order
  - When: Braille mapping uses sequential U+2800 increments rather than a dot-count-sorted lookup table
- **P2**: Elf entities rendered with block element glyphs become invisible against terrain tiles that use the same block element for texture
  - When: No reserved glyph namespace separating entity symbols from terrain texture symbols

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
