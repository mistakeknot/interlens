## Task Context

Garden Salon uses Yjs CRDTs for real-time collaboration with directions as named scopes of work. The default is optimistic — agent changes land immediately and humans annotate post-hoc. Multiple directions can be active simultaneously on the same garden.

## Review Approach

### 1. Direction dependency chains

- Does the direction model support the 'department handoff' pattern — where one direction's output becomes another direction's input, creating a dependency chain that the current flat lifecycle does not model?

### 2. Optimistic concurrency on shared artifacts

- Is the 'optimistic by default' pattern sustainable when multiple agents modify the same artifact simultaneously — post-production learned that editorial and VFX cannot both write to the same timeline frame without a locking or conforming step?

### 3. Attribution survival through transformation

- Does attribution survive artifact transformation — when an agent's output is revised, incorporated, or overwritten by another participant, is the original contributor's attribution preserved, reduced, or voided?

### 4. Conform step after merge

- Is there a 'conform' or 'pull' step that propagates changes from a merged direction into active directions that share the same base material — without this, active directions diverge from main and merge becomes increasingly painful?

### 5. Concurrent work visualization

- How does the visualization layer (Meadowsyn) represent concurrent work on the same artifact by different directions — post-production uses colored timeline markers per department; what is the Garden Salon equivalent?

### 6. Lock mechanism for non-CRDT-safe content

- Is there a defined 'lock' or 'checkout' mechanism for artifacts that cannot tolerate concurrent edits, or does the design assume CRDTs handle all merge cases — some content types (structured data, configuration) may produce semantically invalid CRDT merges?

## Severity Calibration

- **P1**: No dependency model between directions
  - When: If Direction B depends on Direction A's output but both are active simultaneously, merging A changes the base state B was authored against — without a rebase or conform step, B's merge will produce unexpected results or silent data corruption in the CRDT layer

- **P2**: Attribution voided by subsequent edits
  - When: If Participant X contributes 500 tokens to a section that Participant Y then rewrites entirely, X's attribution remains in the ledger but their actual contribution is zero — the append-only model records spend accurately but contribution value is misleading without a 'surviving content' metric

- **P2**: Active directions silently diverge from main after a merge
  - When: When Direction A merges into main, all other active directions are now authored against stale state — without a notification or rebase mechanism, contributors in those directions are working on an outdated view and will discover conflicts only at their own merge time

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
