## Task Context

Elf Revel — Rust colony sim with procedural flora (lifecycle systems, species generation), seasonal weather, and revel events. Exploring ASCII-as-polygon spatial rendering. The procedural art pipeline must translate rich ECS simulation state into visual ASCII output. hecs ECS, WASM browser target.

## Review Approach

### 1. State

- State-to-visual mapping pipeline: elf components (mood, skill, activity) → visual representation (character choice, color, animation state); building components (type, completion, age) → ASCII tile set selection — is this mapping defined declaratively or buried in rendering code?

### 2. Seasonal

- Seasonal and weather variation: the same forest tile should look different in spring (bright green, flowering characters) vs winter (sparse, white/blue); does the pipeline support parameterized tile generation or does it require separate hand-authored tile sets for each season × biome combination?

### 3. ASCII compositing order: terrain layer (floor characters)...

- ASCII compositing order: terrain layer (floor characters) + structure layer (wall/roof characters) + entity layer (elf characters) + effect layer (weather particles, revel sparkles) — what is the compositing model and does it handle transparency/overlap correctly in the isometric view?

### 4. Flora

- Flora and fauna visualization: the game has procedural flora with lifecycle stages (seed → sprout → mature → decay); does the ASCII art pipeline generate visually distinct representations for each stage, and can beauty/health attributes modulate the visual output?

### 5. Asset caching

- Asset caching and invalidation: if a building is constructed over 100 ticks, does the pipeline re-generate its ASCII tile representation every frame or cache it and invalidate only when the building state changes? Stale cache = visual glitches; no cache = performance death

### 6. Revel

- Revel and cultural event visualization: revels are the game's signature events with performances, audience reactions, and emergent drama — how does the procedural art pipeline represent these dynamic multi-entity events in ASCII? Particle effects? Stage layout? Crowd density?

## Severity Calibration

- **P1**: Every visible tile's ASCII representation is regenerated every frame from ECS state queries, causing the rendering pipeline to spend 10ms+ on procedural generation alone — eating the entire WASM frame budget
  - When: No dirty-flag or change-detection system between ECS state and visual cache; full regeneration every frame
- **P2**: All four seasons render identically because the tile generation system only parameterizes on biome type without season/weather inputs, making the passage of time visually imperceptible
  - When: Tile generation function signature lacks season and weather parameters
- **P2**: During a revel event, 30 elves gather in one area but the rendering shows them as overlapping @ symbols with no spatial arrangement — the game's signature event looks like a pile of characters rather than a performance
  - When: No spatial layout algorithm for multi-entity gatherings; entities rendered independently without group composition awareness

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

- P3: Improvements and polish — suggest but don't block on these
