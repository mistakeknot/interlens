## Task Context

Tuivision is a TUI testing/automation MCP server that gives AI agents visual access to terminal applications. Current modes: get_screen text (~200-400 tokens, no style), get_screenshot png (~1600 vision tokens), get_screenshot svg (~2000-8000 tokens, contains text+style but verbose). The goal is a new representation that captures text + task-relevant visual semantics at significantly fewer tokens than PNG/SVG while preserving the semantic information that plain text loses. Ideas already proposed include local OCR on PNGs and optimized SVG stripping.

## Severity Calibration

- **P0**: A 15-turn TUI automation session hits the context window limit at turn 12 because each get_screen result (even in text mode at ~300 tokens) persists in history, and the accumulated 3600+ tokens of screen captures plus conversation leaves no room for the LLM to reason about the remaining 3 steps.
  - When: Occurs in any non-trivial TUI automation workflow with frequent screen polling and a 100k context window, especially when the system prompt is already large.
- **P1**: The diff-based screen update mode sends compact deltas for turns 2-8, but by turn 9 the LLM has lost track of the cumulative screen state and sends a keystroke to a menu that no longer exists, requiring a full-screen refresh that negates the accumulated diff savings.
  - When: Triggered when the LLM's effective working memory for stateful reconstruction is shorter than the diff chain length.
- **P2**: Older screen captures are never evicted from conversation history even though they contain no information relevant to the current task step, consuming 40% of the context window with historical noise that the LLM must process but will never reference.
  - When: Occurs in any multi-turn session without explicit context management — the default MCP behavior is to retain all tool results.

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

A representation that is 50% cheaper per call but causes context overflow 30% sooner in a session is not an improvement — the total session cost and success rate matter more than per-call efficiency. Every design choice is evaluated across the full session lifecycle: turns 1-5 (cheap, plenty of room), turns 10-15 (pressure building), and turns 20+ (at the wall). If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.

- P2: Issues that degrade quality or create maintenance burden
- P3: Improvements and polish — suggest but don't block on these
