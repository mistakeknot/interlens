## Task Context

The brainstorm uses expansion score as the sole input to tier adjustment. Agent-domain difficulty compatibility is not considered.

## Review Approach

### 1. Test-before-deploy

- Test-before-deploy — tameshigiri tests blades at the tier they'll serve (battlefield vs. ceremony). The brainstorm assigns tiers without verifying the agent can perform at that tier. Should there be a lightweight capability check?

### 2. Graded certification

- Graded certification — swords are tested on increasingly difficult targets. Should agents be tested on a calibration prompt before dispatch to verify tier-appropriate capability?

### 3. Overtesting waste

- Overtesting waste — excessive testing damages the blade. Excessive capability verification wastes tokens. Where's the sweet spot?

### 4. Service tier mismatch

- Service tier mismatch — a battlefield sword used ceremonially is wasteful; a ceremonial sword used in battle is dangerous. An opus agent on a trivial domain is wasteful; a haiku agent on a critical domain is dangerous. The brainstorm addresses the dangerous case (safety floors) but not the wasteful case.

### 5. Retirement criteria

- Retirement criteria — swords are retired when they fail tests. Should agents that consistently underperform at their assigned tier be permanently downgraded or excluded?

## Severity Calibration

- **P2**: No capability verification: agent assigned to haiku produces incoherent findings because the domain exceeds haiku's reasoning capacity
  - When: Tier assignment based solely on expansion score, not agent-domain difficulty match
- **P2**: Opus agent on trivial domain: high expansion score assigns opus to a simple pattern-matching task
  - When: Score reflects adjacent domain severity, not this agent's actual task difficulty

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.
