## Severity Calibration

- **P1**: install.sh's 'next steps' print only names the installed components without telling the practitioner how to invoke Auraken — a practitioner who has never seen Auraken before does not know whether to type '/auraken', 'auraken', or something else in their Hermes session
  - When: First-run experience fails at the last step; practitioner reads SKILL.md to discover invocation syntax rather than learning it from the installer
- **P2**: voice-rubric.md ships in the bundle but INSTALL.md does not explain what register_check is or when to use it — the practitioner discovers a file they cannot interpret, creating cognitive load rather than value
  - When: External practitioner assumes voice-rubric.md is an internal development artifact and ignores it, missing the register verification capability entirely
- **P2**: MANIFEST.yaml notes 'observed register drift' for GPT models but INSTALL.md does not explain what register drift means experientially — a practitioner using gpt-5.5 cannot tell whether degraded behavior is expected or a bug to report
  - When: Support burden from practitioners reporting expected behavior as defects

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

A preset pack that requires 30 minutes of reading before producing a single correct image has failed the working photographer. The first correct result should arrive within 5 minutes of install completion — or the onboarding has not done its job. If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.
