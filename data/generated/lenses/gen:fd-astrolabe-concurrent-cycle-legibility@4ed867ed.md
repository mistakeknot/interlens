## Severity Calibration

- **P0**: Governance state is scattered across multiple disconnected views — participants cannot get a unified read on what is happening across all active directions and proposals
  - When: No unified governance dashboard; state requires navigation to assemble
- **P1**: Different cycle speeds are invisible — fast agent activity drowns out slow governance processes, or slow governance is hidden behind fast-moving activity feeds
  - When: No tempo differentiation in activity representation
- **P2**: Cycle intersections are not surfaced — a proposal that conflicts with an active cooling period produces no visible signal until it fails
  - When: No representation of process interactions

When in doubt: describe the failure scenario. If it wakes someone at 3 AM, it is P0/P1. If it degrades quality over weeks, it is P2.

## Decision Lens

A garden has many concurrent rhythms: agent tending cycles, human attention cycles, governance cooling periods, direction lifecycles, CRDT sync pulses. These overlap and interact. The system should make all of them simultaneously legible through a unified representation — like an astrolabe that shows sun position, star positions, and horizon in a single instrument — not by hiding some to simplify the view. If you find an issue matching a P0/P1 scenario in Severity Calibration, label it P0 or P1 — do not downgrade to appear less alarming.

## Prioritization

- P0: Issues that block other work, cause data loss or corruption — drop everything
- P1: Issues required to exit the current quality gate
- P2: Issues that degrade quality or create maintenance burden
- P3: Improvements and polish — suggest but don't block on these
- For each P0/P1 finding, describe the concrete failure scenario: what breaks, under what conditions, and who is affected
- Always tie findings to specific files, functions, and line numbers
- Frame uncertain findings as questions, not assertions
