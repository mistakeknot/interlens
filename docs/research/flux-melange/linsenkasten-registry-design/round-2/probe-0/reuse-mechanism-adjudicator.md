## Findings

### reuse-seam-adjudication-position-2-holds
- **Severity:** P1
- **Where:** docs/brainstorms/2026-09-01-linsenkasten-gate-forks-brainstorm.md:24-27 ("flux-gen and flux-melange consult the registry reuse-before-regenerate through the existing combine/contrast seam"), :35-36 ("the melange fusion seam already calls interlens tools when available, so reuse-before-regenerate plugs into an existing integration point"), :61-62 (embodies "auto-suggested at harvest (embedding match against curated definitions)"), :107-108 ("Query-time text embedding tries local Ollama, then zklw's Ollama over Tailscale, then a lexical fallback")
- **What:** Adjudicated independently against the live repo, not just the prior findings' quoted evidence. Position 1's literal claim — "harvest-time embedding match... with no query-time re-validation" — is refuted: Fork 5 (L107-108) does describe a query-time embedding pipeline, and `search_lenses` genuinely re-embeds free text per call rather than reading a stored vector (`apps/api/lens_search_api.py:376,389` calls `supabase_store.search_lenses(query, k=20)` fresh on every request; `packages/mcp/index.js:44` tool def, `:512` handler takes a `query` string, not a lens id). But position 2's sharpened claim is independently confirmed: the brainstorm names exactly one integration point for reuse-before-regenerate — "the existing combine/contrast seam" — and in this codebase that phrase resolves to `combine_lenses` (`apps/web/api/mcp-sse.js:391-397`), verified directly: it takes `args.lenses` (an array of names), resolves each via `lenses.find(l => l.name.toLowerCase() === name.toLowerCase())`, and produces a prose synthesis string. There is no `args.query`, no embedding call, and no comparison against any "current target" object anywhere in that handler. So as written, the brainstorm points reuse-before-regenerate at a tool that structurally cannot perform a reuse match — not because the match would be stale, but because the named seam was never a matching mechanism at all (it's a lens-blending tool, given lenses you already picked). Nothing in Fork 2's edge types (`embodies`: harvest-time, lens-vs-curated-pattern; `variant-of`: harvest-time, lens-vs-lens-cluster) supplies a target-vs-candidate edge either. Position 2 holds: the risk is an absent match step, not a stale one.
- **Evidence:** `apps/api/lens_search_api.py:376,389`; `apps/api/supabase_store.py:112` (`def search_lenses`); `packages/mcp/index.js:44` (tool schema, `query` string param), `:512-514` (handler calls `api.searchLenses(query, limit)`); `apps/web/api/mcp-sse.js:391-397` (`combine_lenses`: name-array lookup, no query/embedding); brainstorm L24-27, L35-36 (only named seam), L56-66 (no target-facing edge type).
- **Suggestion:** In whatever supersedes this brainstorm as the operative spec (see the companion finding below — the plan already has the real answer), stop describing reuse-before-regenerate as plugging into "the combine/contrast seam." Name the actual match function and require it to embed the live target fresh before consulting any harvest-time vector.

### brainstorm-names-wrong-seam-plan-already-fixed-it
- **Severity:** P2
- **Where:** docs/brainstorms/2026-09-01-linsenkasten-gate-forks-brainstorm.md:24-27, :35-36 (as above) vs. docs/plans/2026-09-02-linsenkasten-registry.md:647-684 (Stage D, Tasks 16-18) and :502-514 (`harvest/thresholds.py` constants + `embedding_text`)
- **What:** This is the insight the contradiction itself exposes: both round-0 and round-1 spent their budget testing whether `search_lenses` or `combine_lenses` implements reuse-before-regenerate — but neither is it. The sibling plan (same day, 2026-09-02) already specifies a third, standalone mechanism that sidesteps both: `scripts/lib_lens_registry.py` in interflux (Task 16) defines `resolve(spec) -> dict | None`, which builds `embedding_text(spec, body)` from the *current* flux-gen spec (persona/focus/decision_lens/review_areas — i.e., a live description of the target being reviewed, not a stored harvest artifact), calls Ollama fresh (local, then a Tailscale fallback, 4s timeout), and matches only against the generated layer's own vectors (`packages/mcp/lib/embed.js:598`: "cosineTopK over `generated` heads only... `matched = matches[0].score >= RESOLVE_MIN_COSINE`") — never against the curated-pattern axis that `embodies` uses, which independently closes round-1's `embodies-embedding-axis-conflation-risk` finding too. Task 17 wires this into `generate-agents.py` via a `--registry=auto|off` flag defaulting to `auto`, inserted *before* the existing `name in existing` skip check. Grep against interflux confirms flux-melange's own phases (`seed.md:19`, `melange-workflow.js:553,1003,1037`) call exactly that script for every round including STEER-WIDE and FUSE, with no `--registry` override — so they inherit the `auto` default and *do* get live re-validation, just never by calling `combine_lenses` or `search_lenses`. `combine_lenses` is real and used elsewhere in melange (`retarget.md:31`, to seed a fused lens's prose) but is unrelated to reuse-matching. So the underlying risk position 2 confirmed is, in the concrete plan, already mitigated — but the brainstorm itself, which is the ratified record of what mk approved, still names a seam that was never it, and would mislead an implementer who reads only the brainstorm (its stated audience, per "ruled by mk in session") rather than the 804-line plan.
- **Evidence:** docs/plans/2026-09-02-linsenkasten-registry.md:655 (`resolve(spec)`, live Ollama, lexical fallback, `RESOLVE_MIN_COSINE`), :502-514 (`embedding_text` reads spec fields, not stored harvest data), :598 (`resolveLens` restricted to generated-layer heads), :662-663 (`--registry` default `auto`, inserted pre-skip-check); `~/projects/Sylveste/interverse/interflux/skills/flux-melange-engine/phases/seed.md:19`, `.../workflow/melange-workflow.js:553,1003,1037` (melange calls `generate-agents.py` for seed/FUSE/STEER-WIDE rounds, no `--registry` override → inherits `auto`); `.../phases/retarget.md:31` (`combine_lenses` used only to seed fused-lens content, confirming it is not the reuse-match tool).
- **Suggestion:** n/a — see remediation.
