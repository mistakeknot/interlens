## Findings

### gap-coverage-three-incompatible-shapes
- **Severity:** P1
- **Where:** `packages/mcp/lib/graph.js` `frameCoverage` (plan line 365) → `packages/mcp/lib/api-local.js` `getRandomProvocation`/`detectThinkingGaps` (plan lines 471-472) → `packages/mcp/index.js:951-965` (`random_lens_provocation`) and `index.js:1013-1052` (`detect_thinking_gaps`)
- **What:** CONFIRMED, and the mismatch is worse than "flat lists vs. counted object" — there are **three** distinct, non-interchangeable "coverage" shapes in play, and Task 6's table actively conflates two of them under one word.
  1. **Task 4's `frameCoverage`** returns flat name arrays: `{explored: [name...], underexplored: [name...], unexplored: [name...], unknown: [...], total_frames: 28}`. No counts, no percentage.
  2. **Task 6's `detectThinkingGaps` promise**: `coverage: {explored_frames, unexplored_frames, underexplored_frames, total_frames, coverage_percentage}`. `index.js:1035-1039` needs `explored_frames` to be an **object** — `Object.keys(cov.explored_frames).length` and `Object.entries(cov.explored_frames).forEach(([frame, count]) => ...)` — while `index.js:1043-1049` needs `unexplored_frames`/`underexplored_frames` to be plain **arrays** (`.length`, `.slice(10)`). Task 6's table gives all three fields identical, undifferentiated notation, so nothing in the plan tells an executor that one of the three must be object-shaped and the other two array-shaped.
  3. **Task 6's `getRandomProvocation` promise** says `gap_analysis?: coverage` — i.e., reuse the same "coverage" type as (2). But `index.js:955-957` dereferences `gap.coverage.explored` and `gap.coverage.total` (both **numbers**, one level of nesting *deeper* than (2)'s `coverage_percentage`/`total_frames`), plus `index.js:959-960`'s `gap.was_gap_biased` (boolean) and `gap.suggested_from_frame` (string) — none of which exist anywhere in (1) or (2). If an implementer follows the table literally and sets `gap_analysis` to the same object type as `detectThinkingGaps`'s `coverage`, then `gap.coverage` is `undefined` and `gap.coverage.explored` **throws a TypeError**, crashing `random_lens_provocation` for every caller that supplies a non-empty `context` — the documented gap-biased path, not an edge case.
  - Two distinct failure modes, both silent to the plan's own gates: `random_lens_provocation` **crashes** (throw) whenever `context` is truthy; `detect_thinking_gaps` produces **silently wrong text** (not a crash — `Object.keys`/`Object.entries` don't throw on an array, they just walk indices) if `explored_frames` is implemented as an array like its two siblings, which is the natural reading of Task 6's table.
- **Evidence:**
  - `docs/plans/2026-09-02-linsenkasten-registry.md:365` (frameCoverage's flat-array return)
  - `docs/plans/2026-09-02-linsenkasten-registry.md:471-472` (the two table rows, `gap_analysis?: coverage` shorthand)
  - `packages/mcp/index.js:955-957` (`gap.coverage.explored`/`gap.coverage.total`)
  - `packages/mcp/index.js:959-960` (`gap.was_gap_biased`, `gap.suggested_from_frame`)
  - `packages/mcp/index.js:1035,1037` (`Object.keys(cov.explored_frames)`, `Object.entries(cov.explored_frames)`)
  - `packages/mcp/index.js:1043-1049` (`cov.unexplored_frames.length`, `.slice(0,10)`)
- **Suggestion:** Define `gap_analysis` as its own type distinct from `detectThinkingGaps`'s `coverage` — e.g. `{coverage: {explored: number, total: 28}, was_gap_biased: boolean, suggested_from_frame: string|null}` — and state explicitly, field by field, that `coverage.explored_frames` is an object map (`{[frame]: count}`) while `unexplored_frames`/`underexplored_frames` are string arrays, so the table's three identically-styled names stop implying one uniform shape.

### framecoverage-drops-per-frame-counts
- **Severity:** P1
- **Where:** `packages/mcp/lib/graph.js` `frameCoverage` (plan line 365, Task 4) vs. `packages/mcp/lib/api-local.js` `detectThinkingGaps` (plan line 472, Task 6)
- **What:** Task 4's `frameCoverage` classifies each frame by its explored-lens count (`≥1` → explored, `==1` → underexplored) but the spec's return value throws that count away — it keeps only which *bucket* a frame name fell into, not the count itself. `index.js:1037` needs `explored_frames` to map frame name → lens count (`Object.entries(...).forEach(([frame, count]) => ...printed as "**frame**: count lens(es)"...)`). An implementer of `detectThinkingGaps` calling `frameCoverage(store, context)` exactly as Task 4 specifies it has no way to recover that count — it isn't in the returned object. Either `frameCoverage`'s signature/return must change (Task 4 is out of scope for the sibling api-local.js task per the table's contract, but the count has to come from *somewhere*), or `detectThinkingGaps` has to independently re-walk `store`'s frame→lens membership to compute counts frameCoverage already computed internally and discarded — duplicated logic the plan never asks for and that could drift out of sync with frameCoverage's own explored/underexplored boundary if the two count passes ever disagree.
- **Evidence:** `docs/plans/2026-09-02-linsenkasten-registry.md:365` ("`explored` = frame names that contain ≥1 explored lens... `underexplored` = frames where exactly 1 explored lens sits") defines only bucket membership, never a returned count; `packages/mcp/index.js:1037` requires the count to exist per frame.
- **Suggestion:** Extend Task 4's `frameCoverage` to return `explored: [{frame, count}]` (or a parallel `counts: {frame: n}` map) instead of a bare name array, and have Task 6's `detectThinkingGaps` build its `explored_frames` object directly from that — one source of truth for the count, not two independent tallies.

### gap-analysis-verify-blind-spot
- **Severity:** P2
- **Where:** Task 6 Step 1 test list (plan line 480) and Step 4 smoke-script verify block (plan, after Step 4)
- **What:** Task 6's own acceptance gate never exercises either failure mode above. Step 1's assertion list touches `detectThinkingGaps(['Eye of Sauron']).coverage.total_frames === 28` and nothing else on that object — no check of `explored_frames`'s type, no `coverage_percentage` check — and never calls `getRandomProvocation` with a context at all. Step 4's smoke commands cover `search_lenses`, `find_lens_journey`, `--resource lens://graph`, and `get_central_lenses` — never `random_lens_provocation` or `detect_thinking_gaps`. So the P1 crash (any context-bearing `random_lens_provocation` call) and the P1 silent-garbage text (wrong `explored_frames` shape) both ship past every command Task 6 designates as its exit gate — `node --test` and the six listed smoke checks all report green.
- **Evidence:** `docs/plans/2026-09-02-linsenkasten-registry.md:480` (Step 1's exact assertion list); the Task 6 `<verify>` block (six `run:` lines, none naming `random_lens_provocation` or `detect_thinking_gaps`).
- **Suggestion:** Add to Step 1: `detectThinkingGaps(['Eye of Sauron']).coverage.explored_frames` is a plain object (not `Array.isArray`) with at least one `[frame]: count` entry; and a call `getRandomProvocation(['Eye of Sauron'])` asserting `gap_analysis.coverage.explored` and `gap_analysis.coverage.total` are both numbers. Add one smoke line: `node packages/mcp/scripts/smoke.mjs random_lens_provocation '{"context":["Eye of Sauron"]}'` → does not throw.

## Verdict
Confirmed and sharpened: the prior finding correctly identifies a shape gap, but the actual mismatch is a three-way collision (frameCoverage's discarded counts, detectThinkingGaps's ambiguous object-vs-array table row, and getRandomProvocation's separately-nested gap_analysis wrongly aliased to the same type) with two distinct failure modes — a crash on the common gap-biased path and silent wrong text on the coverage-summary path — neither of which Task 6's own test or smoke verify steps would catch.
